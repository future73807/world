# 迷雾群岛 · 运行说明

浏览器全屏 3D 开放世界浮岛。Three.js 实时渲染。除史莱姆外，**全部模型和出生岛地形都是 Blender 工程产出的**（`world_v2/prefabs.blend`、`world/terrain.blend`），开拓新区域时 AI 还可以让 Blender 在后台建新模型。UI、模型、地形、材质均为本项目从零制作，未使用恢复包或任何外部游戏资源。

## 启动

需要 Node 22+。开拓新区域会用到下面三样，缺了也能玩，只是开拓功能降级：

| 依赖 | 用途 | 没有它时 |
|---|---|---|
| 本地服务端（`npm run dev` 会一起启动） | 调用 AI、调度 Blender、保存 Key | 游戏照常可探索；不能开拓，设置里提示连不上服务 |
| Blender 4.3 | 预制模型与出生岛地形的制作；开拓时在后台建新模型 | 装在标准目录会自动找到，也可在「设置 → 模型与 AI」填 `blender.exe` 路径；找不到时 AI 只能用现有模型 |
| AI 模型的 Key（可选） | 让大模型读周围地形和模型来设计新区域 | 不配置时开拓一律走「本地配方」 |

```bash
cd app
npm install
npm run dev      # 开发：游戏 http://127.0.0.1:5173 ＋ 本地服务端 :8787
npm run build    # 生产构建 → app/dist
npm start        # 正式运行：服务端同时提供页面与接口 → http://127.0.0.1:8787
```

需要支持 WebGL2 的浏览器。首次进入约 5 秒：没有加载插画，开局那几秒就是游戏自己的世界——**一整片积云盖在还没做完的岛上**，标题浮在云上；世界做好后，云**一朵一朵**抬起、飘开、离开画面，每一朵离场都露出它下面实时渲染的岛，最后直接落到史莱姆身上。（云的错峰窗口比单朵淡出更长，所以任何一刻画面里同时有整朵的云、正在离场的云和已经散掉的空隙。）

## 当前版本：格子世界、AI 开拓与 Blender 资产

### 世界按格子规划

- 世界是一张 **40 BU × 40 BU 的格子地图**（`app/src/game/world.ts`）。每格属于一个群系：草甸、森林、雪原、沙漠、沼泽、火山、海滩、海洋（`biomes.ts` 里有地形参数、地面配色、植被规则，以及"能和哪些群系相邻"）。
- 出生岛是固定的 3×3 九格：北边雪原 ×2 ＋ 火山，中间沼泽 ＋ 森林 ＋ 沙漠，南边海洋 ＋ 草甸 ＋ 沙漠。所以一开局就能看到雪地、沙漠、森林、沼泽、火山、海洋和海岸沙滩。
- 相邻格子的地形在边界上连续混合，没有接缝。还没生成的格子算作外海，所以已知世界天然是一座被雾围住的岛；靠步行走不到的格子会自动接一条沙堤。
- 小地图和全屏地图都画着格子网格：待开拓的格子是虚线框，镜头正对着的那一格是实线框加浅色填充，正在生成的格子单独高亮。
- **哪些格子能开拓**：和已生成格子相邻的未开拓格子。按 E 的条件是离这样一段边境 10 BU 以内，并且它落在镜头前方一个固定扇形里（默认 60°，「设置 → 开拓扇形」可调 30–120°）。

### 按 E 之后发生什么

1. 走到边境、镜头对着待开拓的格子：海面上显出这一格的白色线框，边境点浮现「E 开拓迷雾」。
2. 按 E：弹出「许下你的愿望」——方向、愿望输入（可留空），以及这块区域由谁来设计（`AI · 服务商 模型名`，或 `本地配方`）。
3. 确认后进入**生成中**：那一格涌起雾涡，**「正在开拓」卡片就悬在这一格方框的上方**（跟着镜头走，始终贴着那个白框）——一个转动的白圈、和体力条同款的一条进度、一个「取消」。这期间按 E 无效，并提示"迷雾正在散开，等当前区域完成后再开拓"。
4. 阶段依次是：提交愿望 → AI 构思中 →（需要时）Blender 启动、建模 → 地形升起 → 浮现。新地面先蒙一层白再显出颜色，植被从玩家这一侧一波波浮现，雾墙向后退。做完后顶部浮出一条「新区域已经生成」的提示，几秒后自己消失，不报区域名、也不说谁设计的。如果区域卡说自己比一格大（`extent` 2–3），周围几格会沿用同一份设定一起升起。
5. 随时可以取消，取消会同时终止服务端的 AI 请求和后台的 Blender。
6. 结果写进浏览器本地存档（连同新模型的地址），刷新页面后原样恢复。

### AI 怎么设计新区域

- 浏览器把周围情况交给本地服务端：目标格子坐标，相邻格子的群系、名字、来源、峰高、陆地占比、地形特征，附近已有的模型（带中文名和类别），以及玩家的愿望。
- 服务端把群系表、相邻规则、55 个模型的目录、以前造过的模型和"部件配方"的写法写进提示词，让配置的大模型回一张**区域卡**（JSON）：名字、群系、**需要几格地**（`extent` 1–3 与理由）、峰高、陆地占比、地形特征、植被清单、要不要 Blender、新模型的配方。
- **多大一块地由 AI 自己判断**：多数地方一格够用；一道长山脊、一圈环礁、一整条火山带才写 2–3，并说明理由。浏览器照卡把周围几格用同一份设定一起升起（不重复命名、不重复地标），不会被格子边切断。
- 模型写的每个字段都会被校验和限制：群系必须和相邻格子接壤，峰高不能和邻居相差 ±40% 以上，地标最多 1 个，新模型最多 2 个，不认识的模型丢弃；每一处修正都会写进结果说明。
- **要不要用 Blender 由 AI 判断**：只有区域卡声明"需要模型库里没有的东西"并给出配方时，才在后台启动 Blender；用现有模型能组合出来的就不开。
- 没配置 AI，或者所有服务商都失败时，用**本地配方**（按周围群系和愿望里的关键词决定），结果明确标着"本地配方"。

### Blender 在运行时怎么建新模型

- 一份配方由若干**部件**组成：阔叶树、针叶树、菌类、仙人掌、棕榈、珊瑚、晶簇、小花、拱门、团块、切面岩石、弯管、放样体、草丛、羽叶、叶片、垂帘、尖刺。每个部件有自己的尺寸、位置、旋转、配色（按高度、法线或色带上色）和是否发光。
- `world/blender/build_recipe.py` 在后台 Blender 里校验配方、建模、减面、生成远景 LOD，导出 GLB，并存一份 `models.blend`（可以打开继续手改），一个模型约 1–3 秒。
- 配方不合法或建模失败时，这个模型换成区域卡里指定的"最接近的现有模型"，并在说明里写出来。
- 造过的模型会登记在案，之后 AI 可以直接复用，不必重开 Blender。

### 服务商与 Key

「模型与 AI」里有现成的服务商：智谱 GLM、智谱 GLM · Coding Plan、DeepSeek、Moonshot Kimi、OpenAI、OpenRouter、Claude、Gemini、本地 Ollama，以及"自定义 / 中转"（任何 OpenAI 兼容的中转地址）。没填 Key 的标着"未配置"；本地 Ollama 没在运行时标着"未运行"，也不会被当成备用。

Key 只存在本机的 `runtime/secrets.json`（不进仓库），由服务端保管。浏览器只拿到"是否已保存"和末四位；输入框留空表示沿用已保存的 Key，旁边的「清除」按钮才会删掉它。服务端只监听 `127.0.0.1`。

2026-11-24 从这台机器不带密钥探活的结果：智谱的两个地址、DeepSeek、Moonshot 都返回了鉴权错误，说明地址正确、网络可达；OpenAI、OpenRouter、Claude、Gemini 在这个网络下连不上，需要代理，或者走"自定义 / 中转"。**这些地址只用这种方式核对过，没有一个用真实 Key 跑过。**

智谱的 GLM 会先思考再作答。请求里显式带上了"关闭思考"（接口不认这个参数时会自动去掉重试）；模型只回了思考过程时，结果说明里会写明原因，并改用本地配方。

### 命令

| 命令 | 作用 |
|---|---|
| `npm run dev` / `npm start` | 启动，见上文 |
| `npm run typecheck` | 类型检查（`tsc -b`） |
| `npm run assets:prefabs` | 用 `world_v2/blender/build_prefabs.py` 重建模型库、LOD、碰撞和构建报告 |
| `npm run assets:validate` | 校验 55 个模型、126 个 GLB 网格、顶点色、LOD、碰撞、接地和保留资产 |
| `npm run assets:gui` | 在 Blender 窗口里打开 `world_v2/prefabs.blend` |
| `npm run assets:terrain` | 用游戏代码算出出生岛高度，在 Blender 里建地形工程并导出 |
| `npm run assets:terrain:export` | 手改过 `terrain.blend` 之后只重新导出，不重建 |
| `npm run world:analyze` | 统计出生岛每一格的陆地占比与高度范围 |

**怎么改模型**：修改 `world_v2/blender/build_prefabs.py` 里对应的 builder，再跑 `npm run assets:prefabs && npm run assets:validate`。`world_v2/prefabs.blend` 可以打开检查或手改，但下次构建会按脚本重新生成；需要保留的改动应写回 builder。

**怎么改地形**：用 Blender 打开 `world/terrain.blend`，编辑 `Birth_Terrain` 集合里的地形网格，保存后跑 `npm run assets:terrain:export`。高度会从网格上重新采样，史莱姆走的就是你改过的表面。注意两点：改了地形代码或种子之后要重跑 `npm run assets:terrain`；在一块地形附近开拓过之后，那几块会被实时生成的地形取代。

### 没有 Key 时怎么测 AI 这条线

```bash
node server/mock-llm.mjs        # 本地假模型端点 http://127.0.0.1:18080/v1
```

在「设置 → 模型与 AI」里选"自定义 / 中转"，接口地址填 `http://127.0.0.1:18080/v1`，模型名和 Key 随意。它按愿望里的关键词返回固定的应答：

| 愿望里带 | 假模型的应答 | 用来验证 |
|---|---|---|
| （其它任何内容） | 一张故意写得很乱的区域卡 | 校验、Blender 建模、兜底 |
| `复用` | 只引用以前造过的模型的卡 | 不启动 Blender 的复用路径 |
| `慢` | 先思考 6 秒 | 生成中的界面、取消 |
| `拒绝参数` | 对带 `thinking` 的请求返回 400 | 去掉参数重试 |
| `空回答` | 只有思考过程、没有正文 | 明确报错并改用本地配方 |

测完用「清除」按钮删掉 Key，再把服务商切回去。

### 这一轮实际验证过的（2026-11-24）

- 出生岛的 198 块地形全部来自 Blender 导出；从 Blender 网格采回的高度和解析地形平均偏差 0.0026 BU。
- 浏览器里走通：E 提示 → 愿望框 → 生成卡片（阶段与进度）→ 生成中按 E 被拒 → 取消（AI 阶段和 Blender 阶段都会终止服务端作业）→ 新格子浮现 → 刷新后区域和模型恢复；地图上的格子高亮；扇形偏 25° 可开拓、偏 40° 不可，调到 110° 后偏 40° 也可开拓。
- AI 这条线用假模型端点测过：乱写的卡（不存在的模型、超量地标、3 个新模型、坏配方）全部被修正或兜底；合法的新模型由 Blender 建成并下载进游戏；复用旧模型时不启动 Blender。
- 设置页：切换服务商、Key 保存与脱敏（页面和接口返回里都找不到 Key）、清除 Key、测试连接（坏地址会报错）、两个开关、Blender 自动检测。
- 思考型模型的请求加固用假端点验证过：带 `thinking` 被拒后自动重试；只有思考过程的应答会给出明确原因并退回本地配方。
- 出生点实测（1440×810，RTX 4060）：156 fps，最差一帧 12 ms，323 次绘制，约 98 万三角形，2307 棵植被。
- **没有验证的**：真实的大模型。这台机器上没有任何可用的 Key，AI 路径只验证到协议和校验这一层；真实模型给出的区域好不好，要配上 Key 之后才看得到。

## 历史轮次（第三轮至第十一轮）

下面是早期实现的逐轮记录，当时模型和地形还是浏览器里程序化生成的，很多数字和做法已经被上面的"当前版本"取代，保留下来只为说明设计来由。

**美术方向（第三轮修订，按用户参考录屏逐帧核对）**

早期曾对用户提供的原神录屏做逐帧抽帧分析（参考帧已清理，结论保留如下）：

- **史莱姆**是原神的水史莱姆：近乎球形的蛋形穹体（不是水滴/锥形），半透明青色果冻，**发光的白色竖椭圆眼**带深色描边，没有嘴和腮红。
- **UI** 是原神 HUD：柔边圆形小地图（无白圈边框，橄榄色调地图）、右侧角色栏（名字+绿血条+头像+编号）、底部斜切端头血条（白色数值内嵌）、右下圆形技能钮（键位标签在下方）、右上白色细线图标。
- **场景**：明亮蓝天空、暖阳、饱和草绿、圆润树冠与鹅卵石岩石。

据此重写了史莱姆建模与 HUD 布局。历史说明见文末限制一节。

**世界与美术**

- 确定性高度场：地形、水面、小地图、全屏地图、碰撞和植被散布共用同一 `IslandField`，同种子必然同岛。
- 平滑连续地形：10×10 区块、每块 28×28 细分（约 0.36 BU 采样），共享顶点 + 解析法线，块间无光照接缝；崖壁保留分层色带；三层微噪声让草坡有真实起伏。
- 树冠为"多团块叠加"（`foliageClump`：双尺度椭球叠加 + 高度/法线双渐变），三族树各 3 个结构变体；岩石为圆润鹅卵石；草簇宽叶 9–13 片，约 4200 丛。
- **水滴史莱姆**：蛋形穹体轮廓（参照水史莱姆实测控制点），26 环 × 26 边索引拓扑；半透明果冻材质（菲涅尔边缘增透 + 湿润高光 + 高光斑点）；**发光白色竖椭圆眼**（RGB>1 穿透 ACES 色调映射）带深色描边光环；无嘴无腮红；眨眼/呼吸/挤压拉伸保留。
- 光照：高调日光（暖阳 3.15 + 蓝天补光 + 冷侧补 + 暖轮廓），ACES；天空为亮蓝分层渐变穹顶。
- 远景：11 座独立漂浮小岛与多组云团。

**玩法与界面（第五轮：按反馈收敛 HUD、全屏地图、书本帮助）**

四周被浓雾包围的浮岛；所有界面只保留一套白色语言，页面背后是高斯模糊的世界。

- **小地图**：左上玻璃圆盘，边缘用长渐变完全化开（无任何可见边线）。圆盘外是白蓝云层，走过的地方从云里透出；顶部只有 `N`。已去掉眼睛按钮与区域文字标签。
- **玩家箭头**：圆角蓝色水滴（青→蓝渐变 + 白描边 + 白晕），随镜头朝向旋转。
- **右上三枚白色纹样图标**：罗盘星（地图 M）、问号（帮助 I）、齿轮（设置 C）。三枚共用同一套环形底纹与中心圆点（`Ring`/`Hub`），同尺寸同基线完全对齐，键帽字幕无框白字。
- **世界内“开拓迷雾”提示**：走到离雾缘很近时（朝向前方 9 BU 内采到岛缘入水线）才投影在雾边，白色圆角键帽 E + “开拓迷雾”四字胶囊，纯白样式。指针锁定时点击画布同样能命中提示打开对话框。

## 踩坑清单（持续更新）

- **共面透明圆盘 + depthWrite:true = 星芒伪影**：太阳三层盘曾因三角扇深度打架画出放射尖刺；透明盘一律 `depthWrite:false`（depthTest 照常）。
- **`scene.background` 贴图会被二次编码洗成灰白**：卡通天空最终用「透明画布 + 页面层 CSS 渐变」实现，色调零损失。
- **`setPointerCapture` 拖拽层内的按钮收不到 click**：控件必须放拖拽层外，或 pointerdown 里对 `closest('button')` 直接跳过。
- **Sprite 想在世界里发光必须 `fog:false`**，否则会被场景雾按距离洗掉（测试时红色精灵变粉就是它）。
- **验证相机朝向别手摆**：`g.update()` 每帧用第三人称控制器覆盖 camera.position/lookAt；要用 `g.cam.frame(yaw, pitch, dist)`。
- **`ridgedFbm` 生成地形会出现月球坑**：山体噪声已换平滑 `fbm`。
- **雾粒子的高度带要对着相机眼高调**：云朵 y 低于山脊就会被丘陵挡住，看起来“没渲染”。
- **App 的 fogSpan 状态可能滞后一拍**：地图上迷雾直接读遮罩画布自带的 worldSpan，否则云层与地形“分层”。
- **IAB 面板被遮挡时 rAF 节流**：游戏循环看似死亡（visibilityState 仍 visible、定时器正常）；另外 `waitForLoadState` 必须传对象 `{state:'domcontentloaded'}`，传字符串会被展开成 16 个 key 报错。
- **地图烘焙要延迟**：拖拽期间反复重排定时器，松手 50ms 后再补烤瓦片，否则拖动卡死。

Blender 资产与 AI 开拓这一轮新增：

- **`tsc --noEmit -p .` 在方案式 tsconfig（`files: []` 加 references）下什么都不检查**：要用 `npm run typecheck`（`tsc -b`）。类型错误曾因此漏到 `npm run build` 才暴露。
- **glTF 顶点色不能再归一化**：three 的 `BufferAttribute.getX()` 已经把 UNSIGNED_SHORT 归一化，再除以 65535 会让所有模型发黑。
- **发光件要单独导出**：复合部件（树、菌类等）的 `glow` 不能传给所有子部件，否则整棵树都成了发光体。命名统一为 `<id>__glow`、`<id>__lod1`、`<id>__glow__lod1`。
- **地形导出后要核对"索引顺序 = 高度顺序"**：Blender 里对象的顺序和 Node 写出的顺序不一致时，整块地面会错位（史莱姆陷进地里）。现在索引按对象顺序写，并用解析地形自检。
- **Blender 的 `ray_cast` 必须给 `distance`**，而且高度在 Z 轴而不是 Y 轴。
- **`--export-only` 必须带上种子**：索引里 `seed: null` 会让游戏悄悄退回浏览器自建的地形。种子现在记在工程的场景属性 `mist_seed` 里。
- **开拓后植被为零**：连通性修复会用新对象重新登记格子，之后必须重新 `field.get()`，否则"这个点属于本格子"的比对全不成立。
- **取消要通知服务端**：只改浏览器本地标志的话，AI 请求和后台 Blender 会照常跑完，期间别的开拓请求都被拒。
- **海面上的方块洞**：`isDeepSea` 只看内部采样会漏掉内陆深水湖，要加一圈边界检查。
- **GLB 文件每次导出的字节都略有不同**：Blender 的导出器不保证逐字节确定，比较时看内容（网格数、高度数据）而不是文件哈希。
- **改完代码要双重确认**：Python 写出的补丁里反斜杠可能少一层，`'\'` 这种坏转义 tsc 不报错、Babel 才报；`npm run typecheck` 和 `npm run build` 都过了才算数。
- **自动化测试的两个坑**：浏览器工具的 `fill('')` 清空不了输入框（要全选加退格）；浏览器面板隐藏时页面不排版，按坐标点击会失败（改用 DOM 点击，或把面板显示出来）。
- **海面别用"深度"当遮罩**：泡沫原来按水深画，几厘米深的滩涂整片都算"岸线"，于是白泡沫铺满滩地，从侧面看就是一块插进地面的白板。现在泡沫宽度按地面坡度换算成 BU，并且地面高于潮线 0.02 BU 的地方海面直接 `discard`。
- **阴影相机要跟着玩家**：太阳的阴影相机是固定 ±58 BU 的框；离开出生岛两个格子后，新地就在框外，那块地没有影子（阴影相机的边界还会在地面上切出一道直线）。现在阴影框跟着史莱姆平移，并按整 BU 对齐避免行走时纹素抖动。
- **云的错峰必须长于单朵动画**：一开始 63 朵云同时开始、同时结束，画面只会整体淡一下，看不出"一朵一朵"。把 `animation-delay` 的最宽跨度调到比 `animation-duration` 更长之后（约 1.8 s 跨度 / 2.1 s 动画），任一时刻才会同时存在整朵、半散、已散三种云。
- **淡出中的云不能停在原地**：云如果一边变透明一边不动，就会变成一片半透明的圆盘盖在世界上面（像光斑）。现在云保持不透明先抬起，到 78% 才开始离开画面，透明度只在最后一段掉。
- **网格会落后于高度场**：开拓、连通性补桥、extent 扩格之后，个别地块可能已经在新高度场上，网格却是旧的，表现是一道锯齿状三角墙插进地面。`healTerrain()` 每次铺新地后抽样比对网格与 `field.height()`，差超过 0.5 BU 就重建那一块。

## 当前限制（如实记录）

- **真实的大模型没有验证过**：这台机器上没有可用的 Key。各家接口的地址用不带密钥的请求核对过，请求与校验逻辑用本地假端点测过；真实模型给出的区域好不好、模型名在对应服务商下是否存在，要配上 Key 才看得到。
- **提交三角面约 98 万**，高于最初预算的 25 万：2300 多个植被实例（近远景 LOD 按距离切换）加上 198 块地形。要降下来需要地形按距离分级细分和草地贴片实例化，都还没做。
- **手改地形只作用于出生岛**：开拓出来的格子，地形是浏览器按区域卡实时生成的，不经过 Blender 导出。出生岛里靠近开拓边界的那几块，开拓之后也会被实时地形取代。
- **新模型是"按配方建模"，不是 AI 直接生成网格**：AI 写的是部件配方，Blender 按配方搭建，能做出什么由那 18 种部件决定（树、岩石、晶簇、拱门这一类），配方之外的形状做不出来。
- **预制模型要改配方才能留住**：直接在 Blender 里手改，会被下一次重建覆盖（见上文）。
- 没有天气与昼夜循环；触屏布局只在桌面浏览器的模拟手势下验证过。
- 运行时造出的模型放在 `runtime/generated/`（不进仓库）。删掉它之后，旧存档里引用这些模型的区域还在，但那些模型会消失。
