# 迷雾群岛 · Slime Openworld

> 一套**只写提示词、不写代码**的 3D 开放世界施工图。
> 交给 ZCode + Blender，世界会自己长出来；你只负责给灵感。

---

## 这是什么

这是一个"提示词包"，不是一套成品代码。里面每个 `.md` 是一颗**零件**：一段可以直接丢给 ZCode 的施工指令。ZCode 照着顺序执行，就会在 Blender 里搭出一座低多边形海岛，放一只会呼吸、会跳、会发呆的果冻史莱姆，并在世界边缘铺一圈会翻涌的迷雾。

当你在 Blender 里带着史莱姆走到迷雾边缘，按 `E` 蓄力，后台的 Blender CLI 就开始生孩子——新的地形、新的地标、新的颜色。跑完后，网页驾驶舱会弹出一句话：

> **世界有新的变化，快去看看。**

然后迷雾退去一环，地图变大一圈，AI 给这片新土地编一段来历。

## 三个角色

| 角色 | 位置 | 负责什么 |
|---|---|---|
| **Blender 世界** | `world/`（真身） | 地形、水、植被、史莱姆、迷雾、游玩。**这里才是 3D** |
| **网页驾驶舱** | `app/`（副驾） | 贴 API Key、抽灵感卡、内置 CLI、看地图、收通知 |
| **AI 灵感层** | 服务端代理 | 把一句模糊的愿望，翻译成一份可执行的「世界设定卡」 |

一句话理解：**Blender 是身体，网页是仪表盘，AI 是想象力。**

## 30 秒玩法

1. 打开网页驾驶舱，填入 API Key（跳过也行，会走本地配方）。
2. 抽 3 张灵感卡：「苔藓 / 鲸骨 / 黄昏」，或直接写一句"我想要一个会下雨的火山岛"。
3. 点「生成世界」。
4. 底部内置 CLI 开始滚日志，进度条走过地形 → 水 → 植被 → 史莱姆 → 迷雾。
5. 完成后右上角弹出通知：**世界有新的变化，快去看看**。
6. 切到 Blender，用 `WASD` 带史莱姆走到迷雾边，按 `E` 蓄力 1.2 秒。
7. 迷雾退去，地图扩张，AI 写下新区域的故事。

## 迷雾规则（核心机制）

世界一开始是**固定大小**的。迷雾不是装饰，是"空气墙 + 待解锁的空白"。

| 环 | 世界边长 | 区块网格 | 如何进入 | Blender 生成范围 |
|---|---|---|---|---|
| 0 · 出生岛 | 100 × 100 | 10 × 10 | 初始 | 整岛 |
| 1 | 120 × 120 | 12 × 12 | 走到迷雾边，按 E 蓄力 1.2s | 只生成新的一圈 |
| 2 | 140 × 140 | 14 × 14 | 同上 | 只生成新的一圈 |
| 3 | 160 × 160 | 16 × 16 | 同上 | 只生成新的一圈 |
| 4 · 上限 | 180 × 180 | 18 × 18 | 同上 | AI 送给你的终章 |

每扩一环：总边长 **+20 BU**（每边 +10 BU，正好一个区块宽），新块带 44 个区块，旧区块零改动。

规则细节：

- **迷雾 = 空气墙**：史莱姆撞不过去，但能看见后面的轮廓。
- **每次解锁只扩一环**，旧地形一格不动，新环从迷雾里"长"出来。
- **每环只生成一次**，缓存进 `.blend`；同一 seed 永远长回同样的样子。
- **上限 ring 4（180 × 180）**：不是技术怜悯，是因为再大 Blender 单场景就开始掉帧了。

### 一次拓荒的完整链路

这是一条跨四个角色的长链路，也是整套提示词里最值得看的部分：

```
玩家走到雾边
  → 雾局部变薄，出现「按住 E」           (零件 29)
  → 按住 1.2s，脚下蓄力环填满，世界静默 0.15s
  → Blender 写 unlock_request.json       (零件 29/30)
  → 网页服务端接单，状态机 REQUESTING     (零件 30)
  → AI 生成邻域设定卡 specs/ring_n.json  (零件 31)
  → 网页作业队列入队 job                 (零件 05)
  → 后台 spawn blender -b gen_ring.py   (零件 06)
  → stdout 的 @@PROGRESS 变成进度条       (零件 07)
  → 只生成新的一圈，旧区块哈希必须不变     (零件 32)
  → 退出码 0 + 产物存在 → APPLYING
  → 雾退 1.5s，新土地显影 → REVEALING
  → 网页弹「世界有新的变化，快去看看」     (零件 08)
  → 地图遮罩同步退一圈                   (零件 33)
  → 服务端写 unlock_result.json
  → Blender 读到 ok → 开雾动画 → IDLE，ring +1
```

**这条链路任何一环断了，都算拓荒失败**，而且失败必须回滚到"雾没动、世界没变"的状态。

## 星球与宇宙（第二层玩法）

地表玩够了，可以往上看。

| 视角 | 按什么键 | 看到什么 |
|---|---|---|
| **地表** `surface` | 默认 | 跟着史莱姆在岛上走 |
| **星球** `planet` | `M` | 刚走过的那座岛**卷成一个球**，可以像 Google Earth 一样绕着转、俯冲 |
| **宇宙** `cosmos` | 再按 `M` / 拉远 | 星球在自己的椭圆轨道上公转，恒星照着它 |

### 三种宇宙形态（这是重点）

宇宙可以是**一颗**，也可以是**很多颗**——取决于你正要做什么。

| 形态 | `planets` | 你的世界在哪 | 典型用途 |
|---|---|---|---|
| **单星球** | 1 颗 | 就是它（`origin=grown`） | 截图、看自己走过的岛孤零零悬在星海里 |
| **当前星球入系**（默认） | 3~7 颗 | 第一颗（`home_planet_id`），其余是邻居 | 想知道"我的岛在星系里长什么样" |
| **纯观测宇宙** | 1~7 颗 | 没有（`home_planet_id=null`） | 只造星系、只看风景，不玩地表 |

规则只有两条：

- **`grown` 最多一颗**——宇宙是你的观测框架，家只有一处。
- **`grown` 那颗的 `world_spec` 不允许被 AI 重写**。你一点点长出来的岛，不能因为"生成一个星系"就被覆盖。

每颗行星有**独立存档**（`world/planets/{id}/`），所以你可以降落在一颗邻居星球上，在那里也拓荒、也扩环，然后随时切回自己的岛。`runtime/world_state.json` 永远只描述"当前所在的那颗"，因此零件 01~38 完全不用知道多星球这回事。

### 三个关键技术选择（都在文件里写清了理由）

1. **不是"在球上重做地形"，是"把已有高度场投影到球面"**（零件 39）。同一份数学，换一种投影。所以河流、湖泊、洞穴、树全部零改动。平面→球形的 1.2 秒卷曲动画，是整个项目最震撼的一秒。

2. **不用 N 体积分，用开普勒解析解**（零件 42）。N 体是混沌的，三颗行星就会飞散——玩家改了参数会看到世界崩溃，而不是"新秩序"。改为恒星+每行星的两体 + 相邻弱摄动（±3%），保证稳定、可预测、可任意跳时间，但仍会"互相拉扯"。

3. **宇宙尺度是压缩的**（零件 41）。真实比例下行星是一粒灰。行星渲染直径固定 0.5~2 RU，轨道 4~60 RU，UI 上明确标注"示意尺度"。

### 编辑星球（到底能改多少）

零件 47 把 43 的基础面板扩成**七组、覆盖世界卡的 14 个字段段**：

① 身份（名字/mood/kind/怪度）· ② 地形（山峰/粗糙/岸宽/破碎）· ③ 水文（浪/水色/有没有河）· ④ 气候（雨雪雾云）· ⑤ 生命（树密度/混合/生物/分区）· ⑥ 时间（一天多长/从几点开始）· ⑦ 轨道（半长轴/偏心率/倾角/质量/卫星）

关键在于**脏状态与成本**：改配色是毫秒级，改地形要重建球面（秒级），改轨道只是参数。UI 上直接标出"点下去要等多久"。

还有一条双向性：**改 `palette` 不只改地表，也改从太空看这颗球的颜色**（辉光、云、海洋都读它）。

### 宇宙里还有什么（不只是球和恒星）

零件 48 补了**十种天体**：

`star` / `planet` / `moon` / **`asteroid_belt`** 小行星带 / **`comet`** 彗星 / **`nebula`** 星云 / **`ring`** 行星环 / **`binary_star`** 双星 / **`black_hole`** 黑洞 / **`ruin`** 遗迹

三个我觉得最值回票价的细节：

- **彗尾背离恒星，不是背离运动方向**——真实彗星尾是太阳风吹出来的。做对这一点，懂的人会认出来。
- **双星的阴影是双重的**——这是"这真是双星"最直观的证据。
- **行星环的轴必须与自转轴对齐**，否则一眼假。

### 物理仿真（改一个数，脚下的世界就变）

零件 49 把三条物理链路接通，全部**可感知**：

| 改这个 | 会看到 |
|---|---|
| 行星质量 → | 跳跃变低、落地压得更扁、走路变慢 |
| 轨道距离 / 恒星亮度 → | 温度带变化：雪线上下移动、雨变雪、水结冰 |
| 行星自转 → | 一天变长或变短 |
| 轴向倾斜 → | 日照角度变化（季节感） |
| 开潮汐 → | 水面缓慢呼吸，涨潮淹掉一点沙滩 |
| 光行时（彩蛋）→ | 时间加速 ×100 时能看出"光追上来了" |

原则写死了：**不追求数值正确，追求因果正确**。恒星质量变大 → 跳不起来，这一天你立刻能感觉到；至于 9.8 还是 9.80665，不重要。

五个开关全部独立，关掉任何一项世界仍可玩。

### 造自己的宇宙

零件 43：AI 或一句话生成 **3~7 颗星球**的宇宙卡（每颗都嵌套一份完整世界卡），网页上有轨道示意图与编辑面板——改名字、换 biome、改三个主色、调天气、拖动"恒星质量/轨道松紧/时间流速"三个滑杆，立刻在 3D 里看见变化。还支持增删星球、单独重新生成某一颗。

两个物理模式：

- `cinematic`（默认）：周期由设定给定，只求好看。
- `realistic`：改恒星质量，**所有行星的周期一起变**（开普勒第三定律），这是"模拟宇宙"的乐趣。

## 预制元素（世界不是只有地形和水）

| 元素 | 零件 | 看什么 |
|---|---|---|
| **地形分区** | 16A | 学 MC 的"高程/湿度/温度"三维分带，任何一个断面都是硬边地层，不是一片均匀绿 |
| **植被分区** | 21A | 分区锁物种：这片只有针叶、那片只有阔叶、雪线以上空着；走 60 BU 会经历 2~4 次"林→空地" |
| **动物** | 23A | 鸟群盘旋落树、鱼群被史莱姆惊散、螃蟹横着走、蝴蝶绕花、夜里 40 只萤火虫 |
| **昼夜** | 20A | 太阳真的走、月亮真的升、星星慢慢转；一整天默认 24 分钟现实时间，可 ×60 |
| **天气** | 20B | 雨有涟漪且史莱姆更透、雪会真的铺白再化、风暴水面更浪且打闪 |

**地形与植物确实借鉴了 Minecraft**：借的是它的**分区算法与分层断面**，不借方块外观。16A 与 21A 里各有一段"为什么要学 MC"的说明，以及对应的账目：高程带怎么变成权重场、生物群系表怎么变成材质判定表。具体到数字：MC 的 62 个生物群系 → 我们的 6 个 `biome` + 每环 1~5 个 `regions`，因为**62 个名字是结果，温度/湿度/高度三个维度才是原因**。

### 两份外部对照表

这两个文件是**设计依据**，不是宣传材料：

| 文件 | 对照对象 | 回答什么问题 |
|---|---|---|
| [docs/MC元素对照表.md](docs/MC元素对照表.md) | minecraftsearch 的**五个分类**：工具 10 / 物品 758 / 方块 1110 / 生物 109 / 世界 108 = **2,095 条目** | MC 有的东西里，哪些值得放进这个岛？ |
| [docs/宇宙模拟软件对照表.md](docs/宇宙模拟软件对照表.md) | SpaceEngine（1:1 尺度全宇宙）、Universe Sandbox（N 体沙盒） | 宇宙模拟到底需要什么？我们为什么故意不做真 N 体？ |

**结论（诚实版）**：

- MC：覆盖约 **2% 的条目**，但约 **40% 的"感觉"**。物品整类不做（没有"用"这个动作）、敌对生物整类不做（调性与"可爱"冲突）。
- 宇宙：**对标 17 项能力，简化 8 项，明确不做 8 项**。最关键的取舍是"不追真实，追因果"——真 N 体会让三颗行星就飞散，玩家看到的是世界崩溃而不是新秩序。

反过来我们也有一件它们都没有的东西：**星球表面是真的能玩的**（走、跳、拓荒、扩环），而且那是自己从地表一点点长出来的。

### 和 MC 内容清单的逐项对照

[docs/MC元素对照表.md](docs/MC元素对照表.md) 把 MC 的 74 个内容项逐条映射到本项目：**24 项已覆盖、22 项简化、28 项明确不做（附理由）**。

三个最关键的对照结论：

| MC 有什么 | 我们怎么做 | 差异 |
|---|---|---|
| 6 大生物群系 + 约 60 变种 | 6 个 `biome` × 每环 1~5 个 `regions` | 用"高程/湿度/温度"三维组合变化，不堆名字 |
| **村庄、要塞、下界、末地、红石、战斗、背包、合成** | **不做** | 本项目是"能散步的岛"，不是生存游戏；怪物会毁掉可爱调性 |
| 世界边界（基岩墙） | **迷雾 + 可拓荒** | **MC 没有这个**，是我们的原创机制 |
| 河流 / 湖泊 / 瀑布 / 洞穴 | 17A / 16B | MC 骨架级的四样，我们做简化但真实可走的版本 |

另外这张表还暴露出三个原本"声明了却没实现"的 biome——`volcanic` / `mushroom` / `swamp` 写在 spec 枚举里，但没有任何零件能生成它们。现在由 **23B** 补齐。

## 地图功能

网页右侧是一张 2D 俯视地图，和 3D 世界共用同一份 `map_tiles.json`：

- 已解锁区块按高度着色（水 / 沙 / 草 / 岩 / 雪）。
- 未解锁区域盖着会缓慢流动的灰雾，和 3D 里的迷雾同色系。
- 史莱姆是一个带朝向的小箭头，身后有 3 秒拖尾。
- 地标是手绘小图标：拱门、巨树、陨石、灯塔、骨桥……
- 鼠标靠近迷雾边缘，地图上会浮出「可拓荒」三个字。
- 滚轮缩放、拖拽平移、双击回到史莱姆、右键在世界里插一个 ping。

## 常见问题

**Q：支持哪几家模型？**
七家开箱可用：OpenAI、Claude（Anthropic）、Gemini、DeepSeek、OpenRouter、本地 Ollama、任意自建/中转。真正需要单独实现的只有三种协议（OpenAI 形态 / Claude 形态 / Gemini 形态），其余复用。可以同时配好几家，主家失败会自动换家（零件 13 的 L0.5）。

**Q：不接 API Key 能玩吗？**
能。零件 13 内置四级兜底：换 provider → 本地模板拼装 → 六套手工预设之一。只是世界会"正常"一些，少一点惊喜。

**Q：为什么 3D 在 Blender 里，不在浏览器里？**
因为你要的是"后台跑 Blender CLI"。Blender 才是真身，网页是驾驶舱：发指令、看日志、看地图、收通知。如果你以后想要浏览器里也能走动，二期加 glTF 导出 + three.js 只读预览，零件 33 已留好接口。

**Q：世界能无限大吗？**
本期 5 个环封顶（ring 0~4，180 × 180）。再往外就要换"分档场景"，属于 v2 的范围——**不过星球化（零件 39）本身就是一种"更大尺度"的扩展**：同一个岛，换个观看距离。

**Q：会覆盖我电脑上的东西吗？**
不会。所有产出都写在约定的 5 个目录里；清理只需删掉这 5 个目录。

**Q：只能是多星球吗？我想只看一颗球。**
支持。宇宙卡 `planets` 允许 1 颗——单星球模式下不画轨道、恒星更近、球占据画面 1/3~1/2。很多时候这反而是最适合截图的状态。

**Q：能改星球吗？能改物理吗？**
能。零件 47 让你改一颗星球的所有字段（地形、气候、生命、时间、轨道、配色），零件 49 让"引力/温度/光的传播"这三条物理真的连到你脚下——把行星质量调到 2.0，史莱姆立刻跳不起来、落地压得更扁。

**Q：能造一个宇宙吗？**
能。零件 43 生成 1~7 颗星球，每颗都是一份完整的世界卡；零件 42 给你三个可感知的物理滑杆（恒星质量、轨道松紧、时间流速）。改一个，整个星系一起变。想加一颗、删一颗、单独重生成某颗都行。

**Q：和 Minecraft 比呢？**
[docs/MC元素对照表.md](docs/MC元素对照表.md) 有完整对照。一句话：**借它的分区算法、分层断面、生物群系判定，不借方块与生存玩法**。地形/植物/动物/天气/昼夜这五样一一对应上了；村庄、战斗、背包、红石、下界这些明确不做。

**Q：有动物吗？有天气吗？会天黑吗？**
有。鸟群/鱼群/螃蟹/蝴蝶/萤火虫（23A）、五种天气（20B）、完整昼夜（20A）。它们都不参与玩法，只负责"世界是活的"。

**Q：一次生成要多久？**
出生岛约 60~120 秒（取决于机器），每扩一环约 20~40 秒。页面会显示阶段进度，卡住超 120 秒会标黄提示。

**Q：AI 会不会把世界生成崩？**
不会。零件 10 的设定卡有 schema 校验和数值钳制，零件 13 有兜底，零件 32 的增量改写只允许动"表皮参数"，不允许动几何基座。

## 边界（这套提示词明确不做的事）

- 不做多人联机。
- 不做移动端精细适配（能看，但不为手机重新排版）。
- 不做模型训练、不训练 LoRA、不做图生 3D。
- 不把 API Key 写进仓库或日志。
- 不追求写实，只追求"一眼可爱、跑得动"。
