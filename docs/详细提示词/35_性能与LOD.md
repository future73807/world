# 35 · 性能与 LOD

> **一句话**：以 Three.js 浏览器默认第三人称实机数据为准，用固定三档区块、实例化、合理剔除和远景降级控制成本；先量，再砍，不用离线统计冒充游戏性能。

零件 23（植被与共享实例齐全）、零件 33（地图与环数逻辑可用）；零件 14/15 的 GLB、manifest 和浏览器流式链路已验收。

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**浏览器运行时性能守门员**。所有帧率、帧时间、draw call、实际渲染三角面和资源内存结论都必须来自 Three.js 游戏。Blender 只可提供源资产/GLB 的离线静态核对，不能作为帧率或运行时剔除证据。

### 步骤 1 · 建立浏览器基线

使用正式资源的浏览器构建，记录硬件、系统、浏览器版本、WebGL 能力、分辨率、设备像素比、asset_version 和测试 seed。固定为 1920×1080 验收条件，开发面板与日志默认隐藏。

在三个默认第三人称场景各预热后运行至少 300 帧：

1. 出生岛常态路线：林地、空地与坡地连续移动。
2. 海岸压力路线：水面、浪花、雾、天空与地形同时可见。
3. 当前最大环压力路线：可见区块和实例最多，仍保持实际走跳与相机避障。

每组记录：

- `requestAnimationFrame` 帧间隔的中位数、p95、最低 1% 帧率及实测 fps；不能只报均值。
- `renderer.info.render.calls`、`triangles`、points/lines（正常应为零或明确诊断用途），以及阴影/后处理是否计入当前统计口径。
- `renderer.info.memory.geometries`、共享几何模板数、材质/程序数、已加载区块与实例数。
- 可用的 JS heap、资源下载与解析字节数；显存若无法直接测量就标“未测”，不得用文件大小伪称显存。
- 静态资源口径：当前版本 manifest/GLB 的唯一几何三角面合计，与每帧实际绘制的三角面分开报告。

写入 `runtime/perf_baseline.md`，结构化数据可同步到 `runtime/perf_baseline.json`。没有基线不得开始“优化”，也不能把离线视口帧率填进报告。

### 步骤 2 · 固定三档地形 LOD

以玩家附近优先、距离和视野共同决定档位：

| 档位 | 参考区块距离 | 每块采样位置 | 每块三角面 | 内容 |
|---|---|---:|---:|---|
| L0 | 不超过 3 块 | 11×11=121 | 200 | 全细节地形、近场植被与完整角色/道具 |
| L1 | 4～6 块 | 6×6=36 | 50 | 同高度函数降采样，减少草花，树用低模 |
| L2 | 超过 6 块且在保留范围 | 3×3=9 | 8 | 远地形与必要的极简远景实例 |

- L0 的 100 块出生岛基础地形合计 **20,000 三角面**；出生岛默认实际渲染场景（水、植被、角色、生物与效果全计）目标 **≤250k 三角面**。
- 三档都使用同一世界高度函数、坐标适配与确定性采样。L1/L2 不是把 L0 网格随意删面，而是按固定世界采样位置重新生成并导出。
- 块内共享顶点；跨块可重复边界坐标，但同档边界必须连续。11×11 是采样密度，不是可见网格，禁止用线框或方格表现 LOD。
- 相邻不同 LOD 的边界还要处理线性插值差：使用明确的交接边缝合或过渡索引，保证同一时刻两侧位置连续。基础档仍按上表计数，任何额外缝合并入完整场景预算和浏览器实测，不能藏在统计外。
- 玩家脚下和即将到达区域提前恢复 L0，远处才降档；玩家走近时不得故意让脚下停留 L2。
- LOD 切换可使用约 0.25 秒过渡，优先安排在雾中或视野边缘。过渡期间新旧碰撞只能有一个权威来源，且不能出现透明洞口、双重地面或位置跳变。

### 步骤 3 · Three.js 实例化与合批

- 树、草、花、贝壳等共享 `BufferGeometry` 与材质，优先使用 `InstancedMesh` 或等价的实例化批次；实例变换、色板变体和 ID 由清单/确定性散布恢复。
- 静态石头、漂流木可按“区块 + 材质”合批，保留流式装卸粒度；不得把整岛合成一个无法剔除的大网格。
- 合并后保留三角面与材质分类，不能靠隐藏一部分实例却让统计仍按全量虚报收益。
- 共享模板数量应随模板种类增长，而不是随实例数增长。区块自有地形 geometry 可随唯一块增加，但必须受驻留集和缓存上限约束。
- 走远再回来、扩环和多次版本切换后，共享模板不得重复创建；记录稳定后的 `renderer.info.memory.geometries` 与实例数证明复用。

### 步骤 4 · 可行的剔除与更新调度

- **视锥剔除**：使用 Three.js 的 `frustumCulled` 机制，并为 Mesh/InstancedMesh 计算正确的包围球或包围盒。实例化对象必须按整批实例范围更新包围体，不能只拿单个模板原点做剔除。
- **距离剔除**：按区块或实例批次管理草花、小道具和远景，玩家跨块或每 100～250 ms 更新一次目标集，避免每帧遍历所有对象。
- **遮挡处理**：Three.js 不把阴影属性当遮挡剔除。优先依靠距离、雾和区块 LOD 降低成本；只有实测证明收益大于 CPU 成本时，才增加区块级遮挡查询或软件遮挡策略。
- **批次粒度**：整批隐藏前应确认范围，不能因为一个实例不可见就错误隐藏整块；也不能为了避免少量剔除而让所有远草始终提交绘制。
- 剔除开关状态可由默认隐藏的开发工具查看，但正式游戏画面不因此出现调试线框或区块标签。

### 步骤 5 · 材质、阴影与后处理

- 主方向光阴影贴图从 1024 起步；若项目已使用 CSM，最多保留 2 级并实测收益。未使用 CSM 时不得虚报级联配置。
- 只让地形、树、大石和史莱姆等主要对象投射阴影；草花默认不投影。接收阴影的对象也要按视觉收益限制。
- `M_Terrain` 等共享材质全局复用，有限色阶不得变成每块一份材质或 shader program。
- 水面、雾、Bloom 等透明/后处理效果分别做同机位 A/B，记录额外 draw call 与帧时间；降低叠层比直接删掉核心气氛更优先。
- 浏览器同屏 **draw call ≤600**。统计口径固定主渲染 pass，阴影和后处理附加 pass 另列，避免通过重置计数掩盖成本。

### 步骤 6 · 浏览器预算表

| 指标 | 出生岛 | 每增一环资源增量 | 满环压力场景 |
|---|---:|---:|---:|
| 基础 L0 地形 | 100 块，严格 20,000 面 | 按新块固定规格 | 依据实际块数另计 |
| 默认实际渲染三角面 | ≤250k | ≤80k | ≤570k |
| 同屏 draw call | ≤600 | 不另放宽 | ≤600 |
| 默认第三人称 1080p 帧率 | 目标 ≥45 fps | 不另放宽 | 目标 ≥45 fps |
| 300 帧中位帧时间 | ≤22.2 ms | 不另放宽 | ≤22.2 ms |
| 共享几何模板 | ≤60 | ≤8 | ≤100 |

资源三角面是版本内容的唯一几何口径，`renderer.info.render.triangles` 是实际提交口径，两者都需报告。帧时间 22.2 ms 对应约 45 fps；p95 和最低 1% 仍须单列，不能用中位数掩盖周期性装卸卡顿。若验收硬件未达到目标，必须如实失败，不得换离线引擎数字凑通过。

**扩展系统的浏览器额外成本**：均采用同机位、同帧数 A/B 测量，单位是该系统开启后增加的帧时间。

| 项 | 预算/约束 |
|---|---|
| 生物 | 近景合计 ≤12k 三角面、≤160 实例；行为分帧调度，近景结构不得删成三角片 |
| 天气 | 额外 ≤3 ms；雨/雪合计 ≤240 面 |
| 昼夜 | 额外 ≤1.5 ms；非关键星空/远天更新可降频 |
| 昼夜 + 天气 | 合计额外 ≤4.5 ms |
| 河、湖、瀑布 | ≤6 个额外水体，合计额外 ≤2.5 ms |
| 洞穴 | 每环 ≤4 个，近景每洞参考 ≤4k 面，远景简化 |
| 巨蘑菇 | 近景每棵约 900～1800 面，按距离简化；不得以 120 面球冠通过 |
| 星球本体（可选） | ≤12k 顶点，浏览器额外 ≤4 ms |
| 大气壳 + 云壳（可选） | 合计额外 ≤2 ms |
| 宇宙视图（可选） | ≤8k 面，额外 ≤3 ms |
| 小行星带（可选） | ≤1200 实例、1 套共享几何，额外 ≤1.5 ms |
| 星云（可选） | ≤6 层、每层 ≤200 面，额外 ≤2 ms |
| 黑洞透镜（可选） | 后处理额外 ≤2 ms；超标则关闭该效果 |

超预算时按“远景草花/小件数量 → 远景生物 → 远环树密度 → 远景更新频率 → 远处 LOD 距离 → 非必要后处理”的顺序降级。近景角色、树木、花草和地标必须先满足质量下限；不得把任何近景模型改成方块或粗糙 primitives，不得改变地形 11/6/3 固定采样规格，也不得靠删除史莱姆、水、雾或昼夜宣称达标。

### 步骤 7 · 世界变大后的降级

第 3～4 环的远处区域默认使用 L2，中距离使用 L1；但判据始终是玩家/相机与实际可见性，而不是环号永久锁死。玩家接近新区域时提前准备 L0，加载失败则保留旧版本和可玩碰撞，不用“雾里等待”掩盖脚下低模或空洞。

流式调度与 LOD 共用优先级：玩家下一块和碰撞 > 镜头前方近块 > 近场共享实例 > 远景。扩环版本切换期间限制并发，避免网络解析、GPU 上传和实例重建同时形成长帧。

### 步骤 8 · 默认隐藏的诊断开关

开发工具可分别关闭生物、天气、昼夜推进、雾、草花、水体、洞穴、蘑菇、星球模式和宇宙模式，用于定位回归。每项关闭后核心循环不得崩溃，开关状态与帧时间写入测试记录。

这些开关不是常驻 HUD，也不是普通玩家必须使用的设置。关闭水、雾、昼夜或核心角色得到的高帧率只能作为 A/B 诊断，不能作为正式预算通过证据。

### 步骤 9 · 实机验收与证据

1. 基线与优化后报告均来自同一浏览器、同一硬件、同一路线和同一统计口径。
2. 实测 L0/L1/L2 分别为 11/6/3 顶点每边、200/50/8 面每块；100 块 L0 为 20,000 面，完整出生岛 ≤250k。
3. 记录一次往返与扩环，证明实例复用、hash 稳定、geometry 数量受控，没有重复模板和内存持续增长。
4. 验证三档过渡与交接边连续，默认跟随中脚下不穿地、远处无明显裂缝或突发双重地形。
5. 出生岛和满环压力路线均报告 fps、中位/p95 帧时间、draw call、实际三角面；达标或失败结论明确。
6. 十个诊断开关各执行一次，记录恢复后的世界状态与帧时间；正式通过数据使用核心效果开启的默认配置。
7. 保存至少四张**浏览器默认第三人称**证据：近场 L0、看中距离 L1、看远景 L2、满环实际游玩。可附同机位调试标注或整岛俯瞰帮助定位，但俯瞰只算诊断，不能替代任何一张默认镜头证据。

## 验收标准

1. 基线、优化后和最终数据均为 Three.js 浏览器实测，硬件、分辨率、路线、版本和统计口径完整。
2. L0/L1/L2 顶点与面数严格符合 11/6/3 和 200/50/8；出生岛 100 块基础地形 20,000，完整场景默认实际渲染目标 ≤250k 三角面，质量优先预算不被旧口径覆盖。
3. 实例化与共享材质生效，共享模板不随实例数线性增长；驻留地形 geometry 有明确缓存上限。
4. 视锥包围体、距离剔除与分帧调度在浏览器真实生效，没有借用无关阴影属性充当遮挡剔除。
5. 默认配置达到 draw call 和帧率预算，或保留明确失败结论；没有用关闭核心效果或离线数据冒充通过。
6. 优化前后包含 fps、中位/p95 帧时间、draw call、实际/资源三角面和 geometry 的对照。
7. 主要截图全部来自浏览器默认第三人称；整岛俯瞰若存在，只作诊断附件。

## 回退方案

- **帧时间仍超标**：先砍草花与小件，再降远景密度和更新频率；重测同一路线，不通过改变固定地形采样规格制造假提升。
- **LOD 切换被看见**：把阈值向外调整、提前预取或优化过渡；不能让玩家脚下保持远档，也不能隐藏整块。
- **跨 LOD 接缝**：检查交接边两侧的插值与过渡索引，缝合几何纳入预算；禁止用线框、挡板或雾墙简单遮盖。
- **实例化后反而卡顿**：检查包围体是否过大、批次是否跨整个世界、材质变体是否过多；按区块和材质重新分批。
- **geometry 或内存持续增长**：排查异步回调重复挂载、共享模板重复创建和版本引用未释放，修复后重跑往返与扩环测试。
