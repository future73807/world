# 35 · 性能与 LOD

> **一句话**：让"5 环的世界"不把机器烧掉：区块分级、实例化、视野剔除、远环降级——先量，再砍。

---

## 前置

零件 23（植被齐了）、零件 33（地图与环数逻辑在）。

---

## 提示词正文

你是**性能守门员**。不要凭感觉优化，一切从数字出发。

### 步骤 1 · 先建基线

在当前场景（出生岛 + 已解锁环）里测三组数字：

1. **静态数字**：总三角面、对象数、材质数、draw call 估算（读 Blender 场景统计或视口统计面板）。
2. **帧时间**：在 3 个固定机位各跑 300 帧，取中位数（不是均值——均值会被偶发卡顿带偏）。
3. **内存/显存**：纹理与网格数据块大小。

把三组数字写进 `runtime/perf_baseline.md`。**没有基线之前不要改任何东西。**

### 步骤 2 · 区块分级（LOD 三档）

| 档 | 条件（以史莱姆为准） | 内容 |
|---|---|---|
| **L0 全细节** | 距 ≤ 3 块 | 地形 11×11 顶点、草花全量、石头、树全模 |
| **L1 中** | 距 4~6 块 | 地形 6×6 顶点直出（同高度函数降采样）、草不生成、花不生成、树用低模 |
| **L2 远** | 距 > 6 块 | 只保留地形 3×3 顶点 + 极简树（一个锥）或干脆不建，视距离 |

- 切换用 0.25 秒交叉淡入，**允许有 LOD 跳变**，但要让跳变发生在"没在看的地方"（屏幕边缘或雾里）。
- L0↔L1 的高度必须一致（同一高度函数降采样），避免接缝错位。

### 步骤 3 · 实例化与合批

- 树：三种模板 + 档位颜色，用链接复制或几何节点实例；**网格数据块数量必须是常数**，不随世界变大增长。
- 草/花/贝壳：实例集合或几何节点散布；单个网格数据块。
- 静态石头/漂流木：允许合并成一个网格（按材质分组合并）。
- 把"同材质小对象合并"当作常规手段：每块地形内的草花可以合并为一个网格（顶点色保留）。

### 步骤 4 · 剔除

- **视锥剔除**：靠 Blender 自带，确认每个对象都开启了"视锥裁剪"。
- **遮挡剔除**：地形区块作为遮挡体，标记 `is shadow catcher` 或引擎对应设置。
- **距离剔除**：给草花加"相机距离 > 45 BU 时隐藏"的简单逻辑（Blender 可用几何节点或单个驱动控制器集中处理）。
- **不要**每帧遍历 100 个对象做判断：用一个控制器对象，每 6 帧批量处理一次。

### 步骤 5 · 材质与阴影

- 阴影贴图：1024（低模世界不需要 4k），级联 2 级足够。
- 关闭"每个对象都投影"：只让地形、树、大石、史莱姆投影；草花不投影（看不太出来）。
- 用共享材质：`M_Terrain` 等每种只有一个实例被大量对象引用，**不要**每块地形生成一个材质副本。

### 步骤 6 · 预算表（硬指标）

| 指标 | 出生岛 | 每增一环增量 | 5 环上限 |
|---|---|---|---|
| 三角面 | ≤ 93k | ≤ 31k | ≤ 218k |
| 对象数 | ≤ 1060 | ≤ 270 | ≤ 2150 |
| 网格数据块 | ≤ 60 | ≤ 8 | ≤ 100 |
| 帧时间（1080p Eevee） | ≤ 18ms | — | ≤ 30ms |

超预算的**优先砍**：草 → 花 → 小石子 → 蝴蝶 → 鸟群数量 → 萤火虫 → 远环树密度 → 地形分辨率。不砍史莱姆、不砍水、不砍雾、不砍昼夜（昼夜是氛围核心）。

**新增预算（零件 20A/20B/23A）**：

| 项 | 预算 |
|---|---|
| 生物三角面 | ≤ 3k |
| 生物对象数 | ≤ 160 |
| 生物行为更新 | 每 6 帧一次 |
| 天气额外帧时间 | ≤ 3ms |
| 雨/雪面片 | ≤ 240 面 |
| 昼夜额外开销 | ≤ 1.5ms（星空旋转每 10 帧一次） |
| 水体（河湖瀑布） | ≤ 6 个水体、额外 ≤ 2.5ms |
| 洞穴 | 每环 ≤ 4 个、每个 ≤ 600 面 |
| 巨蘑菇 | 每棵 ≤ 120 面；mushroom biome 合计 ≤ 1200 面 |
| 星球本体（整球） | ≤ 12k 顶点、额外 ≤ 4ms |
| 大气壳 + 云壳 | 合计额外 ≤ 2ms |
| 宇宙视图（多星 + 轨道 + 星空） | ≤ 8k 面、额外 ≤ 3ms |
| 小行星带 | ≤ 1200 实例、1 数据块、额外 ≤ 1.5ms |
| 星云 | ≤ 6 层、每层 ≤ 200 面、额外 ≤ 2ms |
| 黑洞透镜 | 后处理 ≤ 2ms 或贴图方案 |

### 步骤 7 · 世界变大后的降级

扩到第 3~4 环时，最外环整圈默认以 **L2** 呈现（即使玩家走过去，靠近后升 L0 但要等一下——用"雾里慢慢显形"掩盖加载）。

### 步骤 8 · 开关矩阵（必须能全关）

做一个调试面板，能分别关掉：生物、天气、昼夜推进、雾、草花、水体、洞穴、蘑菇、星球模式、宇宙模式。**任何一项关掉后世界仍可运行**。这是排障与低端机的保险。

### 步骤 9 · 验收

1. 基线三组数字已存。
2. 三档 LOD 生效（走过去能看到区块"变细"）。
3. 网格数据块数量是常数（汇报数字）。
4. 5 环上限时帧时间达标，或不达标但已按上述顺序砍到最低并汇报。
5. 草花在远处确实消失。
5b. 开关矩阵十项（生物/天气/昼夜/雾/草花/水体/洞穴/蘑菇/星球/宇宙）各关一次，世界都能跑（记录帧时间）。
6. 优化前后对比表（三角面、帧时间、draw call）。
7. 截图四张（L0/L1/L2 对比、5 环俯瞰）。

## 验收标准

1. 基线存在且数字真实。
2. LOD 三档生效、无可见接缝错位。
3. 实例化生效（数据块常数）。
4. 预算表逐项对照（达标/超限+已砍）。
5. 优化前后对比表。
6. 四张截图。

## 回退方案

- **帧时间仍超**：先把草砍到 0、花砍一半，再看；这是最快见效且用户最能接受的。
- **LOD 切换被看见**：把切换阈值往远推一块，或让 L1 直接等于 L0 的降采样（差一点但没跳变）。
- **对象数爆炸**（每块草单独对象）：必须合并，不要逐对象隐藏。
