# 08 · 完成通知与变更提示

> **一句话**：跑完了别让人盯着转圈——右上角弹一句「世界有新的变化，快去看看」，并且真的能一点就到。

---

## 前置

零件 06、07。

---

## 提示词正文

你是**信使**。只做通知，不生成世界。

### 步骤 1 · 事件驱动

网页监听 `runtime/events.jsonl` 的新增行（轮询 1 秒或 SSE，二选一，选稳的）。只需要关心三种：

- `job.succeeded` → 成功通知
- `job.failed` → 失败通知
- `job.progress` 里 `stage=done` → 先给"就快好了"

**不要**用前端定时器自己编通知；一切以事件流为准。

### 步骤 2 · 文案规范

| 场景 | 标题 | 正文 | 级别 |
|---|---|---|---|
| 出生岛完成 | 世界有新的变化 | 出生岛已就绪，快去看看 | good |
| 新环完成 | 迷雾退去一环 | 第 N 环已展开，世界变大了 | good |
| 失败 | 生成中断 | 附一句人话原因（超时/脚本异常/产物缺失） | error |
| 排队 | 已排队 | 前面还有 N 个作业 | info |

正文里只要含"去看看"，通知卡片右侧渲染一个高亮按钮「打开 Blender」——点击后：先把当前 `world_state.json` 摘要 toast 一下（告诉用户去哪看），再尝试用系统命令把 Blender 窗口提到前台（拿不到就不做，别报错）。

### 步骤 3 · 通知卡片行为

- 右上角堆叠，最多同屏 3 条，超出收进"更多"。
- 进入动效：从右侧滑入 + 柔和上浮，220ms。
- 自动消失：good 8 秒、info 5 秒、error 不自动消失（需手动关）。
- 有"查看日志"时打开终端抽屉并 `cat` 对应日志。
- 同标题同正文的重复通知 30 秒内合并，角标显示 `×2`。

### 步骤 4 · 页面内"变化"提示

除了 toast，还要在**左栏「世界设定卡」卡片**上加一个小红点，表示"世界已更新"；用户点开卡片后红点清除。地图容器在收到 `map.updated` 时也闪一次边缘光。

### 步骤 5 · 声音（可选，默认关）

提供一个"完成提示音"开关，默认关闭；开启后播放一段 0.3 秒的柔和"叮"。资源用合成音，不引外部音频文件。

### 步骤 6 · 自检

手动往 `events.jsonl` 追加一条 `world.born` 与一条 `job.failed`，观察：

- 两条通知的级别与颜色正确
- "打开 Blender"按钮出现（仅 good 含"去看看"那条）
- 错误通知不自动消失
- 重复追加同一条，30 秒内合并出 `×2`

截图存 `renders/app_step08_*.png`。

## 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `POLL_MS` | 1000 | 事件流轮询间隔 |
| `MAX_STACK` | 3 | 同屏最多 |
| `GOOD_TTL_S` | 8 | 自动消失 |
| `INFO_TTL_S` | 5 | |
| `ERROR_TTL_S` | 0 | 0 = 不自动消失 |
| `MERGE_WINDOW_S` | 30 | 重复合并窗口 |
| `SOUND_DEFAULT` | 关 | |

## 验收标准

1. 手动追加 `world.born`：弹出"世界有新的变化，快去看看"，含高亮按钮。
2. 追加 `job.failed`：红色通知，不自动消失，有"查看日志"。
3. 同一条追加 3 次：合并为 `×3`。
4. 左栏设定卡红点出现，点开消失。
5. 截图三张：成功、失败、合并。

---

## 回退方案

- **事件流被别的进程占用/写坏**：前端轮询改为容错读取，跳过非法行并计一次警告；连续 3 次非法告警提示"events.jsonl 可能损坏"。
- **"打开 Blender" 无法置前**：按钮保留但文案改为"去 Blender 看看"，不再做窗口操作。
