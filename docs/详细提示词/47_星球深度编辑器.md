# 47 · 星球深度编辑器（非驻留界面）

> **一句话**：把整颗星球编辑放进一个可关闭的草稿工作台，预览、校验、撤销后显式应用；不是把地表游戏改成三栏参数后台。

---

## 前置

零件 43、45 完成；地表 G0/G3/G4 已通过。此零件属于可选宇宙章节，不能反向修改地表默认 HUD 或模型。

---

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**星球编辑体验设计师与状态事务工程师**。编辑器的布局从零设计；旧三栏、旧侧栏和旧面板 CSS 不作为输入。编辑的是 spec 草稿，不是导入旧 `.blend` 后改对象。

### 步骤 1 · 编辑范围

按玩家可感知的因果分为 8 组，完整覆盖契约中的相关字段：

| 组 | 字段示例 | 应用后的影响 |
|---|---|---|
| 身份 | `name`、`mood`、`weirdness` | 名称、故事与异形倾向 |
| 地形 | `biome`、`terrain.*` | 新预览的峰、岸与粗糙度 |
| 水文 | `water.*`、河湖水体参数 | 波浪、水色、泡沫与水系 |
| 气候 | `weather.*`、`sky.fog_density/cloud` | 雨雪雾云 |
| 生命 | `trees.*`、`creatures.*`、`regions` | 植被群丛与生物活跃程度 |
| 时间 | `time.*`、`sky.time_of_day` | 昼夜时长和起始光照 |
| 轨道 | `orbit.a/e/inclination/period/phase/mass/moons` | 轨道位置与节奏 |
| 配色 | `palette` | 地表、球面、大气和云壳的统一色板 |

`palette` 的修改必须在同一资源版本中传播到地表与太空外观。不能出现网页颜色变了、GLB/球面仍旧色的两套状态。

### 步骤 2 · 从零设计工作台布局

- 通过 Esc/宇宙观察状态的明确“编辑”入口打开；默认地表 HUD 不包含编辑器按钮组。
- 打开后进入一个独立的全屏工作台，背景为同一 Three.js 场景的轻量星球预览；游戏输入暂停，旧玩家/相机状态封存。
- 顶部使用横向星球选择器和明确的“完成/返回”；不得形成左列表+中预览+右表单的旧三栏。
- 8 组字段放入底部可展开的抽屉或按需切换的单个编辑页，一次只呈现一组；预览始终保留足够面积。
- 窄屏变为全屏分页：预览页 ↔ 编辑页，不横向挤压三列。
- 控件根据数据选择：枚举分段按钮、数值滑杆+可输入数字、颜色色块+拾色器；区域列表一次编辑一项，不堆多卡片。
- 文本输入、滑杆、快捷键不穿透；Esc 若有未保存草稿先提示，不直接丢失。

### 步骤 3 · 草稿、脏状态与应用

- 所有修改先写入独立 draft，不直接覆盖正式 spec、GLB 或当前世界状态。
- 每组显示少量脏标记，底部固定“应用更改（N）”与“放弃草稿”；按钮标明预计成本。
- 改配色/时间/气候可快速预览；改地形/水文/轨道需要候选资源重建或校验时，显示轻量进度并锁定冲突操作。
- 应用只更新受影响部分：配色/时间参数、轨道参数或球面网格，不重建无关地表区块。
- 新版本完整验证后一次提交；失败继续使用旧版本，草稿与错误保留，不能清空玩家工作。

### 步骤 4 · 校验分级

| 情况 | 处理 |
|---|---|
| 山顶过多、树太密、沙滩过宽等审美风险 | 黄色提示，允许用户继续 |
| 轨道重叠、realistic 模式违反约束、星球数超范围 | 阻止应用并指出具体字段 |
| 输入缺字段/类型错误 | 按契约补默认值或要求修正，不能悄悄生成另一套 schema |
| 资源生成失败/hash 不一致 | 不发布，保留旧版本与可诊断错误 |
| 会导致当前家园存档被覆盖 | 强制二次确认并提供备份；默认禁止对进行中的地表做无提示重建 |

美学怪异性不拦截，结构、数据和存档冲突必须拦截。

### 步骤 5 · 撤销与历史

- 撤销栈至少 30 步，滑杆拖动结束合并为一步，Ctrl+Z / Ctrl+Shift+Z 只作用于草稿。
- 历史使用人类可读描述；切换星球前提示保存/放弃，不能悄悄清空撤销栈。
- 已应用版本与未应用草稿分开，撤销草稿不能误回滚已发布地表状态。

### 步骤 6 · 预设、复制与导入导出

- 可另存 spec 预设、复制星球和导入/导出 JSON；这些都是数据操作，不能导入旧模型或外部游戏资源。
- 复制后必须修改身份并给出色板/地形等至少三处明显差异，避免克隆世界。
- 导入先校验并展示字段差异，用户确认后才替换草稿；不能直接覆盖正式星球。
- 重置默认回到上次已应用草稿；“恢复出厂”是独立危险操作，必须确认并创建备份。

### 步骤 7 · 关闭与实机验收

1. 从地表和 cosmos 分别打开/关闭工作台，均回到正确的原观察状态，无角色/相机重置或输入穿透。
2. 逐组修改相关字段，配色在地表/太空一致，轨道和气候因果与预览一致。
3. 应用前正式 spec 不变；成功后版本一次更新，失败时旧版继续可玩。
4. 30 步撤销、切星球草稿提示、校验分级和导入差异预览正确。
5. 桌面与窄屏均无三栏挤压、横向滚动或控件遮挡预览；编辑器不属于地表默认 HUD。
6. 保存桌面/窄屏截图和一段打开→编辑→应用→关闭→继续游玩的连续录屏。

---

## 验收标准

1. 编辑器为从零设计的非驻留工作台，无旧三栏结构，不污染默认地表 HUD。
2. 契约相关字段完整可编辑，草稿、应用、失败回滚和版本一致性正确。
3. 配色、时间、气候、轨道等因果有实机证据，未做的能力标“未做”。
4. 撤销、校验、预设、复制、导入导出和关闭恢复均通过。
5. 没有导入旧模型或外部游戏资源；所有新视觉符合原创低模方向。

---

## 回退方案

- **预览太慢**：降低同一 Three.js 预览的更新频率或 LOD，不换成静态截图冒充实时应用结果。
- **字段太挤**：保持一次一组的分页，不恢复固定左右栏。
- **撤销记录爆炸**：按控件提交合并事务，不在每个指针移动事件创建历史。
- **应用后状态不一致**：取消发布并恢复旧 spec/版本指针；先修事务，不刷新页面掩盖。
