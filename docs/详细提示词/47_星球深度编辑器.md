# 47 · 星球深度编辑器

> **一句话**：43 的编辑面板只能改名字和几个色。这一零件把它做成**能改一整颗星球**的东西——分七组、可撤销、有脏标记、有预览、有校验。

---

## 前置

零件 43（宇宙卡与基础编辑区）、10（世界卡字段全集）、45（视角状态机）。

---

## 提示词正文

你是**星球编辑器**。目标：让"改一颗星球"变成一件顺手的事，而不是在 JSON 里手改。

### 步骤 1 · 编辑对象的范围（一张星球卡里到底有多少可改的）

世界卡（契约 F）有 **14 个顶层段**。43 只暴露了 5 个。这一零件按"玩家能感知的因果"重新分组：

| 组 | 字段 | 改了什么会立刻变 |
|---|---|---|
| **① 身份** | `name`、`mood`、`kind`、`weirdness` | 名字、悬停卡文案、整体怪度 |
| **② 地形** | `biome`、`terrain.peak_height`、`roughness`、`beach_width`、`island_bias` | 山有多高、岸有多宽、岛是否破碎 |
| **③ 水文** | `water.wave_height`、`tint`、`foam`；河流/湖泊数量（17A） | 浪、水色、有没有河 |
| **④ 气候** | `weather.kind`、`intensity`、`frequency`、`wetness`；`sky.fog_density`、`cloud` | 雨雪雾云 |
| **⑤ 生命** | `trees.density`、`weights`、`creatures.*` 五项、`regions` 数组 | 绿多少、活多少 |
| **⑥ 时间** | `time.cycle_minutes`、`start_hour`、`day_night`、`sky.time_of_day` | 一天多长、从几点开始 |
| **⑦ 轨道** | `orbit.a`、`e`、`inclination`、`period`、`phase`、`mass`、`moons` | 在星系里的位置与节奏 |
| **⑧ 配色** | `palette` 十色 | 全部色相（**会连带影响天文外观**） |

**重要**：⑧ 配色是**双向**的。改 `palette` 不只改地表，也改"从太空看这颗球是什么颜色"（零件 44 的辉光、云、海洋都读它）。所以编辑器里要给一句提示：*"改这里，太空中的这颗球也会变。"*

### 步骤 2 · 交互骨架（七组面板）

- 左侧：星球列表（可拖动排序 = 调整轨道顺序）。
- 中间：3D 预览（就是零件 40/41 的星球视图，**实时反映编辑**，但用 L2 低精度）。
- 右侧：七组折叠面板。默认只展开"① 身份"。

每组内的控件：

| 字段类型 | 控件 |
|---|---|
| 枚举（biome/weather/kind） | 分段按钮（segmented），不要下拉——一眼看全 |
| 数值有范围 | 滑杆 + 右侧可键入的数字框（滑杆不能精确输入，必须能键入） |
| 颜色 | 色块 + 拾色器；同时给三个 HSL 小滑杆（很多"好看的颜色"用 HSL 才好调） |
| `weights`（三个树的权重） | 三根滑杆，**自动归一化**（改动一根，其余按比例缩） |
| `regions` 数组 | 卡片列表，可增删、每张卡内是 elevation/moisture/temperature 三个小滑杆 + `note` 输入 |
| 颜色/数值的"超范围" | 钳制并在控件旁闪一下红边 + tooltip 说明被夹到哪 |

### 步骤 3 · 脏状态与"应用"

43 说过"编辑不自动重建"。这一零件要把这条做成**可见的心智模型**：

- 任何改动 → 该组标题出现一个**橙点**，顶部出现「应用更改（N）」按钮。
- 编辑**永远不阻塞**：可以连续改 30 个字段，最后一并应用。
- 「应用更改」= 只重建**受影响的部分**，不是重建整颗：
  - 改配色 → 只换材质参数（毫秒级）
  - 改地形/水文 → 重建球面网格（秒级）
  - 改轨道 → 只更新轨道参数（毫秒级）
  - 改时间/气候 → **完全不用重建**（只是参数）
- 给一张"改动 → 重建成本"对照表贴在按钮旁，让用户知道自己点下去要等多久。

### 步骤 4 · 撤销与历史

- **撤销栈**：≥30 步，`Ctrl+Z` / `Ctrl+Shift+Z`。
- 粒度：一次"控件提交"算一步（滑杆拖动结束算一步，不是每帧）。
- 历史面板：可看到"12 步前：把降水从 0.3 改成 0.7"这种可读描述。
- **切换星球时栈清空**（不要跨星球撤销，会产生"我在改哪颗"的困惑），但给出提示"已切换，撤销历史已重置"。

### 步骤 5 · 双向同步与冲突

- 若用户同时在 Blender 里手动改了场景（例如挪了一棵树），编辑器不知道。
- 规则：**编辑器只改"卡"，不读场景**。场景里手改的东西视为"临时"，下次应用更改时被覆盖。UI 上要能说清这一条（一句小字）。
- 若 AI 正在生成这颗星球：编辑面板**只读**并显示"生成中，稍后编辑"。

### 步骤 6 · 校验与提示（不做硬拦截）

| 情况 | 提示 | 是否阻止 |
|---|---|---|
| `peak_height` 高到岛上没有平地 | 黄字"山顶占满整岛，可能走不上去" | 否（允许，只是难看） |
| 树密度 400 但岛只有 100BU | 黄字"会非常拥挤" | 否 |
| `beach_width` + 岛尺度导致没有内陆 | 黄字"岛上可能只有沙滩" | 否 |
| 轨道 `a` 与邻居冲突 | 红字"会与 {邻居} 重叠" | **是**（这是硬冲突） |
| `period` 与 `a` 违反开普勒（realistic 模式） | 自动修正并提示 | 是（自动改） |
| 星球数修改后 < 1 或 > 7 | 阻止 | 是 |

**设计原则**：美学上的怪**永远不拦**，只提示；物理/结构上的不可能**才拦**。玩家想造一个"全是悬崖的岛"是他的自由。

### 步骤 7 · 预设与复制

- 每颗星球可「另存为预设」（存 `specs/presets/planet_{slug}.json`）。
- 「复制这颗」= 完整克隆一份（含色板与区域），然后**强制改三处**（名字加后缀、色相 +40°、biome 换相邻值）——避免造出克隆星。
- 「重置这颗」= 回到上次应用的状态（不是回到出厂，除非明确选"恢复出厂"）。

### 步骤 8 · 导入 / 导出

- 导出单颗星球的 `world_spec` 为 JSON（可分享）。
- 导入一份 JSON → 校验 → 替换某颗星球（应用前先预览差异：一张"字段 / 旧 / 新"的对照表）。
- 也支持整个 `universe_spec.json` 的导入导出（与 43 一致）。

### 步骤 9 · 验收

1. 14 段字段**全部可改**（逐个点一遍），无遗漏。
2. 改配色 → 太空中那颗球的颜色**也变**（截图对比两张）。
3. 脏点、应用按钮、"重建成本"对照表都正确。
4. 撤销 30 步、切换星球清栈。
5. 六类校验提示各触发一次（只有两项阻止）。
6. 复制星球强制产生三处差异。
7. 导入预览能列出字段差异。
8. 六张截图（七组面板、脏状态、成本表、历史、校验、复制差异）。

## 验收标准

1. 14 段全覆盖。
2. 配色双向生效（地表 + 太空）。
3. 脏状态与成本提示清晰。
4. 撤销栈正确、切星球清栈。
5. 校验分级正确（美学不拦、结构拦）。
6. 复制/预设/导入导出可用。
7. 六张截图。

---

## 回退方案

- **面板太挤**：把 ⑤ 生命 与 ④ 气候 合并为一组"环境"，七组变六组。
- **实时预览掉帧**：预览从 L2 降到"静态截图 + 应用后刷新"。
- **撤销太粗**（一次拖滑杆算很多步）：在 drag 结束事件里合并，不要用 change 事件。
- **用户改崩了**：提供"恢复出厂"，并保留一份带时间戳的宇宙卡备份（`specs/backup/` 下）。
- **HSL 滑杆与色板冲突**：以 HSL 为准，反向更新色块；两者不要各写各的。
