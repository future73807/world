# 26 · 精致史莱姆动画与开放世界运动表现

> **一句话**：从起步到落地都有连贯姿态、速度匹配和局部滞后，让角色像有重量的果冻，而不是只循环缩放的身体。

你是**角色动作导演与实时动画工程师**。造型、材质、控制器和动画共同决定精致感。Blender 只离线制作新动画资产；浏览器负责状态机、混合、局部叠加与事件反馈。禁止读取恢复包动画或用 Blender Python 逐帧驱动正式玩法。

### 步骤 1 · 完整动作集合

至少制作并导出以下命名片段：

| 片段 | 主要内容 | 触发/循环 |
|---|---|---|
| `IDLE` | 呼吸、微小重心变化、自然眨眼 | 循环 |
| `START` | 身体轻微预倾、眼神先看向移动方向 | 起步触发 |
| `MOVE` | 与速度匹配的主腹起伏、前倾和底部重量感 | 移动循环 |
| `STOP` | 短促前冲、回稳与视线保持 | 停止触发 |
| `TURN` | 眼睛先导、主腹滞后转向、底缘稳定 | 明显转向 |
| `JUMP_ANTICIPATE` | 下腹压缩、视线集中、顶部略滞后 | 起跳前 |
| `AIR_RISE` | 主体拉伸、顶部跟随、表情轻快 | 上升 |
| `AIR_APEX` | 短暂回稳、视线观察 | 顶点附近 |
| `FALL` | 身体略收、向下观察、准备落地 | 下落 |
| `LAND_LIGHT` | 小幅压缩和一次柔和回弹 | 轻落地 |
| `LAND_HEAVY` | 更明显压缩、底缘稳定和核柔亮 | 重落地 |
| `CURIOUS` | 歪头、视线关注、轻微前倾 | 可打断 |
| `SLEEP` | 闭眼、慢呼吸、身体放松 | 循环 |

每个片段记录目标节点、形态键、时长、循环边界和事件点，不烘焙世界位移或相机。

### 步骤 2 · 待机与表情精修

- 呼吸不是机械正弦缩放：主腹、顶部和底缘有轻微相位差，体积变化保持自然。
- 眨眼间隔在约 2.5～6 秒间确定性变化，可有偶尔连续轻眨；不能每 4.8 秒机械重复。
- 眼神先关注目标，身体再跟随；移动、暂停和互动时表情切换有 anticipation 与 settle。
- 眼睛闭合使用 24 的眼睑/局部形态，不把眼睛直接缩没或藏进身体。

### 步骤 3 · 起步、移动、停止与转向

- `START` 在速度上升初期播放，前倾幅度随加速度变化；短促输入不能被长动画拖住。
- `MOVE` 的播放速度与浏览器实际速度匹配，身体起伏频率与位移对应，避免原地跑步和滑步。
- 主腹、顶部与面部有少量分层滞后，但底缘接触稳定；不能全身统一摆动像钟摆。
- `STOP` 由减速度和前冲量决定强度，停止后自然回 IDLE，不出现速度已为 0 身体仍跑。
- `TURN` 在角速度超过阈值时叠加，角色朝向平滑跟随移动方向，鼠标环视不强迫身体瞬间转动。

### 步骤 4 · 跳跃与落地

- 起跳前压缩 0.08～0.12 秒，上升拉伸、顶点回稳、下落准备构成完整弧线。
- 起跳、离地和落地由 27 的控制器事件决定，动画不能自行修改根位置或决定落地。
- 落地强度由实际下落速度/高度选择 LIGHT/HEAVY，压缩幅度与材质柔亮连续变化。
- 底缘保持稳定接触，主腹和顶部承担变形；最大压缩时面部、法线和透明层不能穿帮。
- 落地镜头反馈、粒子和声音（若有）只触发一次，支持 reduced motion。

### 步骤 5 · 浏览器状态机与混合

状态机至少包含：

`IDLE / START / MOVE / STOP / TURN / JUMP_ANTICIPATE / AIR_RISE / AIR_APEX / FALL / LAND / CURIOUS / SLEEP`

- 状态由速度、加速度、角速度、接地、垂直速度、互动与 AI 共同驱动。
- 常规切换混合 0.08～0.16 秒；起跳/落地可更快，视线/表情可更慢，不能所有状态固定同一淡入。
- 新输入可打断，但必须收敛姿态，不能冻结在当前形变或残留轨道锁根。
- 动画只负责视觉形，27 负责位移和碰撞；通信通过浏览器事件，不经过文件/MCP/Blender。
- 暂停、失焦、资源切换和断线恢复不补播一大段动画，不重置当前动作。

### 步骤 6 · 参数与个性

`bounce` 影响挤压、回弹和跳跃幅度，但不改变碰撞体大小：

- 低 bounce：压缩小、回弹短、移动更安静。
- 高 bounce：相位差和回弹更明显，但不能夸张到穿模或晕眩。
- 性格影响视线、停顿和动作偏好，不能靠给同一动画随机倍速就宣称不同性格。
- 重力、天气和材质状态可叠加，但优先级明确，不相互覆盖基础运动。

### 步骤 7 · 性能与精修验收

- 使用少量骨骼/形态键/局部叠加，避免高密度软体与多层根缩放；记录轨道、混合和内存开销。
- 录制连续“待机→起步→移动→停止→急转→跳→轻/重落地→互动”的桌面与触屏操作。
- 检查速度/动画匹配、起步停止、转身、坡面、落地接触、视线与混合，无明显滑步、弹跳相机或穿模。
- 以 30/60fps 和模拟长帧验证，不靠提高帧率掩盖状态机问题。
- 关闭 Blender 后全部成立；保存高保真近景录屏和浏览器性能数据。

## 验收标准

1. 完整动作集合与浏览器状态机覆盖起步、移动、停止、转向、跳跃各阶段和落地。
2. 动画与真实速度/碰撞同步，无明显滑步、机械循环、瞬间换向或残留形变。
3. 局部滞后、眼神、材质和落地反馈共同形成精致果冻手感，近景无穿插。
4. 桌面/触屏、30/60fps、暂停恢复与资源切换全部通过，关闭 Blender 仍成立。
5. 连续高保真录屏与性能数据完整，不仅提交几张缩放截图。

## 回退方案

- **像机械伸缩**：检查局部相位、速度匹配和状态过渡，不增加无意义动作数量。
- **滑步**：以真实位移修播放速率和控制器，不用镜头遮挡。
- **变形塌陷/脸穿出**：回 24 修拓扑和形态键，不删除近景表情。
- **切换跳变**：修轨道优先级和收敛姿态，不简单把所有混合时间加长。
- **性能不足**：减少不可见叠加和远景动画更新，不降低玩家输入采样和近景动作质量。
