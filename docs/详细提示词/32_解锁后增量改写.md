# 32 · 解锁后增量改写（新环 GLB 与原子发布）

> **一句话**：扩环只导出那一圈 10 BU 宽的新带与完整候选 manifest，旧 GLB/hash 一个不动；服务端验证完整后发布，浏览器预载并原子接入，玩家和相机始终不变。

---

## 前置

零件 15（区块框架）、零件 30（状态机与发布边界）、零件 31（新环 spec 已就绪）。

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**增量资源工程师与浏览器版本切换验收者**。核心只有两句：**只生成新东西，接缝要融合；只发布完整版本，切换不重置游戏。** Blender CLI 离线生成新环资产，Three.js 浏览器保留旧场景并增量接入 GLB，不存在把 `.blend` 对象追加到实时玩家场景的步骤。

### 步骤 1 · 几何关系

与零件 01 的契约保持一致：

- 环 r 的世界边长 = `100 + 20 × r`。初始 `S=100`，每扩一环总边长 +20 BU，即每边各外扩 10 BU，正好一个区块宽。
- 旧世界占据新世界的中心区域：新坐标范围 `[-(S+20)/2, +(S+20)/2]`，旧范围 `[-S/2, +S/2]`。
- 新增区域是外框减去旧框的“口”字带，带宽 10 BU = 一个区块；扩环永远落在区块边界上，不切碎旧区块。
- 网格边长 `g_新=g_旧+2`，初始 10，扩一环为 12；`island_size_新=island_size_旧+20`，增长量只引用契约 `RING_STEP=20`。

### 步骤 2 · 只生成新带

- 只生成新带内的区块：外环区块索引 `cx,cy ∈ 0..(g+2)`，其中 g 为旧网格边长，并排除旧框内区块。
- 旧区块 GLB、LOD、共享几何、材质、URL 与内容 hash 不重新生成、不改写；旧浏览器实例也不删除重建。
- 新环的树、草、道具、水体、生物、地标和碰撞只写入新带。可复用已有共享 GLB，但不得为复用而修改旧资源内容。
- 新区块坐标落在全局区块网格上，加载后与旧区块共享同一坐标适配、原点与尺度。

### 步骤 3 · 新环一侧的接缝高度融合

高度函数读取“该点所属环”的 spec，旧环已经烘焙的高度永远不重新求值写回。

- 每个新区块按全局区块中心确定 `ring_of(cx,cy)`，使用该环 spec 生成新高度。
- 在旧边界线上，新环边界顶点必须直接采样旧版同源的边界高度/法线，保证坐标与法线判定一致。
- 从新环边界向新带内部设置默认 8 BU 的过渡带：`t=smoothstep(到旧边界距离 / 过渡宽度)`，新顶点高度由“旧边界延续高度”平滑过渡到新环原始高度。
- 过渡只发生在**新环一侧**。不存在需要修改旧顶点的“跨环区块”，也不许为了视觉连续性重算旧 GLB。
- 新带内水岸、植被和碰撞采样使用同一份最终新高度，避免视觉无缝但角色脚下有台阶。

### 步骤 4 · 新环 GLB/manifest 增量导出

离线生成作业输出一个不可变候选 `asset_version`，不得覆盖当前版本：

1. 新带每个区块、每个所需 LOD 导出独立 GLB；地形、植被、生物、水体、地标和简化碰撞引用同一份最终新环数据。
2. 新共享角色/植被等资源写入候选 `shared/` 或复用旧版本已验证条目；材质按稳定名称与 hash 复用，不无意义复制。
3. 导出与该版本配套的小地图数据、边界/可站立信息和可编辑的新环源 `.blend`。源工程用于开发者复查，不是浏览器加载入口。
4. 候选 `manifest.json` 必须完整描述切换后的世界：保留全部旧区块条目及其原 URL/hash，追加新区块/LOD/ring/bounds/hash，追加或复用 shared，并写入新 `asset_version`、world_seed、ring、island_size、map_url、spec_hash。
5. 若候选目录物理上只存新增文件，manifest 中旧条目可以引用仍保留的旧版本 URL；不得复制旧文件后给出一个不同 hash，也不得让旧 URL 指向会被覆盖的“latest”。
6. 所有必需文件写完、hash 与结构校验通过后，才把候选标记为“完整”。服务端只有收到完整候选并通过零件 30 的发布校验，才能原子切换当前版本指针。

### 步骤 4B · 浏览器预载与原子切换

浏览器收到 `ok` 结果后，不刷新页面、不重载整岛，按以下顺序执行：

1. **继续旧版本**：旧地形、旧碰撞、旧雾和玩家输入正常可用；下载与解析候选新环在后台进行。
2. **完整预载**：验证 manifest 身份与 hash，加载新环所有近场必需 GLB/LOD、共享依赖、碰撞和地图。缺失任何必需资源都不进入激活步骤。
3. **帧边界一次提交**：把已准备的新环根组加入 Three.js 场景，更新资源流送器的当前 manifest/世界边界、碰撞查询、小地图与雾目标；不得出现半圈新块或一帧无碰撞。
4. **旧内容保持原实例**：旧区块不重新实例化、不改 transform、不换材质；共享缓存继续复用。后续 LOD 可以按正常规则变化，但不能改变旧资源 hash。
5. **游戏状态连续**：玩家位置、朝向、速度、当前输入、动画状态，以及相机位置、yaw、pitch、dist、弹簧速度和目标点全部保留。不得回出生点、不得重新默认环视、不得因扩环顿一下后重置镜头。
6. **提交后再开雾**：零件 30 的 REVEALING 只操作浏览器表现；失败时旧场景仍在，可按旧版本回滚。

### 步骤 5 · 每环新增预算

| 项 | 预算 |
|---|---|
| 区块数 | `4*(g+2)-4` 个边缘块，g=10 时 44 块 |
| 实际渲染三角面 | ≤80k |
| 树 | 约 `0.6 × 初始树数` |
| 草 | ≤900 实例 |
| 地标 | ≤1 |

超过就按草、小件、远景密度顺序降级，不降地标，不把树木改成方块。

### 步骤 5B · 新元素的增量规则

扩环不只加地形，还要加区域、植被与生物。规则是：**新环的新东西不许动旧环的旧东西。**

| 元素 | 扩环时怎么做 | 绝对不许 |
|---|---|---|
| **区域**（16A） | 新环 regions 由新 spec 提供；旧环权重场和已烘焙高度不重算 | 因 regions 变多而重写旧块高度 |
| **植被**（21A） | 只在新带按新 tree_mix 散布，复用共享 GLB | 重建旧树或改旧实例位置 |
| **生物**（23A） | 新带补充鸟/鱼/蟹/蝶/萤火虫；旧带行为路径中心不迁移 | 重新分布全岛生物 |
| **天气**（20B） | 全局切换，浏览器当前天气状态在版本切换中连续 | 半个世界晴、半个世界雨 |
| **昼夜**（20A） | 全局，只有 ring 0 的 time 生效；切换不重置时钟 | 每环一个时钟 |
| **水体**（17A） | 新带泉眼/河/湖只在新带生成，旧河不改 | 让旧河改道或重新挖槽 |
| **洞穴**（16B） | 新带按新 spec 生成，旧洞与入口零改动 | 在旧环边缘补洞或改洞 |
| **蘑菇/湿地**（23B） | 新带按 biome/regions 散布 | 重建旧环植被 |
| **星球化**（39） | 若启用，派生球面副本整体重投影并随完整版本发布 | 只更新新环球面顶点留下空洞 |

天气与昼夜是世界属性，玩家站在接缝上不能“左脚晴右脚雨”。星球化重投影只改派生球面副本，地表旧区块 GLB/hash 仍不变。水与洞穴涉及几何，因此必须局部；旧河即使在新地形旁略显不合理，也不得以改旧河破坏 hash。

### 步骤 6 · hash 与发布验证（硬验收）

1. 导出前读取当前 manifest 与 `runtime/chunk_hashes.json` 中所有旧块条目，使用零件 15 统一的规范化 hash 口径。
2. 候选导出后逐块核对：旧条目 id、URL 或稳定资源身份、各 LOD hash 与变换约定必须 100% 保持一致；需要重算时只读旧文件，不重写。
3. 验证新区块 hash、边界、ring、LOD 与文件实际内容一致，所有 manifest 引用可读取且无缺失。
4. 验证 `world_seed/ring/island_size/spec_hash` 与请求和状态快照一致，候选版本号不可与已发布版本冲突。
5. 任一旧块变化或新资源缺失，候选立即失败，**服务端不得发布**；输出具体块、LOD、URL 与 hash 差异。

这项必须是自动检查，不能用“截图看着没变”代替。浏览器激活后还要确认旧场景实例未被替换，玩家/相机状态前后数值一致。

### 步骤 7 · 浏览器视觉与操作验收

1. 玩家站在旧边界朝新区域看，地形连续、色调渐变、无贴片感；沿横切线采样，接缝无异常阶跃。
2. 第三人称从新环走回旧环，视觉与碰撞一致，没有区块消失、突然浮空或雾/墙版本不同步。
3. 新带树/草/水域/生物符合新 spec；旧树、石头、地标位置与旧 GLB/hash 零变化。
4. 扩环前后记录玩家位置、朝向、动画与相机完整状态，提交点无重置；同一机位新旧对比可辨认“只多了外环”。
5. 雾墙由零件 30 移到新边界，地图、碰撞与 manifest 同属新版本。
6. 保存 `renders/step_32_seam.png`、`step_32_before.png`、`step_32_after.png`、`step_32_switch.webm` 与 hash/状态对比；整岛俯瞰只能另标诊断图。

### 步骤 8 · 回滚

- **发布前失败**：当前指针、状态与旧场景不变；候选标失败并保留诊断，浏览器不显示候选内容。
- **预载失败**：浏览器继续旧版本，释放未激活的候选缓存；服务端依据零件 30 保持或恢复旧指针/状态，玩家不受打断。
- **激活校验失败**：不执行帧边界提交；若服务端已发布，则按备份恢复旧世界状态和旧版本指针，并给轻量错误提示。
- **提交后诊断失败**：由于提交本身不可分，测试发现异常即停止开雾并切回保留的旧版本组；不得通过删除旧资源或刷新页面掩盖。
- 旧 GLB/manifest 至少保留到浏览器完成确认且回滚窗口结束。失败候选、日志和 hash 报告保留，不删证据。

## 验收标准

1. 新带各 LOD GLB、共享依赖、地图/碰撞和完整候选 manifest 一次性备齐，服务端只在验证全部通过后发布。
2. 旧区块/LOD hash 100% 不变，旧场景实例、transform 与材质不被替换；自动报告可定位差异。
3. 新环一侧 8 BU 融合带连续，横切采样无 >0.5 BU 异常阶跃，视觉、碰撞和高度函数一致。
4. 浏览器后台预载并在帧边界原子接入，无半圈、空白或整岛刷新；玩家位置/输入/动画和相机 yaw/pitch/dist/弹簧状态完全连续。
5. 新环区域、植被、生物、水体与地标完整，旧环路径、河道、昼夜和天气状态不被重置。
6. 发布前失败、预载失败和激活失败均有可用回滚，旧版本可继续游玩，证据完整。

## 回退方案

- **hash 总有几块不一致**：检查生成器是否读取了可变当前场景或覆盖旧 URL；恢复只读坐标 + spec 的纯函数与不可变版本目录。
- **接缝有明显台阶**：确认过渡只在新侧且边界顶点直接采用旧边界采样；在 10 BU 新带宽度内调整 smoothstep，不去改旧块。
- **共享材质冲突**：优先按契约名称/hash 复用；确需新变体时加新环后缀，但不得覆盖旧同名材质。
- **浏览器切换时闪空或重置玩家**：把加载与激活分开，只有全部准备后才一次提交；禁止以页面 reload 或重建玩家控制器实现扩环。
- **每环内存变重**：按零件 35 调整非近场 LOD 与流送，保留不可变源资源和旧 hash，不删回滚所需版本。
