# 32 · 增量生成新环（旧地形零改动）

> **一句话**：扩环只生成"那一圈 10 BU 宽的新带"，旧区块一个顶点都不许动——并且在边界处无缝融合。

---

## 前置

零件 15（区块框架）、零件 31（新环 spec 已就绪）。

---

## 提示词正文

你是**增量工程师**。这是整包最容易翻车的一步，核心只有一句：**只碰新东西，接缝要融合。**

### 步骤 1 · 几何关系

全包统一的口径（与契约 A、零件 01 一致）：

- 环 r 的世界边长 = `100 + 20 × r`。初始 `S = 100`，每扩一环**总边长 +20 BU**，即每边各外扩 **10 BU**（正好一个区块宽）。
- 旧世界占据新世界的中心区域：新坐标范围 `[-(S+20)/2, +(S+20)/2]`，旧范围 `[-S/2, +S/2]`。
- 新增区域 = 新的外框减去旧框，形状是一圈"口"字带，**带宽 10 BU = 一个区块**。这让扩环永远落在区块边界上，不会切碎区块。
- 网格边长：`g_新 = g_旧 + 2`（初始 10，扩一环 12）。

一次扩环后：`island_size_新 = island_size_旧 + 20`。这个数字只允许在一处定义（契约 `RING_STEP = 20`），其它零件一律引用，不许各写各的。

### 步骤 2 · 生成范围

- 只生成"新带"内的区块：外环区块索引 `cx,cy ∈ 0..(g+2)`，其中 `g` 为旧网格边长，且排除"旧框内"的区块。
- 旧区块**不重新生成、不重建、不重算哈希**。
- 旧区块的集合、对象、材质**保持原引用**，不做"删了再建"。

### 步骤 3 · 高度函数如何换 spec

关键设计：高度函数读的是"该点属于哪一环"的 spec。

- 每个区块算一个"归属环"：`ring_of(cx,cy)` 由它的中心距中心坐标决定（按新边长分环）。
- 生成某块时，用 `ring_of` 对应的 spec 求值。
- **边界带的融合**：对于"跨环边界"的区块（即部分在旧环、部分在新环），高度取值用 `lerp(h_old, h_new, t)`，`t` 是"该点到旧边界的有符号距离"在 `[-5, +5]` 上的 `smoothstep`。

这样接缝处不是断崖，而是一段 8 BU 的渐变过渡带。

### 步骤 4 · 生成脚本的产物约定

`world/scripts/gen_ring.py` 的职责：

1. 读环境变量：`MIST_RING`、`MIST_SPEC`、`MIST_STATE`、`MIST_OUT`。
2. 打开 `world/final.blend`（或当前最新 step 的副本）。
3. 只生成新带区块与它们的树、草、道具、地标。
4. 在 `runtime/ring_{n}.manifest.json` 写清单：新增对象名、数量、哈希。
5. 另存为 `MIST_OUT`（`world/ring_{n}.blend`）。**不要**覆盖 `final.blend`。

Blender 里"应用"时（零件 30 的 APPLYING），用**追加/链接**的方式从 `ring_{n}.blend` 导入这些对象，或直接在当前场景里跑同一份生成逻辑——两条路选一，但**必须只加不改**：

- 允许：新增对象、新增集合、新增材质。
- 禁止：删除旧对象、重命名旧对象、修改旧材质参数、重写旧区块顶点。

### 步骤 5 · 预算

每扩一环的新增预算：

| 项 | 预算 |
|---|---|
| 区块数 | `4*(g+2)-4` 个边缘块（g=10 时 44 块） |
| 三角面 | ≤ 45k |
| 树 | 约 `0.6 × 初始树数` |
| 草 | ≤ 900 实例 |
| 地标 | ≤ 1 |

超过就降密度（草先降），不降地标。

### 步骤 5B · 新元素的增量规则（16A/20A/20B/23A 都要遵守）

扩环不只加地形，还要加**区域、植被、生物**。规则只有一条：**新环的新东西不许动旧环的旧东西**。

| 元素 | 扩环时怎么做 | 绝对不许 |
|---|---|---|
| **区域**（16A） | 新环的 `regions` 由新 spec 提供；旧环的区域权重场**不重算**（旧区块的高度已烘焙） | 因为 `regions` 变多而重算旧点的高度 |
| **植被**（21A） | 只在新带内按新 spec 的 `tree_mix` 撒；旧树对象零变动 | 重建旧环的树 |
| **生物**（23A） | 鸟群/鱼群/蟹/蝶/萤火虫：新带内补充，数量按新 `creatures`；旧带内的生物**不迁移路径**（它们的盘旋中心仍在旧岛心） | 重新分布全岛生物 |
| **天气**（20B） | **全局切换**（不是按环），因为天气是整个世界的事；但风暴/降雪强度可按新 spec 微调 | 让半个世界下雨、半个世界晴 |
| **昼夜**（20A） | **全局**，不按环。新环的 `time` 字段**忽略**（只有 ring 0 的 `time` 生效） | 每个环各有一个时钟 |
| **水体**（17A） | 新带的泉眼/河/湖只在新带内生成；旧河不改 | 让旧河改道或重新挖槽 |
| **洞穴**（16B） | 新带内按新 spec 生成 2~4 个；旧洞零改动 | 在旧环边缘补洞或改洞 |
| **蘑菇/湿地**（23B） | 新带内按新 `biome` 与 `regions` 撒；旧环不改 | 重建旧环植被 |
| **星球化**（39） | 扩环后**必须重投影**：球面是所有环的投影，新环一旦并入，球的顶点就要更新。这是"局部规则"的唯一例外 | 只更新新环顶点、留下空洞 |

**为什么天气/昼夜必须全局**：玩家站在接缝上时，不能"左脚晴右脚雨"。这两项是世界的属性，不是区域的属性。

**星球化的特殊处理**：球面不是"按环生成的"，而是"所有环的整体投影"。所以扩环后必须做一次**全量重投影**（把新环顶点也投上去）。这与"旧区块零改动"不冲突——因为重投影**只改球面副本的顶点**，平面世界的区块顶点一个不动，哈希依然成立。

**为什么水与洞穴必须局部**：它们改变的是**几何**（挖槽、开洞）。每环重算一次几何，就意味着旧岛的每个顶点都要重算，与"零改动"直接冲突。

**一个必须接受的例外**：如果新环的地形抬升让旧环边缘的河流"看起来该改道"，**不要改**。旧河已烘焙，改它必破坏哈希。在汇报里写清"旧河在新地形里略显不合理"，这是增量的代价。

**为什么区域/植被必须局部**：它们已经烘焙进几何与对象里，重算就等于重画旧岛。

### 步骤 6 · 哈希验证（硬验收）

扩环前后：

1. 读 `runtime/chunk_hashes.json` 的旧块哈希。
2. 扩环完成后重算所有旧块哈希。
3. **比对必须 100% 相等**。任何一块不一致 → 立即判定失败，回滚（删新增、恢复状态文件备份），并输出是哪一块、差在哪个顶点。

这条要写成自动检查，不是"我看了一眼"。

### 步骤 7 · 视觉验收

1. 站在旧边界上，朝新区域看：地形连续、色调渐变、没有"贴片感"。
2. 新带里的树/草密度符合新 spec。
3. 旧区域内的树、石头、地标位置零变化（截图对比或哈希）。
4. 雾墙已移到新边界（零件 30 的 REVEALING 负责，这里只确认边界位置对）。

### 步骤 8 · 回滚

任何一步失败：

1. 删除本次新增的对象与集合（按 manifest 清单精确删）。
2. 恢复 `runtime/backup/world_state_{timestamp}.json`。
3. 删除 `world/ring_{n}.blend` 与 manifest。
4. 写 `job.failed` 事件，`error_tail` 含具体失败块。
5. 状态机回 IDLE，雾不移动。

## 验收标准

1. 旧块哈希 100% 不变（自动检查输出）。
2. 接缝 8 BU 内高度平滑（采样一条横切线，无阶跃 > 0.6 BU）。
3. 新带内容完整（地形/树/草/地标）。
4. 回滚可用：人为制造一次失败，能回到扩环前状态。
5. 三角面在预算内。
5b. 新环有区域/植被/生物差异，且旧环的生物路径与区域零变化（截图对比）。
5c. 新环有自己的河/湖（若新 spec 有），旧河河道零改动（哈希 + 截图双证）。
6. 三张截图（接缝近景、新环俯视、新旧对比）。

## 回退方案

- **哈希总有两三块不一致**：几乎必然是生成函数读了"当前场景里已存在的对象"；把它改成纯函数（只读坐标 + spec）。
- **接缝有明显台阶**：`BLEND_BAND` 提到 16，并把融合从"线性插值"改成"smoothstep 插值"。
- **追加对象时材质冲突**（同名不同参数）：新环材质统一加后缀 `_R{n}`，命名规则写进汇报。
- **合并后场景变重**（每环都加 geometry）：把最外 2 环降级为 LOD 代理（零件 35），不删数据。
