# 15 · 区块坐标与流式装载

> **一句话**：Blender 负责确定性地产出分块 GLB 与清单，Three.js 浏览器按清单真正加载、替换、卸载和恢复资源；走远再回来，几何、实例与 hash 都不变。

零件 03（浏览器全屏游戏壳可用）、零件 14（源工程与唯一导出口可用）；seed 已由零件 12 或本地预设确定。

你是**世界资源流式运行时工程师**。本零件先用平坦高度验证资源生命周期，真实地形由零件 16 接管。验收对象是浏览器中实际增删的 Three.js 场景节点、GPU 资源和静态实例，不是 Blender 集合数量，也不是网页对 Blender 的遥控或只读预览。

### 步骤 1 · 区块坐标与网格边界

- 区块边长固定 **10 BU**；出生岛为 10×10=**100 个区块**，`(cx,cy)` 均为 `0..9`。
- 区块中心世界坐标为 `x=(cx-4.5)×10`、`y=(cy-4.5)×10`，中心轴与高度轴遵守零件 14 的 Z-up 契约。
- 区块本地 X/Y 覆盖 `-5..+5`，端点必须包含。L0 使用 11×11=121 个采样位置，L1 使用 6×6，L2 使用 3×3。
- L0 每块为 200 三角面，100 块基础地形合计 20,000 三角面；L1 每块 50 面，L2 每块 8 面。
- 块内使用索引共享顶点，不得把每个三角形或采样单元做成独立对象。跨块可以重复边界坐标，但同一世界坐标必须由同一纯函数给出一致位置，视觉上连续。
- 11×11 是采样密度，不是要显示的方格。不得添加网格描边、砖缝、独立面片或像素化表现来“说明区块”。

### 步骤 2 · 确定性生成、导出与 hash

源侧区块生成入口保持 `ChunkGen(cx,cy,spec,seed)` 语义：

- 相同 `(cx,cy,seed,spec,算法版本)` 得到相同的几何、材质引用、静态实例和对象顺序。
- 求值只依赖世界坐标与输入，不读取邻块当前是否加载，也不依赖上一次生成结果。
- 源对象归入 `W_CHUNKS/Chunk_{cx}_{cy}`，主要网格命名为 `Terrain_{cx}_{cy}`。
- 本阶段高度暂取 0；正式阶段即使地块在岛屿蒙版外，也按零件 17 生成连续水下地形，不能留下空洞。
- 所有区块/LOD 只能经 `world/scripts/export_world.py` 写入 GLB 和 manifest，禁止本零件另开一套导出逻辑。

每个区块的确定性 hash 由唯一出口按规范化内容计算：固定精度的顶点位置、索引、材质标识和静态实例变换以固定顺序参与，文件名、导出时间和对象随机 ID 不参与。`runtime/chunk_hashes.json` 可保存离线诊断副本，但浏览器以当前 `asset_version` 的 manifest 中 `chunks[].hash` 为资源身份依据。

### 步骤 3 · 浏览器实际加载链路

Three.js 资源管理器必须完成完整链路，而不是只生成 Blender 区块：

1. 从服务端 API 取得当前版本指针，再获取该版本 `manifest.json`，校验 `schema_version`、seed、ring、岛尺寸和 spec hash。
2. 根据玩家/流式锚点所在块计算目标集合，从 `chunks[].lods[]` 读取真实 URL；不得按目录名猜测资源版本。
3. 用 GLTFLoader 实际请求 GLB，经**唯一坐标适配层**恢复 Z-up，再挂入 Three.js 游戏场景。
4. 按 manifest 的 `shared[]` 加载共享模板，用实例化恢复树木、岩石等静态内容；不得为每棵实例复制几何与材质。
5. 记录 `asset_version + chunk id + lod + hash`、场景节点、碰撞数据、实例 ID 与引用计数。只有加载和校验成功后才把块标为可用。
6. 卸载时从场景、碰撞与可见实例集合移除对应内容，按引用计数释放区块私有 GPU 资源；共享模板在仍有引用时不得销毁。

网络日志、资源管理器状态与 Three.js 场景统计必须能证明上述请求和增删确实发生。Blender 场景截图或 `.blend` 中的区块数量不算证据。

### 步骤 4 · 流式范围与调度

以史莱姆或本阶段的浏览器流式锚点为基准，使用区块距离并设置滞回：

- 半径不超过 3 块：目标 L0，中心区域最多形成 7×7=49 块常驻集。
- 半径 4～6 块：目标 L1。
- 半径超过 6 块但仍在视野/迷雾保留范围：目标 L2。
- 超过保留半径 8 块且不在待切换集合：卸载。进入和离开阈值错开，避免边界反复装卸。

只在跨块或版本目标变化时计算差集；加载按由近到远排序。每帧最多启动 2 个区块任务只是上限，还必须服从主线程时间预算。网络请求异步进行，已可用旧块在新块准备好之前不得提前消失。

地形碰撞必须在玩家到达前可用。视觉淡入/淡出可使用约 0.3 秒的短暂过渡，但不能用透明洞口代替已加载地形，也不能因淡出继续保留旧碰撞造成双重地面。

### 步骤 5 · 卸载恢复与实例一致性

走远后允许释放场景节点，但不得改变静态世界的确定性。返回时：

- 从同一不可变版本 URL 或已校验缓存恢复 GLB，并核对 manifest 中的 id、LOD 与 hash。
- 按固定顺序恢复共享资产实例的变换、色板变体与实例 ID；禁止重新随机散布。
- 区块碰撞、地图分类和视觉几何来自同一版本，不得出现“旧碰撞配新网格”。
- 卸载静态区块不得清空玩家、相机、目标、时钟或互动状态；这些实时状态由浏览器游戏单独持有。

本阶段可用浏览器内的临时流式锚点做自动往返测试；后续零件 27 接入真实玩家后，必须再用默认第三人称走一遍，不得保留 Blender 键盘控制或 Blender 帧回调作为实现。

### 步骤 6 · 版本切换

扩环或资源更新时，浏览器执行明确的准备—切换流程：

1. 新版本全部 GLB、manifest 与地图发布完成后，才收到可切换版本指针。
2. 预取玩家附近和即将开雾区域的新版本资源；旧版本场景在准备期间继续渲染和操作。
3. 对新旧 manifest 做差集。hash 未变的旧块复用已加载资源或实例，不重复生成、不重置变换；新增块按序加入，失效块在新场景可用后移除。
4. 在同一次运行时提交中更新资源版本、地图和迷雾边界，再释放不再使用的旧版本引用。
5. 玩家实时位置、输入和相机保持连续，不回出生点。任一新资源失败则继续使用旧版本并给轻量提示，不出现空白世界。

版本切换与 LOD 切换共用资源引用计数，避免旧块在异步回调返回后被重复挂载或误删。

### 步骤 7 · 浏览器实测与证据

在浏览器记录单块网络等待、解析、上传 GPU、场景接入和卸载耗时；目标为**单块主线程接入耗时低于 8 ms**，网络等待另列，不能混成同一个数字。记录中位数与 p95，不能只写平均值。

验收路线从 `(-30,0)` 到 `(10,0)` 再返回，跨越 4 个区块宽度；另做一次扩环版本切换。保存：

- 网络请求与 manifest/GLB 版本记录。
- 装卸前后区块 id、LOD、hash 和共享实例数量对照。
- 浏览器帧时间与主线程接入耗时。
- 默认第三人称跨块行走截图/录屏，近地接缝清楚可见；整岛俯瞰只能作为附加诊断。

## 验收标准

1. 当前 manifest 对出生岛列出 100 个区块及所需 LOD；L0 逻辑总量为 20,000 三角面，数字与 GLB 实测一致。
2. 浏览器网络记录证明 GLB 按清单真实请求；Three.js 场景中能看到目标块加载、LOD 替换和卸载，不是只更新 Blender 集合。
3. 中心区域目标常驻集为 49 块，世界边缘按实际合法块减少；移动 4 个区块宽度后近块补齐、远块按滞回收回。
4. 返回原区域后，区块 hash、静态实例 ID/变换和碰撞与首次一致，没有重新随机散布或重复挂载。
5. 相邻块在默认第三人称近地视角下连续，无可见区块描边、独立方砖或裂缝。
6. 新版本准备期间旧世界可玩；切换后玩家/相机不重置，未变 hash 的块被复用，失败时旧版本仍在。
7. 单块主线程接入耗时、帧时间和网络等待分别记录，证据来自浏览器。
8. 正式运行路径没有 Blender 帧变化回调、Blender 键盘移动或网页遥控 Blender 步骤。

## 回退方案

- **装卸造成卡顿**：先减少并发任务、分帧解析/接入并缩小保留半径；L0/L1/L2 的固定采样规格不变。
- **边界反复装卸**：扩大进入/离开滞回，按跨块事件调度，不用提高每帧遍历频率解决。
- **恢复后 hash 或实例变化**：检查是否读取了邻块加载状态、遍历顺序不稳定或重新使用随机数；回到纯函数与固定排序。
- **共享资源被误删**：按版本和引用计数释放，仍有实例引用时保留几何、材质与纹理之外的共享数据；本风格不应依赖纹理。
- **版本切换失败**：保留旧版本和玩家状态，报告缺失 URL/hash 对照，不通过刷新页面或回出生点掩盖。
