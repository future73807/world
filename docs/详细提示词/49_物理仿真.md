你是**浏览器物理参数与因果工程师**。原则：相关物理链路可感知、可关、可恢复；重力、温度、光照和潮汐的游戏效果由 Three.js/TypeScript 实时执行，参数编辑只在非驻留工作台。

先定一条总则，写进汇报：

> **不追求数值正确，追求因果正确。** 恒星质量变大 → 引力变大 → 跳不起来 → 这一天你立刻就能感觉到。至于具体是 9.8 还是 9.80665，不重要。

### 步骤 1 · 三条链路（先看全貌）

```
恒星质量 ──► 表面重力 ──► 跳跃高度 / 跌落速度 / 史莱姆压扁程度
     │                        └─► 潮汐强度 ──► 水面高度（可选）
     └──► 温度 ──► 雪线 / 水结冰 / 生物活跃 / 颜色偏移
             └──► 光强度 ──► 大气辉光亮度 / 夜晚亮度
轨道半径 ──► 温度（距离平方反比）──► 同上
     └──► 光行时（可选彩蛋）──► 太阳位置比"看到"的晚几秒
```

### 步骤 2 · 表面重力（最直接的一条）

从行星的 `mass` 与 `radius` 算表面重力（比例即可）：

`g_rel = mass / radius²`（相对地球=1）。

然后直接改史莱姆的手感（零件 27/26 的参数）：

| 量 | 随 `g_rel` 变化 |
|---|---|
| 跳跃初速 | 不变（角色能力），但**跳跃高度** `∝ 1/g_rel` |
| 下落加速度 | `∝ g_rel` |
| 落地压扁程度 | **`∝ g_rel`**（重力大 → 压得更扁 → 更可爱） |
| 待机呼吸幅度 | `∝ 1/sqrt(g_rel)`（重力小 → 飘一点） |
| 走路速度 | `∝ 1/sqrt(g_rel)`（低重力可以跳着走） |

**注意上限**：`g_rel` 钳制在 `[0.2, 3.0]`。低于 0.2 会变成月球蹦床（好玩但失控），高于 3.0 史莱姆走不动。

- 在非驻留参数界面给一句人话：`重力 0.7× — 跳得更高，落地更软`；默认地表 HUD 不增加物理参数。

### 步骤 3 · 温度（决定地貌，不只是数字）

**平衡温度**（示意，不求精确）：

`T_rel = luminosity / (a² × 4π)` —— 用"相对地球=1"的归一化。

映射到一张**温度带表**：

| `T_rel` | 世界反应 |
|---|---|
| < 0.45 | 冰封：水面全结冰、雪线降到海平面、生物几乎为零、色板强制偏冷 |
| 0.45 ~ 0.8 | 寒带：雪线低、针叶为主、雨变雪 |
| 0.8 ~ 1.4 | 温带：默认（当前世界的样子） |
| 1.4 ~ 2.2 | 热带：无雪、阔叶密、湿度高、雨频繁 |
| > 2.2 | 灼热：水蒸发（水面下降/消失）、岩石裸露、沙尘、生物极少 |

**双向生效**：

1. 从星球的 `a` 与恒星 `luminosity` 计算 `T_rel` → 生成候选 spec 与候选资源；验证后一次发布，不直接改写当前 `world_spec` 或旧 GLB。
2. 也允许**手改温度滑杆**直接覆盖（编辑器里给一根"本星温度偏移"滑杆）。

**昼夜温差**（进阶，可选）：`day_night` 滑杆控制"白天与夜晚温度差"→ 表现为夜里的霜、清晨的雾更浓（联动 20B）。

### 步骤 4 · 光的传播（三件小事，一件彩蛋）

**A · 光照强度与大气辉光**

- 恒星越亮（`luminosity`）→ 星球的明暗对比越强、边缘辉光越亮（44 的 `atmo_intensity` × `luminosity`）。
- 距离越远 → 对比更弱、暗面更暗（但环境光下限仍在）。

**B · 日长与自转**

- 行星 `spin` 决定一天长度。`20A` 的 `cycle_minutes` 应该**由 `spin` 推导**（或反过来），不要两处各写一个数。
- 规则：`cycle_minutes ∝ 1 / spin`。给一个默认映射表，改自转 → 一天变长/变短。

**C · 季节（轴向倾斜）**

- `axial_tilt`（0~45°）→ 太阳的"赤纬"随公转位置变化。
- 表现为：同一个世界，**季节不同时日照角度不同**（雪线上下移动、白天长度变化）。
- 不需要真做四季，只要让倾斜角**可见地影响光照角度**。

**D · 彩蛋：光行时**

- `a` 很大时（外行星），"你看到的恒星位置"比"实际位置"晚几秒（甚至几分钟）。
- 做法：渲染用的恒星位置取 `t - a/c` 的解析解。玩家几乎察觉不到，但在**时间加速 ×100** 时会看出"光追上来了"。
- **可关**（默认开，因为它零成本且很妙）。

### 步骤 5 · 潮汐与海水（可选，但很值）

- 潮汐力 `∝ mass / a³`（卫星或有近邻时）。
- 若 `tidal_force` 超过阈值：19 的水面整体高度做 ±0.15 BU 的周期起伏（周期 = 该天体的公转周期）。
- 联动：退潮时露出潮间带（17 已有沙滩带），涨潮时淹掉一点。**这是"活的世界"最便宜的一招。**
- 不给真实潮汐表，只做"能看出水在呼吸"。

### 步骤 6 · 一个总开关（重要）

物理默认**分层开启**，因为有些玩家只想看风景：

| 开关 | 默认 | 影响 |
|---|---|---|
| `physics.gravity` | **开** | 跳跃、压扁、速度 |
| `physics.temperature` | **开** | 雪线、结冰、生物 |
| `physics.light_delay` | 开 | 光行时（彩蛋） |
| `physics.tides` | 关 | 潮汐（会干扰"水看起来是静的"） |
| `physics.seasons` | 开 | 轴向倾斜 |

- 一个总的「物理仿真」开关（关掉则全部回到中性的 1.0 世界）。
- **任何一项关掉后，世界必须仍可玩**（不能出现"关了重力史莱姆就浮着"）。

### 步骤 7 · 一致性检查（这一条最容易漏）

同一颗星球上，三处读到的"重力/温度"必须一致：

1. 编辑器显示的数字（47）
2. 地表的实际手感（史莱姆跳跃）
3. 太空视图的视觉（大气亮度、云厚度）

写一个 `runtime/physics_report.md`：每颗星球一行（`g_rel`、`T_rel`、`day_length`、`tidal`），并在汇报里指出"三处一致"的抽查结果。

### 步骤 8 · 验收

1. 把某行星 `mass` 调到 2.0：跳跃高度明显变低、落地压得更扁（两张对比截图）。
2. 把某行星挪到内圈（`a` × 0.6）：温度带从温带变热带，雪消失、雨更频繁（截图）。
3. 挪到外圈：变寒带，雨变雪。
4. `spin` 改大：一天变短（报分钟数），昼夜切换可见地更快。
5. `axial_tilt` 改大：日照角度改变（同日不同时刻对比）。
6. 潮汐开启：水面有可感知的缓慢起伏。
7. 五个开关各关一次，世界仍可玩。
8. `physics_report.md` 三处一致。
9. 六张截图 + 一段"改重力"的对比录屏。

## 回退方案

- **重力改小后史莱姆飘出地图**：`g_rel` 下限提到 0.3，并给"飘太高"加一个柔和的天花板（不硬撞）。
- **温度带改完地面却没变**：检查候选资源是否重新评估材质与雪线并完成发布；不能直接覆盖旧资源，也不能只改编辑器数字。
- **光的彩蛋看不见**：把 `light_delay` 的强度调成"随距离增加"更明显（×100 时间下）。
- **潮汐让玩家晕**：默认关；开启后振幅降到 0.08。
- **一致性对不上**：只允许**一处计算**（`physics` 模块），其余地方全部读它，禁止各自算。
