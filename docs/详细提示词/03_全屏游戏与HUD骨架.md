> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。

> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。

> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**开放世界游戏 UI/UX 设计师与 Three.js 运行时工程师**。先完成原创高保真设计，再实现。参考原神等开放世界游戏的世界优先、操作直接、信息层级与反馈，不复制具体图标、字体、色值、布局截图或素材。

### 步骤 0 · 先交完整设计包

#### A. 桌面与触屏线框

分别画出：

- 默认游玩 HUD。
- 全屏地图及目标/路径点操作。
- 暂停/设置与世界创建。
- 靠近对象、按 E、蓄力、取消、成功和失败的互动反馈。
- 开发者工具的独立入口，证明它不会混入玩家 HUD。

标明角色与前方道路安全区，默认至少 80% 画面保持世界可见；桌面不显示虚拟摇杆，触屏避开系统手势区。

#### B. 高保真效果图

至少交付桌面与触屏两套：

1. 默认 HUD（含小地图、目标、角色状态、情境互动）。
2. 全屏地图（选中地标、放置路径点、回到玩家）。
3. 暂停/设置（世界背景保留、焦点状态明确）。
4. 世界创建（幻想世界气质，不是后台表单）。
5. 迷雾互动（接近、蓄力、取消、完成）。

线框只用于结构评审，**高保真效果图未确认前不得用组件库拼界面并宣布完成**。

### 步骤 1 · 全屏 Three.js 游戏底座

- 在 `app/` 建立新的 Vite + React + TypeScript 工程并实际使用 Three.js。
- 根路由 `/` 是全屏实时游戏；`THREE.Scene`、透视相机、WebGLRenderer 与 `requestAnimationFrame` 循环完整。
- `app/game/` 管渲染/输入/运动/相机，`app/components/` 管 UI，`app/lib/` 管类型/状态，`app/server/` 管服务端。
- Canvas 覆盖视口，处理 resize、DPR、WebGL 上下文丢失、页面隐藏与恢复。
- 可使用明确标注的临时三角坡面验证渲染，但不能用占位模型通过任何正式视觉验收。
- `WorldAssetLoader` 只按 manifest 和统一坐标适配加载新 GLB，不读取历史资源。

### 步骤 2 · 玩家界面状态机

| 状态 | 世界与输入 | 指针与 UI |
|---|---|---|
| `playing` | 实时游戏，接收运动/相机输入 | 单击后指针锁定，显示轻 HUD |
| `map` | 默认冻结角色移动，可按设计保留世界时间 | 释放指针，地图捕获缩放/拖动/选择 |
| `paused` / `settings` | 冻结角色输入与相应世界更新 | 释放指针，显示可关闭游戏菜单 |
| `creating` | 保留明确背景状态，不污染当前世界 | 释放指针，创建流程独立 |
| `developer` | 由开发开关明确进入 | 独立日志/CLI/性能，不向普通玩家默认显示 |

- 关闭任何覆盖界面后恢复玩家位置、相机、当前目标、时钟与 HUD。
- 文本输入、按钮、滑杆和弹层捕获自己的事件，WASD/空格/E/滚轮不得穿透。
- Esc 优先取消当前操作/关闭顶层界面，再进入暂停；不能一键直接退出或丢进度。

### 步骤 3 · 默认 HUD 的精致布局

- **左上小地图**：桌面约 160～176px，圆形/柔边裁切，含玩家朝向、北向、必要地标和边界；下方区域名与一行时间/天气。
- **当前目标**：在小地图下方或左侧安全区显示一个主目标和至多两个短子项；J 展开详情，默认不遮挡前路。
- **右上功能入口**：少量原创圆形地图/目标/暂停图标，提供键位提示，不形成网页导航条。
- **底部角色状态**：只显示当前史莱姆真正需要的信息，避免虚构血条、背包和复杂属性。
- **情境提示**：锚定当前最佳对象，显示输入图标 + 动作文字 + 进度；键鼠/触屏提示随最近输入切换。
- **临时反馈**：区域发现、目标更新与资源状态使用原创小型动效，自动消退，不堆成通知中心。

HUD 容器默认 `pointer-events: none`，只有真实控件接收事件；不能用透明全屏层抢走相机输入。

### 步骤 4 · 高保真全屏地图

- M 或地图入口打开，Esc/M/关闭返回原状态；不是右侧永久地图栏。
- 世界/地图同源，地图居中占据主要区域，背景游戏适度压暗，标题与关闭按钮清晰。
- 支持滚轮/双指缩放、拖动、双击/按钮回到玩家、选择地标、设置/取消路径点。
- 地标与路径点使用原创图标，选中后通过可关闭的轻详情展示名称、note、距离与“设为当前目标”。
- 当前目标和路径点在游戏内提供方向引导，不自动传送玩家。
- 迷雾、已解锁区域、资源版本与 Three.js 一致；无棋盘格、外部地图素材和复杂筛选后台。
- 筛选与图例放在按需底部抽屉，触屏可单手关闭。

### 步骤 5 · 暂停、设置与世界创建

- 暂停/设置保留世界背景并适度压暗，菜单采用原创图标和清晰分组，不做三栏管理后台。
- 主菜单突出“继续游戏”，设置包含操作、镜头、画面、声音（若有）和舒适性；危险操作与普通设置分开。
- 世界创建采用世界灵感卡、色板摘要与可预览的参数分组，高级字段按需展开；确认/取消路径明确。
- 所有界面具备键盘焦点、触屏 44px 点击区、中文标签、可见选中态和对比度。
- 不用“打开 Blender”“遥控史莱姆”“只读预览”等文案。

### 步骤 6 · 开放世界输入与反馈

建立统一 `InputController` 输出移动、环视、跳跃、冲刺、互动、地图、目标与暂停：

- 桌面：WASD/方向键、单击指针锁定、鼠标环视、滚轮、空格、Shift、E、M、J、Esc。
- 指针锁定不可用时使用明确拖动回退；覆盖界面和失焦必须释放并清空持续输入。
- 触屏：左下摇杆、右侧滑动环视、右下跳跃/冲刺/互动，地图/目标/暂停有独立入口。
- 最近有效输入去抖切换键鼠/触屏提示，避免兼容鼠标事件造成图标闪烁。
- 当前最佳互动对象按距离、视角与可达性选择；目标变化、不可达、按住、取消和完成反馈清晰。
- 输入抽象保留未来手柄扩展，不在首轮为支持列表虚标未实现能力。

### 步骤 7 · 实机与视觉验收

1. 在 1280×720、1440×900、1920×1080 检查默认 HUD，角色/前路清楚，无网页滚动条与遮挡。
2. 对照高保真稿检查字体、图标、间距、透明度、焦点、动效与视觉层级，不接受“功能相同但明显粗糙”。
3. 录制移动中打开/关闭地图、设置路径点、暂停/返回、创建取消、E 蓄力/取消的连续操作。
4. 验证指针锁定/释放、输入隔离、失焦恢复、触屏安全区和提示切换。
5. 保存高保真稿与对应实机截图；任何占位 UI、通用组件默认皮肤或调试面板都不得作为正式视觉证据。

## 验收标准

1. 根路由为全屏实时 Three.js 游戏，默认 HUD 与高保真原创设计一致，世界占主体。
2. HUD、全屏地图、暂停/设置、世界创建和互动形成统一且完整的开放世界 UI，不是网页组件拼盘。
3. 地图路径点、目标、输入提示、指针锁定、触屏布局和关闭恢复全部可用。
4. 有完整线框、高保真稿、token、交互分镜和对应实机证据；无恢复包或外部游戏素材。
5. 控制台无错误，默认无三栏/日志/开发面板，视觉粗糙不能仅凭功能通过。

## 回退方案

- **HUD 看不清**：调整局部渐层、字体与阴影，不扩大成网页卡片。
- **UI 像后台**：回到高保真评审，重做视觉层级和游戏场景关系，不继续加组件。
- **地图/相机抢输入**：统一状态机和输入仲裁，不用透明补丁层掩盖。
- **动效/模糊掉帧**：减少大面积模糊与同时动效，保留清晰反馈，不牺牲游戏帧率。
- **WebGL 不可用**：如实报告环境，不用静态图冒充游戏。
