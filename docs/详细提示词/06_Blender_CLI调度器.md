# 06 · Blender CLI 调度器

> **一句话**：服务端把世界生成作业安全地交给离线 Blender CLI，验收 GLB/manifest 等完整产物；日志默认只进事件流与开发者工具，不抢占游戏。

零件 05（队列）、零件 03（非驻留开发者工具）完成。

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**离线资产作业调度工程师**。调度器不管模型长什么样，也不控制玩家。它负责安全启动、日志、超时、退出码和产物校验；Blender 没有玩家窗口。

### 步骤 1 · 作业规格

接收：`kind`、`script`、`args`、`source_blend`、`out_dir`、`asset_version`、`timeout_s`。

- `script` 必须解析到 `world/scripts/` 内；参数用数组传递，不拼接 shell 字符串。
- 使用 `blender -b`，可按任务打开指定源 `.blend`，再通过 `--python` 执行生成/导出脚本。
- 输出写入不可变候选目录，禁止直接覆盖当前已发布资源。
- Windows 可执行路径通过环境探测或非驻留开发设置指定，结果可缓存但需可重新验证。

### 步骤 2 · 环境与输入

按任务注入：`MIST_SEED`、`MIST_RING`、`MIST_SPEC`、`MIST_STATE`、`MIST_OUT`、`MIST_ASSET_VERSION`、`PYTHONUNBUFFERED=1`。

- 子进程只读明确输入，输出 GLB、manifest、地图、碰撞、hash 与源 `.blend`。
- 不注入任何 API Key；生成器不读取浏览器实时玩家输入。
- 工作目录固定在项目根；输入/输出路径必须解析到允许的目录内，拒绝越界。

### 步骤 3 · 日志与进度

- stdout/stderr 同时进入内存环形缓冲与 `runtime/logs/{job_id}.log`，统一 UTF-8。
- `@@PROGRESS` 解析为 `job.progress`，无法解析的行保留但不打断作业。
- 普通游戏 HUD 只显示必要的简短阶段；完整逐行日志仅开发者显式打开时可见。
- 页面失焦或开发面板关闭不影响作业和日志落盘。

### 步骤 4 · 退出与完整产物

| 结果 | 处理 |
|---|---|
| 退出码 0 | 继续校验所有声明产物、GLB/manifest/hash/文件大小与版本一致性，全部通过才 succeeded |
| 脚本异常/参数错误 | failed，保留尾部与 Traceback |
| 超时 | 先请求终止，超时后终止已确认的进程树，标 failed |
| 其他退出码 | failed，保留完整日志与候选目录供诊断 |

**退出码 0 不等于成功。** 缺 GLB、空 manifest、hash 不匹配或候选不完整都不能发布。

### 步骤 5 · 测试作业

提供不创建正式资产的 `test` 作业：输出固定进度、结束事件和一个小型合法测试产物，写入 `runtime/jobs/` 的隔离目录。

- 开发者工具中看到分段日志与退出状态；普通游戏只出现可消退完成通知。
- 测试期间玩家走跳、相机和 HUD 状态不受影响，不打开 Blender 窗口。

### 步骤 6 · 与拓荒状态机的关系

- 零件 30 的服务端状态机调用 `kind=ringgen`，传入新环 spec 与候选 `asset_version`。
- 状态机负责 `fsm` 和 `pending_ring`，调度器不自行修改世界进度，不轮询浏览器请求文件。
- 调度器写完 `job.*` 事件后交由 30/32 做候选校验与发布；不能自己把当前指针切到候选。
- 失败时保留旧版本和日志，玩家继续在旧世界操作。

## 验收标准

1. 测试作业的分段日志、进度、退出与完成事件正确，默认 HUD 无日志面板。
2. 路径越界、脚本异常、超时、退出 0 但缺产物都被正确拒绝或标失败。
3. 日志不含 API Key，进程终止无本项目子进程残留。
4. ringgen 只产候选，不完整就不发布；旧世界和玩家操作不中断。
5. 开发工具开关和关闭返回游戏有实机证据，全程无 Blender 玩家窗口。

---

## 回退方案

- **找不到 Blender**：报告实测路径和最短修复方式，不生成静态图冒充资源完成。
- **Windows 输出乱码**：子进程按 UTF-8 解码并保留原始日志，失败时记录编码诊断。
- **进程树残留**：只按已验证 PID/进程组终止本项目子进程，不宽泛杀其他 Blender/Node 进程。
- **候选产物不完整**：保留诊断并标失败，禁止发布或导入旧模型补齐。
