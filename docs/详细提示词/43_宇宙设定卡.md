# 43 · 可选宇宙设定卡与多星球编辑

> **一句话**：可选宇宙可以是**一颗球**，也可以是**多颗球**——你长出来的那颗可以成为其中之一；不启用时不改变地表游戏，编辑只在可关闭的暂停/设置界面进行。

## 前置

零件 10（世界设定卡引擎）、39~42（星球与轨道）。39～49 整组为可选扩展，未启用宇宙功能时不得阻塞核心地表版。

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**宇宙编纂者**。这是"创造宇宙"这个可选需求的落地点：**一张卡，多个星球**。浏览器仍是唯一实时运行时，星球与轨道画面由 Three.js 渲染；Blender 只由后台用于离线生成和导出资产。

### 步骤 0 · 可选入口与形态（三种入口，别混）

宇宙创建/编辑入口只放在暂停/设置的「宇宙」页或相应宇宙视角的明确操作里，不在地表 HUD 增加常驻星球列表、轨道参数或编辑按钮。未生成宇宙时，默认地表游戏与轻 HUD 完全不变。

用户在可选创建流程中可能想要三种完全不同的东西，**先在这一界面问清是哪一种**，再往下做；取消后回到原地表/星球/宇宙观察状态，不修改当前世界：

| 形态 | 怎么生成 | `planets` 长度 | `home_planet_id` |
|---|---|---|---|
| **A · 单星球** | 不跑 AI，直接把你当前的世界卡包成宇宙卡（1 颗 `grown`） | 1 | 那颗 |
| **B · 当前星球入系** | 你当前的 `world_spec` 作为 `p_home`（`origin=grown`），AI 再造 2~6 颗邻居 | 3~7 | `p_home` |
| **C · 纯观测宇宙** | 全部由 AI 或模板生成，与地表世界无关 | 1~7 | `null` |

默认走 **B**（最符合"我造了个岛，想知道它在星系里长什么样"）。

三种形态的**共同点**：都只是"多了一份轨道编排"，没有任何新的地形代码。

### 步骤 1 · 宇宙设定卡（`specs/universe_spec.json`）

结构（顶层字段冻结）：

- `version` 整数
- `name` 字符串（宇宙名，2~14 字）
- `seed` 整数
- `mood` 一句（如"九颗石头在等一个太阳"）
- `star` 对象：`name`、`palette`（`core`/`corona` 两色）、`mass`（0.3~3）、`radius`（0.8~2 RU）、`luminosity`（0~1）
- `physics` 对象：`mode`（`cinematic`/`realistic`）、`orbit_tension`（0.6~1.6）、`universe_day_scale`（5~200）
- `planets` 数组，**1~7 项**，每项：
  - `id`（如 `p_01`）、`name`（2~10 字）
  - `origin`（`grown` / `born`）——见契约 F3；`grown` 最多一颗
  - `kind`（`rocky`/`ocean`/`ice`/`gas`/`lava`/`verdant`/`mushroom`/`ruin`）
  - **一份完整的 `world_spec`**（即零件 10 的卡，嵌套在这里，字段与契约 F 完全一致）
  - `orbit` 对象：`a`（半长轴，RU）、`e`（0~0.35）、`inclination`（0~45°）、`period`（宇宙天）、`phase`（0~1）
  - `mass`（0.1~10）
  - `moons` 数组（0~2 项）：`a`、`period`、`radius`、`palette`
  - `note`（一句，如"这里下金属雨"）
- `weirdness`（0~1）
- `relation` 字符串：一句"这些星球之间的关系"（如"它们曾经是一颗"、"潮汐互相锁定"）

**注意**：`planets[i].world_spec` 就是零件 39/44 用来贴到球面上的那张卡。所以"多星球"= "多张世界卡 + 一份轨道编排"，不需要新的地形代码。

### 步骤 2 · AI 的提示词

用中文写清，要点：

- 只输出 JSON，不要解释。
- 造一个"宇宙"，**1~7 颗星球**；若只有 1 颗，要写清它是"孤独的"（`relation` 写"只有它一个"）。
- **已有一颗 `origin=grown`（`p_home`）时，它的 `world_spec` 不许改**——只生成其余 `born` 的邻居。这是硬约束：你造出来的岛不能被 AI 重写。
- `born` 的星球必须与 `grown` 那颗**至少三处不同**（biome、主色相、天气、时段、水系、生物），否则星系会像"五个同一个人的克隆"。
- 星球的 `world_spec.name` 与宇宙的 `name` 不要重复用词。
- `orbit.a` 必须**单调递增**（内圈到外圈），且间距满足 `a_{i+1} / a_i ≥ 1.35`（否则会挤在一起）。
- `period` 与 `a` 的关系：若 `physics.mode=realistic`，必须满足 `period = 2π × sqrt(a³ / 恒星质量)` 的近似（同一天单位）；若 `cinematic`，也要"内圈快、外圈慢"。
- `relation` 要具体（"第三颗的潮汐被第二颗锁住"好于"它们互相影响"）。
- 允许一颗星球是"死星"（`biome=desert`、无生物、`mood` 写荒凉）；也允许一颗是"乐园"。**对比才好看。**

### 步骤 3 · 校验与钳制

复用零件 10 的宽松解析，另加宇宙级校验：

| 校验 | 处理 |
|---|---|
| `planets` 长度不在 1~7 | 越界就钳制（0 颗→补到 1；>7 截断） |
| `origin=grown` 超过 1 个 | 只保留 `home_planet_id` 指向的那个，其余改 `born` |
| `home_planet_id` 指向不存在的 id | 置 null（退化为纯观测宇宙），并提示 |
| AI 试图改 `p_home` 的 `world_spec` | 直接丢弃该字段，用现有存档 |
| `orbit.a` 非递增 | 排序；若撞在一起，按 `1.35` 倍率重排 |
| `world_spec` 缺字段 | 用契约 F 的默认值补 |
| `kind` 与 `world_spec.biome` 冲突 | 以 `biome` 为准，`kind` 改写成对应值 |
| 所有星球 `palette` 主色相太接近 | 强制把第 2、4、6 颗的色相旋转 ±35°（并记录修正） |
| `relation` 为空 | 用本地关系模板填一句 |

结果写入 `specs/universe_spec.json` + `specs/universe_spec.md`（可读摘要：一张表列出每颗星球的名字/biome/主色/天气/生物密度）。

### 步骤 4 · 非驻留多星球编辑 UI（浏览器）

已生成宇宙后，玩家可从 Esc 暂停/设置的「宇宙」页打开可关闭编辑界面；在地表 `playing` 状态不显示宇宙面板，更不把它放到右栏地图上方。界面采用单一编辑上下文：主区域是浏览器 Three.js 星球/轨道观察画面，选择器与当前字段组按需展开，不把星球列表、预览和参数表同时铺成三栏。

- 顶部摘要：宇宙名 + 恒星色块 + 星球数，附明确关闭按钮。
- 可切换的**轨道示意页**（纯 SVG/CSS，仅用于编辑示意，不替代 Three.js 游戏）：几条同心椭圆弧，每颗行星一个小圆点，颜色取自它的 `palette.accent`。点圆点选中那颗，再进入单星球编辑页。
- 单星球编辑页一次展开一组字段：
  - 名字（改）
  - biome（六选一）
  - 三个主色（拾色器）
  - 天气（五选一）+ 强度滑杆
  - 生物生机滑杆
  - **"重新生成这颗"按钮**（只重跑这一颗的 `world_spec`）
- 物理参数放在独立「轨道与时间」页：恒星质量、轨道松紧、时间流速与物理模式开关（cinematic/realistic）；不作为地表 HUD 的底部常驻滑杆。
- 所有编辑先更新本次草稿，点「保存」才写回 `universe_spec.json`（原子替换），但**不自动重新生成几何**——要按「应用」才排队重建（避免每拖一下滑杆就重算行星）。保存、应用与浏览器资源已更新是三个明确状态，不得混为一谈。
- 编辑界面捕获文本、滑杆、滚轮和快捷键输入，不穿透到地表角色或观察相机。取消、Esc 或关闭后回到进入前的 `surface`/`planet`/`cosmos` 状态，恢复原玩家位置、相机姿态和轻 HUD；有未保存草稿时提供"保存并关闭 / 放弃 / 继续编辑"。
- 应用重建后允许关闭界面继续原游戏，后台只显示轻量进度与自动消退通知；完整作业日志仍只在开发工具。任何按钮都不要求玩家打开 Blender。

### 步骤 5 · 增删星球

- **加入一颗**：在轨道示意图**外侧插入**（`a` 最大 ×1.35），用 AI 或本地模板生成它的 `world_spec`。
  - **心智模型是从恒星向外长，不是往列表末尾追加**。这是根据轨道结构做出的本项目交互选择；加入后轨道示意图真的多出一圈，由内到外重排，不复制外部软件布局。
  - 也支持**插入到内圈**：选中某颗，在它和内侧邻居之间插入，`a` 取两者的几何平均。
- **删掉一颗**：确认后移除，其它轨道不动（留一个空位，避免"整个宇宙重排"带来的困惑）。
- **`grown` 那颗不许删**（那是你的地表世界）。要删它就先问用户"这会删掉你的存档"。
- 上限 7 颗、下限 1 颗。

### 步骤 6 · 降落在一颗 `born` 星球上（新增，重要）

用户在非驻留宇宙编辑/观察界面点了 `born` 星球并选「下去看看」时：

1. **没有地表存档** → 确认后关闭编辑界面并提交后台作业（跑零件 14~23 的完整离线生成与 GLB 导出流程，但只做 **1 环**：环 0），原场景在新资源就绪前保持可用。
2. 生成完写入 `runtime/world_state.json`，原子切换该星球资源版本，并把 `current_planet` 设为该 id。
3. 按视角状态机回到 `surface` 时，浏览器 Three.js 世界里就是这颗新星球的地表；切换失败则保留原视角与旧资源并给轻提示。
4. 原来的 `grown` 存档**保留**（`world/planets/p_home/`），随时可切回。
5. 若用户在 `born` 星球上也拓荒扩环，那是**这颗星球自己的一份独立存档**——不要与 `p_home` 混写。

**存档路径规则**：每颗行星一份独立存档目录：

- `world/planets/{planet_id}/`（含 `base.blend`、`final.blend`、`chunks/`）
- `runtime/planets/{planet_id}/world_state.json`
- `runtime/planets/{planet_id}/chunk_hashes.json`

**`runtime/world_state.json` 保留为"当前所在星球"的那一份**（避免所有零件都要改路径），另有一个 `runtime/planets_index.json` 记录每颗星球的存档路径与状态。这样零件 01~38 **完全不用改**。

### 步骤 6B · 与后台生成及 GLB 的衔接

- "生成宇宙"= 后台对每颗星球依次跑一次"星球化"（39）与统一 GLB 导出，总耗时约 `星球数 × 单球耗时`。玩家不操作 Blender 或 CLI。
- **必须分批**：一次只生成一颗，该颗 GLB、地图和 manifest 校验完成后就在浏览器 Three.js 中可见（玩家可以转着看第一颗，其余在后台排队）。这比"等全部生成完"体验好一个量级。
- 编辑界面内进度可显示 `3 / 5 颗星球已就绪`；关闭后普通游戏最多保留一条轻量进度与自动消退通知，不显示完整队列。
- 某颗失败：在编辑/观察界面标记待重试并允许单独重试，不影响其它；普通游戏只收人话通知，完整错误尾部在开发工具。

### 步骤 7 · 持久化与恢复

- `universe_spec.json` 是设定唯一真相；每颗星球的离线源工程存 `world/planets/{id}.blend`，浏览器实际加载的是按版本导出的 GLB、地图与 manifest，不能直接打开 `.blend` 游玩。
- 再次打开页面只恢复宇宙卡与资源索引，**不自动抢占地表默认画面**。有地表存档时回到原地表状态，由玩家主动进入星球/宇宙视角；纯观测宇宙才可恢复上次宇宙观察状态。
- 缺失产物在宇宙编辑/观察界面标为待生成，不弹出常驻错误面板；当前可用地表或旧版本星球资源继续可玩。
- 版本字段用于数据兼容升级；读到旧 schema 时仅按契约补默认值并保留原文件备份，不借此导入旧 UI 或模型。

### 步骤 8 · 验收

1. 未启用宇宙功能时，核心地表游戏与轻 HUD 无变化；未做本扩展时总验收标"未做"而非阻塞核心版。
2. 在可选创建流程中，一句话或抽卡能生成一个 3~7 颗星球的宇宙，`universe_spec.json` 合法。
3. 每颗星球的 `world_spec` 都合法、且彼此明显不同（报色相与 biome 差异表）。
4. 轨道 `a` 单调递增且间距合规。
5. 非驻留宇宙编辑界面能选中、编辑、保存写回；字段输入不穿透，取消、Esc 和关闭均回到原观察状态、玩家与相机。
6. "重新生成这颗"只影响那一颗（其它星球哈希不变），保存后仍需应用才重建。
7. 增删星球不导致全宇宙重排。
8. 分批生成：第一颗 GLB 与 manifest 就绪后就能在浏览器 Three.js 中看，其余后台排队，无 Blender 玩家步骤。
9. 重启页面能恢复宇宙数据但不自动抢占地表；缺失产物不破坏现有游戏。
10. 六张截图（非驻留宇宙编辑、轨道示意页、单星球编辑、物理参数页、后台轻进度、失败重试），另存关闭后原地表轻 HUD 对照。

## 验收标准

1. 宇宙卡合法、星球数合规。
2. 星球间至少三处不同（附差异表）。
3. 轨道单调递增、间距合规。
4. 编辑能写回、能生效。
5. 单颗重生不影响其它（哈希验证）。
6. 增删不重排。
7. 分批生成可见。
8. 重启可恢复。
9. 六张截图。

## 回退方案

- **AI 造出的星球都差不多**：加硬约束"每颗必须与所有其它星球至少三处不同"，并把温度降到 0.75（更敢写差异）。
- **轨道挤在一起**：校验里按 `1.35` 倍率重排；必要时把 `a_outer_max` 提到 120。
- **生成太慢**（5 颗 × 3 分钟）：`bake_batch=1` 分批 + 允许"先看低模球（L2）"，进入 `planet` 模式再升精度。
- **编辑后几何没变**：那是"只改卡没重建"；明确提供"应用"按钮，并在有未应用修改时高亮。
- **用户想手写宇宙**：提供"导入 JSON"，直接读 `universe_spec.json` 并校验。
