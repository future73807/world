# 30 · 拓荒解锁状态机

> **一句话**：浏览器蓄力并请求拓荒，服务端跑后台作业、验证并发布完整新版本，浏览器读取结果后预载新环、原地开雾；Blender 只作为离线生成器出现。

---

## 前置

零件 06（服务端能跑后台作业）、零件 28、29（浏览器边界、碰撞与蓄力请求已就绪）。

---

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**仪式主持人与作业编排者**。整个“拓荒”的生命周期由你管：浏览器和服务端各自负责什么、失败怎么回滚、完整资源版本何时可见。任何状态都不得把玩家移动、输入或相机的控制权交给 Blender 或服务端旧快照。

### 步骤 0 · 三方职责与通信边界

| 参与方 | 负责 | 绝不负责 |
|---|---|---|
| **浏览器 Three.js 游戏** | 靠近/蓄力、调用拓荒 API、保存 `request_id`、读取进度/结果、预载 GLB、原子激活、碰撞扩边、播放开雾、维护玩家与相机 | 直接写服务端文件、直接操作 Blender、等待每帧控制指令 |
| **网页服务端** | 持久化请求、幂等校验、AI/离线预设、作业队列、进度与结果、候选版本验证、世界状态与当前版本指针发布、备份和回滚 | 逐帧移动玩家、覆盖浏览器相机、把半成品目录暴露给玩家 |
| **Blender CLI 离线生成进程** | 由服务端作业调度，读取新环 spec 与导出输入，生成新环 GLB、源 `.blend` 和校验信息 | 接收 WASD/E、运行玩家控制、轮询结果来驱动游戏、保存实时相机 |

通信约定：

- 浏览器通过 HTTP/WebSocket 或等价游戏 API 与服务端通信；服务端将请求与结果持久化为 `runtime/unlock_request.json`、`runtime/unlock_result.json` 或等价记录。浏览器不直接写这些文件。
- 请求至少含 `request_id`、`ring_from`、`direction`、`player_pos`、`created_at`。结果至少含 `request_id`、`status`（`ok`/`failed`）、`ring_new`、`asset_version`、`error`、`finished_at`。
- `runtime/world_state.json` 是服务端持久世界进度的唯一真相，由服务端状态机写入；浏览器读取发布快照，但实时移动、跳跃、输入与相机不归它管。
- `player_pos` 只用于请求诊断和检查点参考，不作为让服务端持续纠正玩家位置的依据。
- `request_id` 全链路保持不变，服务端对同一 id 幂等处理。网络重试不新建作业，浏览器重连不重复播放已确认的开雾。

### 步骤 1 · 状态定义与所有权

| 状态 | 执行者 | 含义 | 退出 |
|---|---|---|---|
| `IDLE` | 服务端持久状态 | 无拓荒，也是成功/失败后的结束态 | 收到合法请求 |
| `NEAR_EDGE` | 浏览器本地 | 已在可拓荒区，不写入服务端状态机 | 离开或开始蓄力 |
| `CHARGING` | 浏览器本地 | 零件 29 的按住蓄力 | 满、松开或取消 |
| `REQUESTING` | 服务端 | 请求已持久化，正在校验、准备 spec 并入队 | 入队成功或失败 |
| `GENERATING` | 服务端作业 | 离线资产生成器正在产出候选版本 | succeeded / failed / timeout |
| `APPLYING` | 服务端 | 校验完整 GLB/manifest、备份并原子发布状态与版本指针 | 发布成功或回滚 |
| `REVEALING` | 浏览器 | 读取 `ok` 结果，预载并激活新环，扩边与开雾 | 浏览器完成回执或激活失败 |

- 服务端 `world_state.fsm` 记录持久阶段 `idle/requesting/generating/applying/revealing`；浏览器 `NEAR_EDGE/CHARGING` 是本地交互状态，不高频写盘。轻 HUD 可组合显示服务端阶段与浏览器本地阶段。
- `REQUESTING/GENERATING/APPLYING/REVEALING` 期间拒绝新的拓荒请求，并提示“拓荒进行中”。同一 `request_id` 的查询和重试不算新请求。
- 发布前失败：回到 `IDLE`，ring、当前版本、地图、雾与碰撞保持原状，允许重试。
- 发布后浏览器激活失败：旧场景始终保留，浏览器报告失败；服务端按备份恢复上一世界状态和版本指针，再记录失败结果。不得留下“状态已扩环、浏览器却只能玩半张图”的无标识中间态。

### 步骤 2 · 请求（REQUESTING）

按顺序执行，任一步失败都走可恢复失败路径：

1. 服务端读取并校验请求和 `runtime/world_state.json`：`ring < MAX_RINGS`、方向未解锁、当前无其他 running/pending 作业、`ring_from` 与当前一致。
2. 生成下一环设定卡：以父环 spec、方位和可选玩家心愿调用零件 31。AI 可以较慢，因此在后台执行，轻 HUD 显示“正在构思新土地…”。
3. AI 失败或超时使用零件 31 的确定性离线预设，不把无 Key 当成阻塞游玩的理由；记录实际使用的是 AI 还是兜底。
4. 将完整卡写入 `specs/ring_{n+1}.json`，记录下一环 seed 与 `pending_ring=n+1`，**此时不增加 ring、不改当前版本指针**。
5. 入队 `kind=ringgen` 作业。输入包括新环 spec、当前状态快照、当前资源版本与不可变候选 `asset_version`；产物要求按零件 32 是新环 GLB、完整候选 manifest、地图/碰撞数据与可编辑源工程。
6. 入队成功进入 `GENERATING`；入队失败清理 pending 标记并回 `IDLE`，不发布任何候选路径。

### 步骤 3 · 生成中（GENERATING）

- 服务端把 `job.progress` 转成人类可读阶段，如“在种树…”，浏览器用轻提示和角色附近小进度点呈现，不打开常驻日志。
- 浏览器中的雾可轻微脉动（0.5Hz、振幅 0.5 BU），这是本地等待表现；玩家仍可移动、跳跃和环视，旧空气墙持续有效。
- Blender CLI 只在后台生成资产，没有玩家窗口，也不接收浏览器逐帧消息。
- 默认 240 秒超时：服务端终止作业、保留失败记录、清理 pending，当前指针与世界状态不变。浏览器收到 `failed` 后恢复雾的常态并允许重试。

### 步骤 4 · 校验与发布（APPLYING）

作业成功不代表可以立即发布。服务端只发布**完整且验证通过的版本**：

1. 按零件 32 验证候选 manifest、全部必需 GLB/LOD、共享资源、地图、碰撞数据、seed/ring/island_size 和 hash；旧区块 hash 必须 100% 不变。
2. 验证候选 `asset_version` 与请求、`pending_ring`、spec 一致，所有资源已写完并可读取，禁止引用尚未完成的文件。
3. 备份当前 `world_state.json`、当前版本指针及请求上下文到 `runtime/backup/`，保留上一资源版本，不覆盖旧 GLB。
4. 在一个服务端提交事务中更新：`ring += 1`、`island_size += 20`、追加 seeds/unlocked_chunks/landmarks、设置新 `asset_version` 与 `last_generated_at`，清除 `pending_ring`，把 `fsm` 置为 `revealing`，并原子切换当前版本指针。
5. 写入匹配 `request_id` 的 `ok` 结果，包含新版本和可校验的 manifest 信息。只有到这一步，浏览器才可发现并使用新版本。

`APPLYING` 不打开 `.blend`、不向 Blender 场景追加对象，也不重建浏览器整岛。实际新增内容只有零件 32 已导出的新环资源。

### 步骤 5 · 浏览器预载、激活与开雾（REVEALING）

浏览器读到 `ok` 后仍继续显示旧版本，先预载并校验新环 GLB、共享资源、碰撞和地图。全部准备成功后，按零件 32 在一个帧边界原子激活；玩家位置、实时输入、相机 yaw/pitch/dist 与弹簧状态不变。

随后播放 1.5 秒浏览器开雾动画：

- 0~0.5s：旧雾透明度从 0.65 降到 0.15，每边向外移动 10 BU（总边长增加 20 BU），让新土地从雾里浮出。
- 0.5~1.0s：新环 GLB 从边缘向内显影，可用材质透明度或裁剪扫过；对应碰撞已随原子激活准备完毕。
- 1.0~1.5s：新边界重新凝雾，透明度回到 0.65，小地图与碰撞边界保持同一新版本。

播放完成后浏览器发送匹配 `request_id + asset_version` 的完成回执。服务端幂等追加 `ring.unlocked`、将 `fsm` 回到 `idle`，零件 08 再触发轻通知。重复回执不得重复加环或重复事件。

### 步骤 6 · 唯一真相、并发与资源回滚

- 服务端先读 → 改 → 写临时文件 → 原子替换；写后校验 JSON 可解析、ring 合法、manifest 与版本一致。文件锁与进程内互斥用于防双写，拿不到锁按参数重试。
- 当前版本指针与状态提交必须可恢复；不可变候选目录绝不被后续作业覆盖，旧版本在浏览器完成或失败结论前不得删除。
- 发布前任何失败都无需碰旧资源。发布后激活失败则恢复备份中的旧状态与旧指针；失败候选和日志留作诊断，不删证据假装成功。
- 浏览器可以在激活失败后继续玩旧场景，回滚期间不重置玩家、相机、时间和天气。
- 重试必须创建新的请求轮次或沿用服务端明确允许的同一幂等请求，不得绕过 `ring_from` 与单作业校验。

### 步骤 7 · 崩溃与断线恢复

- 服务端在 `REQUESTING/GENERATING` 崩溃：重启后读取 `pending_ring` 和作业记录。作业仍有效则续接；无有效产物则标失败并允许重试，不增加 ring。
- 在 `APPLYING` 崩溃：依据提交日志判断是“未发布”还是“已完整发布”。未发布可重新验证候选；已发布必须能恢复对应结果，不再生成第二份环。
- 已发布但浏览器未回执：保留 `revealing` 和旧版本资源。浏览器重连后按 `request_id` 继续预载/激活，或明确报告激活失败以触发回滚；服务端不重复扩环。
- 浏览器崩溃不意味着丢失实时控制权威。重连后从已发布版本和最近确认检查点恢复，不能在每个进度包到达时把当前玩家拉回旧坐标。

### 步骤 8 · 验收

1. 用真实新环 GLB 跑通 `IDLE → REQUESTING → GENERATING → APPLYING → REVEALING → IDLE`，ring +1、版本 +1，浏览器连续可玩。
2. 分别模拟 AI 失败走离线兜底、作业失败、超时、候选缺 GLB、旧 hash 变化，均不得发布半成品；雾与世界保持原状。
3. 连点两次蓄力、网络重试和断线重连只产生一个有效作业与一个 `ring.unlocked`。
4. 在生成、发布前后和浏览器预载阶段分别模拟崩溃，恢复路径明确，不双扩环。
5. 人为制造浏览器激活失败，确认旧场景可继续玩、旧状态与版本指针可恢复、玩家相机不重置。
6. 保存浏览器连续录屏、请求/结果、作业进度、状态与 manifest 前后对比、回滚证据；全程没有交互式 Blender 玩家窗口。

## 参数表

## 验收标准

1. 浏览器请求 → 服务端作业 → 完整版本发布 → 浏览器预载/激活/开雾的责任链完整，Blender 仅离线出资产。
2. 状态流转与非法转移拒绝正确，失败不泄露半成品；发布后失败能回滚资源版本和状态。
3. 请求、回执和事件均幂等，连点、重试、崩溃恢复不会双生成或重复扩环。
4. 开雾由浏览器播放，新 GLB/manifest/地图/碰撞一致，旧区块 hash 不变，玩家与相机不重置。
5. `world_state.json` 原子可解析，`ring.unlocked` 与轻通知链路正确，重复回执不重复事件。
6. 真实浏览器全流程、失败与回滚证据完整，没有 Blender 客户端读写玩家控制的环节。

## 回退方案

- **AI 卡生成超过 90 秒**：直接采用零件 31 的确定性离线预设并记录，不在同一作业中途换 spec。
- **候选产物冲突**：新环对象/资源使用环号命名空间，但共享材质按契约复用；任何旧资源被改动都拒绝发布。
- **开雾掉帧**：降为 0.6 秒交叉淡入，仍保留旧雾退去与新边界凝成，不改变版本提交顺序。
- **浏览器预载失败**：继续旧版本并报告明确错误，触发状态/指针回滚；不显示空白页，不要求玩家打开 Blender。
- **回执丢失**：浏览器用同一 `request_id + asset_version` 重试，服务端幂等完成，不重新入队。
