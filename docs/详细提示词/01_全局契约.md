## 契约正文

### A. 单位与坐标

- 长度单位：Blender 默认单位（BU）。1 BU ≈ 1 米。
- 出生岛：边长 **100 BU**，中心在原点，平面 X-Y，高度沿 +Z。
- 海平面：**Z = 0**。地形最低点不低于 -8，最高峰不高于 30。
- 区块边长：**10 BU**。出生岛 = **10×10 = 100 个区块**，索引 `cx, cy ∈ 0..9`，区块中心 = `(cx-4.5)*10, (cy-4.5)*10`。
- 环（ring）编号从 0 开始，环 r 的世界边长 = `100 + 20*r`（r=0 时 100，r=4 时 180）；上限 4 环，也就是玩家能把它扩到 180×180。
- 每扩一环：总边长 **+20 BU**（每边各外扩 10 BU = 一个区块宽），网格边长 +2。扩环永远落在区块边界上，不会切碎区块。

**三级尺度（39~45 引入，必读）**：本项目有三套互相独立、只通过"设定卡"通信的坐标尺度。混用它们是最容易出的灾难。

| 层级 | 单位 | 尺度 | 谁在用 |
|---|---|---|---|
| **地表（surface）** | BU | 岛 100~180，史莱姆 1.5，树 2~4 | 零件 14~38 全部 |
| **星球（planet）** | BU | 半径 `planet_radius`（默认 120），地形起伏按 `relief`（0~1）缩放到该半径的比例 | 零件 39、40、44 |
| **宇宙（cosmos）** | RU（宇宙单位） | 恒星 1 RU，行星轨道 4~60 RU（**对数压缩**） | 零件 41~43、45 |

- 地表 → 星球：**投影**（把岛的径向高度场贴到球面），位移量 = `relief × planet_radius × 0.08`。不缩放岛尺寸，只缩放起伏。
- 星球 → 宇宙：**压缩**。行星直径在宇宙视图里固定为 `0.5~2 RU`（**不按真实比例**，否则行星是一粒灰）。真实半径只用于物理计算，不用于渲染。
- 宇宙单位与 BU **永不直接相加**。任何跨层级运算必须显式经过上面两条换算。

### A2. 主运行时与资源契约

- **浏览器是唯一实时游戏运行时**：`app/` 用 Three.js/WebGL 负责渲染、输入、玩家移动、跳跃、相机、碰撞、动画状态与 HUD。
- **Blender 是离线资产工具**：生成可编辑 `.blend`、低模 GLB、地图与诊断截图。不得要求玩家在 Blender 中运行控制脚本。
- 禁止用整岛图片、视频、DOM 瓦片或 2.5D 精灵冒充可进入的 3D 世界。

**分块资源**：

- 每个区块、每个 LOD 导出独立 GLB，公共资源（树、草、角色等）单独导出并复用几何与材质。
- 路径：`app/public/world/{asset_version}/chunks/Chunk_{cx}_{cy}_L{lod}.glb`。
- 公共资源：`app/public/world/{asset_version}/shared/`。
- 清单：`app/public/world/{asset_version}/manifest.json`；当前版本指针由服务端 API 提供，禁止浏览器猜测目录名。

`manifest.json` 必含：

| 字段 | 含义 |
|---|---|
| `schema_version` | 清单结构版本 |
| `asset_version` | 一次完整导出的不可变版本号；新扩环生成新版本 |
| `world_seed` / `ring` / `island_size` | 与当前世界状态一致的身份信息 |
| `coordinate_space` | 固定为 `blender_z_up_game` |
| `chunks[]` | `id`、`cx`、`cy`、`ring`、`lods[]`、`bounds`、`hash` |
| `lods[]` | `lod`、`url`、`triangles`；L0/L1/L2 至少提供契约所需档 |
| `shared[]` | 公共资产 `id`、`url`、`hash` |
| `map_url` | 与该版本同批生成的 `map_tiles.json` |
| `spec_hash` / `created_at` | 设定卡一致性与导出时间 |

**坐标转换**：Blender 与游戏逻辑均使用 Z 向上；标准 glTF 导出为 Y 向上。加载 GLB 时只允许在一个统一适配层执行转换：glTF `(x, z, -y)` 经根节点绕 X 轴 `+90°` 转回游戏 `(x, y, z)`。不得在各零件中分别猜轴向。

**版本切换**：

1. 新版本所有 GLB、清单与地图写完后，才原子切换当前版本指针。
2. 切换期间保留旧版本，已加载场景不得突然消失。
3. 扩环只新增区块并更新边界；旧区块 `hash` 必须保持不变。
4. 玩家实时位置、输入状态与相机由浏览器维护，资源切换不得把玩家传送回出生点。
5. 加载失败继续显示旧版本并给出轻量提示，不显示空白驾驶舱或整页错误。

### F. 世界设定卡 schema（字段名冻结，类型冻结）

顶层字段：

- `version` 整数
- `seed` 整数（0 ~ 2^31-1）
- `name` 字符串（世界名，2~12 字）
- `biome` 枚举：`island` / `snow` / `desert` / `volcanic` / `mushroom` / `swamp`
- `mood` 字符串（一句氛围描述）
- `palette` 对象，含 `sky_top`、`sky_horizon`、`sun`、`water_deep`、`water_shallow`、`sand`、`grass`、`rock`、`snow`、`accent`，均为十六进制颜色字符串
- `terrain` 对象，含 `peak_height`（8~26）、`roughness`（0~1）、`beach_width`（2~8）、`island_bias`（-1~1）
- `water` 对象，含 `wave_height`（0~0.4）、`tint`（0~1）、`foam`（0~1）
- `sky` 对象，含 `time_of_day`（0~1，0=日出，0.5=正午，1=日落）、`fog_density`（0~1）、`cloud`（0~1）
- `time` 对象，含 `cycle_minutes`（一整天现实分钟数，默认 24）、`start_hour`（0~24，默认取 `sky.time_of_day` 换算）、`day_night`（0~1，昼夜对比强度）
- `weather` 对象，含 `kind`（`clear`/`rain`/`snow`/`storm`/`mist`）、`intensity`（0~1）、`frequency`（0~1，切换天气的频繁度）、`wetness`（0~1，雨后地面变深的程度）
- `regions` 数组，1~5 项——**高程—温湿度生态分区**。这是原创环境组织参数，不是任何外部游戏的视觉或玩法复刻。每项含：
  - `id` 字符串（如 `north_ridge`）
  - `elevation`（该区的高程带，0~1，映射到本岛的相对高度）
  - `moisture`（0~1，决定草地/沼泽/沙）
  - `temperature`（0~1，决定雪线/针叶/阔叶）
  - `tree_mix` 对象（三种树的权重，和为 1）
  - `palette_shift`（-0.2~0.2，对该区色相做微调）
  - `note`（一句中文，如"背风坡，土更干"）
- `creatures` 对象，含 `birds`（0~1）、`fish`（0~1）、`crabs`（0~1）、`butterflies`（0~1）、`fireflies`（0~1）；每个是"是否有 + 多寡"的滑杆
- `trees` 对象，含 `density`（0~400）、`weights`（三种树的权重，和为 1）、`scale_jitter`（0~0.4）
- `slime` 对象，含 `hue_shift`（-0.5~0.5）、`personality`（`shy`/`curious`/`sleepy`/`bouncy`/`grumpy`）、`bounce`（0~1）
- `landmarks` 数组，0~3 项，每项含 `kind`（`arch`/`giant_tree`/`meteor`/`lighthouse`/`bone_bridge`/`shrine`）、`note`（一句描述）
- `weirdness` 数字（0~1）

任何零件读 spec 时，缺字段一律用「契约默认值」补，不许抛错。

**新增字段的默认值**（老 spec 缺这些字段时用）：

| 字段 | 默认 |
|---|---|
| `time` | `cycle_minutes=24`、`start_hour=6.5`、`day_night=0.7` |
| `weather` | `kind=clear`、`intensity=0.3`、`frequency=0.3`、`wetness=0.4` |
| `regions` | 单区：`elevation=0.35`、`moisture=0.55`、`temperature=0.6`、`tree_mix` 取 `trees.weights`、`palette_shift=0`、`note="一整片"` |
| `creatures` | `birds=0.6`、`fish=0.4`、`crabs=0.4`、`butterflies=0.4`、`fireflies=0.5` |

### F2. 宇宙设定卡 schema（`specs/universe_spec.json`，零件 43）

按 `universe_spec.json` 的结构另有一份卡（不与世界卡混用）。核心只有一句：**宇宙卡 = 恒星 + 多份世界卡 + 轨道编排**。

- `planets[i].world_spec` 就是契约 F 的完整世界卡。所以"多星球"不引入任何新的地形代码。
- `planets[i].orbit` 含 `a`（半长轴 RU）、`e`、`inclination`、`period`、`phase`。
- `physics` 含 `mode`、`orbit_tension`、`universe_day_scale`。

宇宙卡顶层字段：`version`、`name`、`seed`、`mood`、`star`（`name`/`core`/`corona`/`mass`/`radius`/`luminosity`/`temperature_k`）、`physics`、`planets`（**1~7**）、`bodies`（非行星天体，见 48）、`home_planet_id`、`weirdness`、`relation`。

**`bodies`**（零件 48）：5 类非行星天体，`type` ∈ `asteroid_belt` / `comet` / `nebula` / `ring` / `black_hole` / `binary_star` / `ruin`。每项含 `id`、`type`、`a`（若是绕行物）、以及该类型专有字段。**`ring` 挂在某颗行星上**（用 `host_planet_id`），其余绕恒星。

**`physics`**（零件 49）：`mode`、`orbit_tension`、`universe_day_scale`、**`gravity`**（开/关）、**`temperature`**（开/关）、**`light_delay`**（开/关）、**`tides`**（开/关）、**`seasons`**（开/关）。

**`planets` 是 1~7 而不是 3~7**：1 颗 = **单星球模式**（没有星系，只有一颗球和一颗恒星）。这是合法的、甚至推荐的第一种形态——**先有一颗球，再谈宇宙**。

### F3. 星球归属（`origin` 与 `home_planet_id`，必须理解）

宇宙里的每颗星球有两种**出身**，这是本设计最重要的区分：

| `origin` | 含义 | 有没有"地表世界" | 能不能走进去 |
|---|---|---|---|
| `grown` | **你在地表一点点长出来的那颗**（有环数、有区块哈希、有史莱姆走过的痕迹） | 有，且在 `world_state.json` 里 | 能，且是唯一能继续拓荒的 |
| `born` | **只在宇宙里生成的观赏星球**（有地形有天气，但没人走过） | 没有独立存档 | 能降落观赏，但不能拓荒（或拓荒会新建一份存档，见 43 步骤 6） |

**`home_planet_id`**：指向那颗 `origin=grown` 的星球。规则：

- **有且至多一颗** `grown`。宇宙是你的观测框架，你的家只有一处。
- 允许 `home_planet_id = null`（整个宇宙都是 `born`，你在看别人的星系）。
- **单星球模式**下，那颗唯一的星球必须是 `grown`（否则你就没有"地表"了，退化成一个纯观赏球）。

**三种合法形态**（对应你的问题）：

1. **单星球**（`planets` 长度 1，`home_planet_id` = 它）—— 只有你和一颗恒星。`cosmos` 视角里是"一颗球孤零零地悬着"，这本身就很美。
2. **当前星球入系**（`planets` 长度 ≥2，其中一颗 `origin=grown` 且 `home_planet_id` = 它）—— 你长出来的岛成为星系的第一颗行星，其余是邻居。
3. **纯观测宇宙**（全部 `born`，`home_planet_id=null`）—— 没有地表，只有宇宙。适合截图与探索。

**关键约束**：`planets[i].orbit.a` 必须单调递增，相邻比值 ≥ 1.35；若 `physics.mode=realistic`，`period` 与 `a` 必须满足 `period ∝ a^1.5`。
- 三层尺度见 A 节末尾，**永不交叉相加**。

### G. 状态文件 `runtime/world_state.json`

必含字段：`version`、`ring`（当前已解锁到第几环，0 起）、`seeds`（每环一个整数数组）、`unlocked_chunks`（字符串数组，格式 `cx_cy`）、`landmarks`（数组，含 `kind`、`ring`、`position`）、`player`（含 `x`、`y`、`z`、`yaw`）、`island_size`（当前世界边长）、`asset_version`（当前完整资源版本）、`last_generated_at`（ISO 时间）、`jobs_last`（最近一次作业 id）。

**权威边界**：服务端持久化世界环数、seed、已解锁区块、地标和最近确认的玩家检查点；浏览器对实时移动、跳跃、相机和瞬时输入具有唯一控制权。浏览器以 1 秒节流及关键事件上报玩家位置，服务端不得用旧快照持续覆盖实时坐标。`player` 使用游戏/Blender 的 Z 向上坐标，不是 glTF 的 Y 向上原值。

**扩展字段**（可选，但一旦写入就必须遵守命名）：

- `fsm`：状态机当前状态（`idle`/`charging`/`requesting`/`generating`/`applying`/`revealing`），供轻 HUD 显示。
- `pending_ring`：正在生成中的环号（无则 null）。
- `mist`：迷雾外观快照，含 `bounds`（当前边界边长）、`color`、`alpha`；3D 与小地图共用。
- `clock`：世界时钟快照，含 `hours`（0~24 浮点）、`day_index`（第几天）、`weather_kind`、`weather_intensity`、`updated_at`。**昼夜与天气的持久化真相在这**，浏览器负责插值和表现，HUD 可显示“第 2 天 · 06:42 · 小雨”。
- `view`：当前视角（`surface`/`planet`/`cosmos`）与过渡进度（0~1）。**只改观察方式，不改世界状态**（零件 45）。
- `current_planet`：`cosmos` 模式下选中的星球 id（`surface`/`planet` 模式下也有值，表示“我在哪颗上”）。

写入规则：**先读 → 改 → 写临时文件 → 原子替换**。禁止直接覆盖。

### H. 事件名（`runtime/events.jsonl`，一行一个 JSON）

| 事件 | 触发时机 | 必含字段 |
|---|---|---|
| `job.enqueued` | 作业入队 | `job_id`、`kind`、`created_at` |
| `job.started` | 进程启动 | `job_id`、`pid`、`started_at` |
| `job.progress` | 收到进度行 | `job_id`、`stage`、`percent`、`message` |
| `job.succeeded` | 退出码 0 | `job_id`、`duration_ms`、`artifacts` |
| `job.failed` | 非 0 或超时 | `job_id`、`exit_code`、`stderr_tail` |
| `world.born` | 出生岛完成 | `seed`、`island_size`、`summary` |
| `ring.unlocked` | 新环并入场景 | `ring`、`island_size`、`seed`、`summary` |
| `map.updated` | 地图瓦片变化 | `ring`、`tile_count` |
| `notify` | 需要打扰用户 | `level`（`info`/`good`/`warn`/`error`）、`title`、`body`、`deep_link` |

`notify` 以不遮挡操作的轻提示呈现。`deep_link` 只能指向游戏内位置、目标或非驻留设置界面，不得要求玩家启动 Blender。

### I. 进度协议（Blender 脚本 → 调度器）

Blender 脚本向 stdout 输出固定前缀行，调度器只认这个：

`@@PROGRESS stage=<stage_name> pct=<0-100> msg=<一句话>`

`stage_name` 枚举：`init`、`terrain`、`region`、`coast`、`shade`、`water`、`sky`、`daynight`、`weather`、`trees`、`veg_zone`、`props`、`creatures`、`slime`、`mist`、`ring`、`done`。

脚本正常结束时再多打一行 `@@DONE chunks=<n> landmarks=<m>`。调度器解析失败不算错，只是进度条不动。

### J. 视觉与性能预算

- L0 基础地形：每块 200 三角面，出生岛 100 块合计 20,000 三角面；此数字不限制角色、树木、岩石与地标的近景细节。
- 出生岛默认实际渲染场景（含地形、水、植被、角色、生物与效果）目标 **≤250k 三角面**；每环新增实际渲染增量目标 ≤80k，满环目标 ≤570k。
- 统计必须区分独立源资产、驻留 LOD、实例源面数与当前渲染提交量；共享几何和不同 LOD 不得重复累计为“同屏面数”。
- 浏览器同屏 Draw Call ≤600（实例化、共享几何与合批）。主运行时目标为 1080p、验收硬件下 ≥45fps；Blender Eevee 帧率不能替代。
- 树 ≤260 棵，草簇 ≤2500 个实例，花 ≤600 个实例；按距离分配近/中/远 LOD，不逐棵复制网格。
- 史莱姆近景主体目标 1,200～2,000 三角面，整只近景 ≤3,000；身体、表情、透光与动画先达质量，再优化。
- 生物合计目标 ≤12k 三角面、≤160 个实例；天气特效 ≤240 个基础面片，可用 shader 增加细节而非简单删光效果。
- 昼夜与天气在浏览器中的合计额外帧时间 ≤4.5ms。
- **任何性能降级不得把主角或近景模型退回粗糙 primitives、方柱/方冠或单纯大三角片。** 优先调整实例数量、远景 LOD、更新频率和不可见内容。

### K. 地形网格统一口径

- L0：每块 11×11 = 121 顶点；10×10 个采样单元，每单元 2 个三角面 = 200 三角面。
- L1：6×6 顶点 = 50 三角面；L2：3×3 顶点 = 8 三角面。
- 顶点 XY 可做确定性扰动，三角形交替对角线；不得把采样单元渲染成独立方砖或描出网格线。
- 块内索引共享顶点。跨块允许边界重复顶点，但同一世界坐标必须由纯函数产生相同位置与法线判定，保证视觉上无缝。
- 方块轮廓不能靠减小三角面尺寸来辩解；验收看整体轮廓与近景实拍。
- 任何零件不得再使用 17×17、25k、120k 等旧数字；确需调整时先改本契约并同步全库。

### L. 输入、运动、镜头与 UI 统一口径

- 桌面：WASD/方向键移动，单击后指针锁定环视，滚轮缩放，空格跳跃，Shift 冲刺，E 互动，M 全屏地图，J 目标详情，Esc 取消/关闭/暂停。
- 触屏：左下虚拟摇杆、右侧滑动环视、右下跳跃/冲刺/情境互动；地图和菜单有独立原创入口，避开系统手势安全区。
- 角色运动包含待机、起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；速度、动画、碰撞与镜头反馈一致，不能滑步。
- 相机默认第三人称跟随，支持自由环视、平滑缩放、避障与遮挡淡出；松开鼠标不强制回正，只有设置允许的移动辅助回正。
- 互动目标按距离、视线方向与可达性选择，提示跟随当前最佳目标并随输入设备更新图标。
- 默认 HUD 只有小地图、简短目标、必要状态、情境提示与临时通知；全屏地图、暂停/设置、世界创建和开发者工具各自独立且可关闭。
- UI 必须先有桌面/触屏线框，再有默认 HUD、地图、暂停与互动的高保真设计稿和统一 token；禁止直接以通用网页组件拼盘通过。
- UI 使用原创图标、合法字体、排版和动效，参考开放世界游戏的信息层级，不导入其他游戏资源。
