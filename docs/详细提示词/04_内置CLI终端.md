# 04 · 开发者 CLI 终端

> **一句话**：为开发者提供默认隐藏的白名单终端——流式输出、可中断，危险命令一律拦下；普通游戏不显示、不依赖它。

## 提示词正文
> **共同硬约束（独立执行本零件也必须遵守）**
> - 主游玩端是浏览器全屏 Three.js/WebGL；Blender 只负责从零生成、导出和离线检查，禁止把“打开 Blender”作为玩家步骤。
> - 恢复包中的任何文件均不得读取、参考或导入；所有 UI、模型、材质和动画从空白重新设计，禁止迁移、换皮或使用外部游戏/现成模型包资源。
> - 目标是**精致风格化低模**：大/中/小结构、合理拓扑与平面/分组平滑/加权法线、原创程序化材质和近景细节。低面数不等于简陋，禁止方块、体素、像素纹理和粗糙 primitives 通过。
> - 新模型先交剪影、灰模、材质完成图及近/中/远实机证据；美术不合格不能用低面数、帧率或“非 MC”豁免。
> - 新 UI 先交桌面/触屏线框和高保真 HUD/地图/暂停/创建/互动设计稿，使用原创图标、合法字体和统一 token；只参考开放世界游戏的信息层级，不复制具体素材。
> - 默认第三人称跟随。角色具有起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地；桌面 WASD/指针锁定/空格/Shift/E/M/J/Esc，触屏才显示虚拟控件；松鼠标不强制回正。
> - 禁止三栏/左右常驻面板/常驻日志。CLI 与性能工具默认隐藏，创建、设置、编辑只在高保真非驻留界面。
> - 本零件与上述约束冲突时，上述约束优先；若正文仍存在旧指令，停手报告，不擅自回退产品方向。

你是**终端接线员**。目标：开发者在显式打开的开发工具里敲一条命令，服务端 spawn 它，stdout/stderr 实时流回开发终端。安全优先，终端不是玩家入口，也不是常驻底部抽屉。

### 步骤 1 · 服务端执行路由

在 `app/server` 建一条 POST 路由，接收 `{ cmd, args, cwd }`。执行前做三件事：

1. **白名单**：只允许 `blender`、`npm`、`node`、`python`、`py`、`git`、`ls`、`cat`、`echo`、`cls`。其余一律拒绝，返回"该命令未在白名单"。
2. **参数审查**：拒绝任何含 `rm `、`rmdir`、`del `、`format`、`mkfs`、`curl | sh`、`> /dev`、盘符根路径写入的调用。
3. **路径钳制**：`cwd` 必须落在项目根目录之内（解析绝对路径后前缀校验），越界拒绝。

被拒绝时不要只回 403，要回一条能显示在终端里的红字，让用户知道哪一条规则拦的。

### 步骤 2 · 流式回传

执行体用子进程 spawn（不是 exec 拼字符串，参数数组传）。把子进程的 stdout 与 stderr 分别打上 `out` / `err` 标记，按行通过 SSE 或分块 HTTP 回灌。每行带 `ts`（毫秒时间戳）与 `stream`。

前端按行追加，`out` 用浅灰白，`err` 用暖橙，`system` 用青。

### 步骤 3 · 生命周期

- 每条命令生成一个 `run_id`，可以在开发终端里点"停止"发中断（Windows 下用任务树杀，别只杀父进程）。
- 命令结束追加一行 `[exit N · 1.2s]`。
- 同一时刻最多 1 条终端前台命令（背景作业归零件 05，不走这条）；这里的"前台"只指 CLI 会话，不代表它占据游戏前景。

### 步骤 4 · 开发终端交互与游戏输入隔离

- 仅在开发模式开启后，通过明确的开发操作进入 `developer` 状态；默认 HUD 不放 CLI 图标、日志摘要或命令输入框，普通玩家流程也不需要打开它。
- 打开后，终端是非驻留、可关闭的开发界面。终端输入框与按钮捕获自己的键鼠事件，`WASD`、空格、`E`、方向键和终端快捷键不得传给角色、相机或情境互动。
- 关闭终端时清空按键按下集合，回到进入前的游戏状态，保留玩家位置、相机姿态与目标；不得借关闭操作触发一次跳跃、互动或视角缩放。
- 输入行支持 `↑/↓` 历史（存 localStorage，最多 50 条）。
- `Ctrl+L` 清屏，`Ctrl+C` 中断当前终端前台命令，均只在终端输入上下文聚焦时生效。
- 输入 `help` 打印本终端支持的内建指令：`help`、`clear`、`history`、`jobs`（接零件 05 后可用）。输入 `?` 与 `help` 等价。
- 自动滚动到底；用户手动上滚时暂停自动滚动，出现"回到底部"小按钮。完整 stdout/stderr 只留在这里，不复制到普通游戏 HUD。

### 步骤 5 · 命令预设小按钮

开发终端顶部四个 chip，点了直接填充输入框（不自动执行）：

`blender --version` · `npm run dev` · `git status` · `cat runtime/events.jsonl`

`blender --version` 只用于开发环境诊断；资产生成由后台调度器离线执行，不提供"打开 Blender"命令或玩家引导。

### 步骤 6 · 自检

- 默认进入游戏并操作走、跳、环视，确认终端与日志不可见；未做显式开发操作时也不能通过游戏按键误开。
- 显式打开开发终端，跑 `blender --version`，应输出版本行。
- 跑 `rm -rf /`，应被拦，红字显示规则名；跑 `cat ../secret`（不存在路径），应显示错误但不崩。
- 终端输入框聚焦时按 `WASD`、空格与 `E`，角色不移动、不跳跃、不互动；关闭后回到同一玩家位置与相机，且无粘键。

存默认游戏与开发终端截图 `renders/app_step04_*.png`，默认游戏截图中不得出现 CLI 或日志。

## 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `MAX_LINE` | 4000 | 单行截断字符数 |
| `MAX_BUFFER` | 2000 | 面板保留最大行数，超出丢最旧 |
| `HISTORY_MAX` | 50 | 历史条数 |
| `FG_TIMEOUT_S` | 600 | 前台命令超时强杀 |
| `ALLOWLIST` | 见上 | 白名单，扩展需用户同意 |

## 验收标准

1. 默认全屏游戏没有 CLI、日志或常驻终端入口；只有开发模式下的显式操作能打开。
2. `blender --version` 在开发终端里输出正常，只作为离线环境诊断。
3. 危险命令被拦，文案说清拦的是哪条规则。
4. 流式输出不是一次性吐出（跑一个会分段 sleep 的测试命令，能看到逐行出现）。
5. `↑` 历史、`Ctrl+L`、`Ctrl+C` 三件可用，且不会穿透成游戏输入。
6. 停止按钮能真正杀掉子进程（任务管理器里确认无残留）。
7. 开关终端前后玩家位置、相机与目标不变，输入无粘滞；危险命令、正常命令及默认无终端的游戏截图已存。

## 回退方案

- **Windows 上杀进程残留**：改用 `taskkill /PID <pid> /T /F`；仍残留则在汇报里标注，让用户手动清。
- **SSE 被代理缓冲**：改分块 HTTP（`Transfer-Encoding: chunked`）并禁用压缩。
- **白名单误拦**：不要放宽到任意命令；把用户想加的命令逐条写进 `ALLOWLIST` 常量并注明原因。
