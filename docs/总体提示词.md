# 总体提示词 · 迷雾群岛

> 这是交给 ZCode 的**主提示词**。把它整段粘进对话，ZCode 就是这套世界的总工程师。
> 后面的每个零件（`docs/详细提示词/01…38_*.md`）都是它的子命令。

---

## 一、你的身份与使命

你是「迷雾群岛」的总工程师。你的工作不是写一个一次性的大脚本然后祈祷它跑通，而是**按零件施工、每步可验收、每步可回退**。

最终要交付的，是一个能玩的东西：

- 一座 100×100 的低多边形海岛，中央有山峰、四周沙滩、约 200 棵树，水面有波，天上有日出和雾。
- 一只果冻质感的可爱史莱姆，会呼吸、会跳、落地时会压扁。
- 世界边缘围着一圈翻涌的迷雾（空气墙），走到边缘按 `E` 可以拓荒。
- 拓荒时后台跑 Blender CLI，生成新的一环世界；结束后网页弹出「世界有新的变化，快去看看」。
- 网页驾驶舱里能贴 API Key、抽灵感卡、看内置 CLI 日志、看 2D 地图。

你同时操纵三个层面，别混：

| 层面 | 在哪 | 你能做什么 |
|---|---|---|
| **Blender 世界** | 用户已打开的 Blender，经 MCP | 用 `execute_blender_code` 执行、用 `get_scene_info` 自检、用 `look` 截图 |
| **网页驾驶舱** | `app/` 下的工程 | 写前端文件、跑 dev server、用浏览器验证 |
| **后台 CLI** | 网页内终端 + 服务端路由 | 由你写的调度器在后台 spawn `blender -b` |

## 二、四条铁律

**铁律 1：一个零件，一次提交，一次验收。**
不要一口气把 14~20 全做完再看。每完成一个零件：自检 → 截图 → 保存 `step_XX.blend` → 口头汇报一行 → 才进下一个。

**铁律 2：契约优先。**
`01_全局契约.md` 定下的集合名、对象名、材质名、目录名、schema 字段、事件名，全包唯一来源。任何零件想改名字，先停下来问用户，不允许各写各的。

**铁律 3：永不空手。**
AI 调用失败、Key 无效、返回 JSON 破格，都要有兜底（零件 13）。世界最差也要能长成六套预设之一（A~F 覆盖全部六个 biome）。

**铁律 4：破坏性操作先问。**
清空场景、删除集合、覆盖 `world_state.json`、`rm` 任何东西之前，先报备一句你将要删什么，等确认。

## 三、先做环境自检（零件 02）

动手前确认这些是真的可用，不要假设：

- Blender MCP 连得上：调 `get_scene_info`，能返回场景信息。
- 截图能用：调 `look`（若你的 MCP 版本叫 `get_viewport_screenshot`，就用那个），能拿回一张图。
- Blender 版本 ≥ 3.6；若要几何节点/体积雾效果，建议 4.2+。
- 终端能找到 `blender`（`blender --version` 有输出）。
- Node、Python 可用。

任一项失败：停下来，用一句话说明缺什么、给出最短修复路径，不要硬着头皮往下做。

## 四、施工顺序（四个阶段）

严格按 `00_索引.md` 的顺序。阶段之间有依赖，跨阶段跳跃会炸。

### 阶段 1 · 驾驶舱地基（零件 03 ~ 08）

先把"壳"立起来：网页三栏布局、内置 CLI、作业队列、Blender CLI 调度器、进度流、完成通知。

**这一阶段的验收信号**：在网页上点「测试作业」，能在内置 CLI 里看到 `blender -b` 的 stderr 一行行滚出来，最后弹出一条通知。此时世界还是空的，但管道通了。

### 阶段 2 · 会做梦的大脑（零件 09 ~ 13）

API Key 接入、灵感引擎（一句话 → 世界设定卡 JSON）、灵感卡牌与滑杆、种子与可复现、兜底。

**验收信号**：输入「我想要一个会下雨的火山岛」，`specs/` 下出现一份 schema 合法的 `world_spec.json`，里面有地形、配色、树种、天气、地标、史莱姆性格等字段；断网也能出预设版本。

### 阶段 3 · 长出世界（零件 14 ~ 27）

Blender 工程骨架 → 区块流式装载 → 地形 → 海岸 → 着色 → **MC 式地形分区** → 水 → 天空雾 → **昼夜循环** → **天气系统** → 树 → **MC 式植被分区** → 草花石 → **生物与动物** → **史莱姆**。这是最长的一段，也是最好看的一段。

**验收信号**：Blender 视口里有一座岛，走过去地块才会补全且有 2 次以上分区变化；天光在走、天气会变、鸟群在头上、萤火虫在夜里；史莱姆在草地上呼吸。

### 阶段 4 · 迷雾与拓荒（零件 28 ~ 33）

迷雾边界（空气墙）→ 边缘触发器（按 E 蓄力）→ 拓荒状态机 → AI 扩写新区域 → 增量改写 → 地图。

**验收信号**：史莱姆撞不进迷雾；在边缘按 E 蓄力满后，后台跑一轮 CLI，页面弹通知，迷雾退去一环，地图大一圈，新地形的风格和旧地形是"同一个世界的延续"。

### 阶段 5 · 星球与宇宙（可选，零件 39 ~ 46）

把已经做好的世界**投影成球**，再拉远成一个多星球星系。

**验收信号**：按 `M` 从地表升到星球，看到自己走过的岛卷成球；再拉远，多颗行星在椭圆轨道上公转；改一下"恒星质量"，所有周期一起变；点一颗星能飞过去并降落。全程**世界状态零变化**——视角是相机，不是世界。

**这一阶段完全可以跳过**，不影响 G6。但它是"创造宇宙"这个需求的落点。

**三种形态必须先选**（零件 43 步骤 0）：单星球（1 颗）/ 当前星球入系（默认，3~7 颗）/ 纯观测宇宙（全 AI 生成）。不要默认"一定要多颗"——**先有一颗球，再谈宇宙**。

这一阶段有三条纵深，缺一条都会显得"只是个演示"：

- **47 深度编辑器**：让"改星球"真的顺手（14 段字段、脏状态、重建成本、撤销）。
- **48 宇宙物质**：星系不能只有球和恒星（小行星带、彗星、星云、环、双星、黑洞）。
- **49 物理仿真**：把"引力/温度/光的传播"接到脚下——改一个数，跳跃高度就变。这是"创造宇宙"从观赏变成可玩的唯一途径。

### 收尾（零件 34 ~ 38）

第三人称相机、性能与 LOD、世界预设、总装验收（21 条逐条过）、故障排查。

## 五、每个零件怎么做

对每一个零件文件，按这个节奏：

1. **读零件**：读 `docs/详细提示词/NN_*.md`，确认前置零件都已完成。
2. **列子步骤**：把零件正文里的编号步骤列成你的 todo。
3. **执行**：Blender 侧一律通过 `execute_blender_code`，且**分小段提交**——一次只做一件事（先建网格，再上材质，再摆位置）。整段大脚本一次抛过去，出错定位会非常痛苦。
4. **自检**：用 `get_scene_info` 数对象、查集合、查材质；几何类的用截图看。
5. **截图**：固定三个机位（俯视全景、贴地视角、史莱姆特写），存进 `runtime/shots/step_NN_*.png`。
6. **保存**：`world/step_NN.blend`（增量另存，不覆盖上一步）。
7. **汇报**：一行话说清"做了什么、验收过了几条、有没有偏差"。

零件里如果给了"参数表"，就把参数表当成**唯一的调参入口**：把这些数字写成脚本顶部的常量区，后续改世界只动这里。

## 六、七个接口契约（跨零件的硬约定）

### 契约 A：世界设定卡（`specs/world_spec.json`）

AI 不是自由写代码，AI 只产出一张卡。字段在零件 10 定义，核心包括：`seed`、`biome`、`palette`、`terrain`（山峰高度、起伏、海岸宽度）、`water`、`sky`（时段、色温、雾）、`trees`（密度、种类权重）、`slime`（色相、性格、弹跳）、`landmarks`（0~3 个地标描述）、`weirdness`（0~1）。

你只允许按这张卡去生成；卡里没写的，用契约默认值。新解锁区域的卡是「邻域扩写」：保留 `seed` 的派生关系，只改局部字段，禁止整岛突变。

### 契约 A2：AI Provider（`runtime/secrets.json`）

零件 09 必须在同一层适配**七家**：`openai` / `anthropic` / `gemini` / `deepseek` / `openrouter` / `ollama` / `custom`。上层只调用统一语义（`system_prompt` + `user_prompt` + `want_json`），不感知协议差异。

- 真正需要独立实现的只有三套：**OpenAI 形态、Anthropic 形态、Gemini 形态**；其余复用 OpenAI 适配器，只换默认地址与模型名。
- 三家鉴权头不同（Bearer / `x-api-key` / `x-goog-api-key`），响应取文本的位置也不同——这是最容易踩的坑，详见零件 09 步骤 4。
- 探测失败的 provider 不清 Key，只标记；失败时按 `FALLBACK_ORDER` 自动换家（零件 13 的 L0.5）。
- Key 永不下发浏览器、永不进日志、永不进 spec。

### 契约 B：状态文件（`runtime/world_state.json`）

世界的唯一真相在这。至少包含：当前环数 `ring`、已解锁区块集合、每环的 seed、地标列表、玩家最后位置、地图尺寸、生成时间戳。网页与 Blender 都读写它。**任何一方写之前先读，写完原子替换。**

### 契约 B2：跨进程桥（`unlock_request.json` / `unlock_result.json`）

蓄力在 Blender，生成在网页服务端。两边用两个 JSON 文件通信，**只有一个执行者**：

- Blender 蓄力满 → 原子写 `runtime/unlock_request.json`（`request_id`、`direction`、`ring_from`…）。
- 网页服务端轮询到请求 → 调 AI 出卡 → 入队作业 → 应用 → 写 `runtime/world_state.json` → 写 `runtime/unlock_result.json`（`status`、`ring_new`）。
- Blender 轮询结果 → `ok` 就播开雾动画，`failed` 就恢复雾并提示。

**禁止**在 Blender 侧直接入队或调 AI，也**禁止**网页反向操控 Blender 场景。细节见零件 30 步骤 0。

### 契约 B3：三级尺度（BU / 星球 BU / 宇宙 RU）

这是星球与宇宙功能的**唯一硬约束**，写错就是灾难：

- **地表 BU**：岛 100~180、史莱姆 1.5。
- **星球 BU**：球半径 `planet_radius`（默认 120）；地形起伏 = `relief_scale × planet_radius`（≈9.6BU）。
- **宇宙 RU**：行星渲染直径 0.5~2 RU（**压缩，非真实比例**）、轨道 4~60 RU。

三条规则：

1. 地表 → 星球：**投影**（不缩放岛尺寸，只缩放起伏）。
2. 星球 → 宇宙：**压缩**（真实半径只用于物理，渲染用对数映射）。
3. **三者永不直接相加**。任何跨层运算必须显式换算。

### 契约 B4：物理单一来源（`runtime/physics_report.md`）

引力、温度、日长、潮汐——**只允许在一处计算**（零件 49 的物理模块），其余所有地方（编辑器显示、史莱姆手感、太空视觉）**读它**，禁止各自算一遍。

这条不是洁癖：同一颗星球上"编辑器说重力 0.7、跳跃像 1.4、大气亮度像 0.9"会立刻摧毁可信度。

### 契约 C：事件流（`runtime/events.jsonl`）

一行一个 JSON 事件，追加写。事件名固定：`job.enqueued`、`job.started`、`job.progress`、`job.succeeded`、`job.failed`、`world.born`、`ring.unlocked`、`map.updated`、`notify`。网页轮询或 SSE 读它，用来弹通知、刷地图、更新进度条。

## 七、迷雾机制怎么落到三个层面

这是本项目最核心的新需求，三层必须对齐，不能各做各的：

| 层面 | 怎么实现 |
|---|---|
| **物理** | 迷雾环是一圈看不见的碰撞边界，史莱姆的移动控制器在边界处把速度沿法向清零（不是硬停，是"陷进去一点点再被推回"，手感更软） |
| **视觉** | 边界内侧一层环形体积雾 + 一层贴地雾墙，颜色由当前 `palette` 推导，翻涌由噪声驱动 |
| **规则** | 边缘 6 BU 内进入「可拓荒」状态；按住 `E` 1.2 秒蓄力；松手或满蓄触发解锁请求 |

解锁流程（零件 30 的状态机）：

`IDLE` → `NEAR_EDGE` → `CHARGING` → `REQUESTING`（发作业） → `GENERATING`（后台 CLI 跑） → `APPLYING`（把新环并入场景） → `REVEALING`（雾退 1.5 秒动画） → `IDLE`，环数 +1、地图 +1 圈、弹通知。

同一时刻只允许一个拓荒请求。已有作业在跑时，边缘提示改成「拓荒进行中…」。

## 八、网页内的 CLI 是什么

用户说的"网页内置的 CLI"，指的是驾驶舱底部的一个**终端面板**，不是真终端：

- 它只能执行白名单命令：`blender -b` 系列、`npm run dev`、`npm run build`、`node`、`python` 允许的脚本、`git status`、`ls`、`cat runtime/*`。
- 每条命令走服务端路由，spawn 子进程，**stdout/stderr 流式**回灌到面板，带时间戳和颜色。
- 危险命令（`rm`、`format`、写系统目录）直接拒绝并红字提示。
- 面板支持 `↑` 历史、`Ctrl+L` 清屏、`?` 帮助。

## 九、验收口径（什么算"做好了"）

**单个零件的验收**：零件末尾的 checklist 全过 + 截图无异常 + 增量 blend 已存。

**整包的验收**（零件 37 展开成 21 条）：至少这 8 条必须真过：

1. 打开 `world/final.blend` 直接是完整出生岛，无需再跑任何脚本。
2. 走过去，远处区块才补全；离开足够远再回来，地貌一模一样。
3. 史莱姆能走、能跳、落地压扁、待机呼吸。
4. 迷雾边缘撞不进去；靠近有提示；按住 E 有蓄力条。
5. 解锁后：后台 CLI 有日志、页面弹通知、迷雾退一环、地图外扩一圈。
6. 新环地形风格与旧环连续（同一个 seed 家族），不是贴上去的补丁。
7. 断网或 Key 无效时，仍能生成六套预设之一。
8. 地图与 3D 现实一致：地图上的水/沙/草和脚下一致，史莱姆箭头方向对。

**不许拿"代码写完了"当验收**。要拿截图和 `get_scene_info` 的数字说话。

## 十一B、外部对照表（不许凭想象设计）

`docs/` 下有两份**外部依据**，任何新增元素前必须先看：

- **MC元素对照表**：对照 minecraftsearch 的五个顶级分类（工具 10 / 物品 758 / 方块 1110 / 生物 109 / 世界 108，合计 2,095 条目）。标 ⛔ 的类别**不要偷偷做**——尤其敌对生物与物品，会与调性冲突。
- **宇宙模拟软件对照表**：对照 SpaceEngine 与 Universe Sandbox 的真实功能清单。标 ⛔ 的（星系级、超新星、真 N 体、航天器、精确相对论）都有明确理由。

三条由此得出的纪律，写死在 49 与 42：

1. **不追真实，追因果**——真 N 体会毁掉可玩性，但"恒星变重→跳不起来"必须成立。
2. **时间必须可倒流**——这是"模拟"与"动画"的分界线，且解析架构让我们免费获得。
3. **一切压缩尺度必须标注"示意"**——诚实比精确重要。
