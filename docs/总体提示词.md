# 总体提示词 · 迷雾群岛

> 本文件是产品方向的唯一总纲。`docs/详细提示词/` 中的零件只能细化实现，不能改变这里规定的主游玩端、美术质量、镜头、操作和 UI。
>
> 若任何零件仍出现与本文件冲突的旧指令，停手报告，不要继续施工。

---

## 0. 一句话目标

**做一个打开浏览器就能玩的精致风格化低多边形开放世界：玩家用第三人称控制一只果冻史莱姆，在细节完整、材质柔和、光影协调的浮岛上探索，并通过类似原神这类开放世界游戏的直观操作与游戏 UI 去理解世界、追踪目标和拓荒迷雾。**

不是网页驾驶舱，不是 Blender 查看器，不是 Minecraft 换皮，也不是用少量几何体拼出的技术演示。

**“低多边形”是美术语言，不是粗糙、简陋或面数越少越好。**

---

## 1. 从零开始，不使用任何历史实现

- 仓库外恢复包中的代码、UI、模型、材质、贴图、截图、设计参数与脚本，**一律不得读取、参考或导入**，包括所谓“只看反例”。
- 不打开旧 `.blend`、旧 GLB、旧网页或旧截图，不做兼容性迁移、换皮、删面、缩放或局部修补。
- 从空白设计稿、空白 Blender 场景和新的浏览器工程开始。只使用本次明确编写的产品与技术契约。
- 外部游戏只用于理解抽象体验，不导入其模型、图标、截图、字体、色板采样、动画或其他资源。

---

## 2. 主游玩端与产品优先级

### 2.1 浏览器就是游戏

- `app/` 使用 Three.js/WebGL，负责实时渲染、输入、角色运动、相机、碰撞、动画、地图和 HUD。
- `world/` 中的 Blender 工程负责从零制作源资产、分块 GLB、材质与离线检查。
- 打开浏览器直接进入游戏；不需要打开 Blender、运行 Blender 脚本或操作命令行。
- 后台只生成并校验资源，浏览器预载后原子切换；不得无提示重置玩家、镜头、天气或世界进度。

### 2.2 优先级不可颠倒

1. 模型、材质、光照达到**精致风格化低模**的视觉质量。
2. 浏览器里确实可玩，角色运动与相机有开放世界游戏手感。
3. UI 是完整、协调、高保真的游戏界面，而不是网页组件拼盘。
4. 岛、史莱姆、地图和迷雾拓荒形成完整体验。
5. 生态、天气、生物等丰富系统。
6. AI、CLI、星球和宇宙等扩展。

**功能数量、低面数和帧率都不能用来抵消“看起来粗糙”或“操作像技术演示”。**

---

## 3. 美术目标：精致风格化低模，不是方块

### 3.1 轮廓与结构

每个重要模型都必须有大、中、小三层结构：

- **大形**：远距离可辨的独特剪影，角色、树木、岩石与地标不能共用通用几何轮廓。
- **中形**：枝干、根部分叉、岩层转折、角色顶部偏移、地标支撑等体积关系。
- **小形**：少量服务近景的边缘、切面、嵌件、色带、装饰几何或程序化细节，不能平均撒噪点。

地形使用连续共享顶点三角网；山体、海岸、树冠和角色通过设计过的轮廓与曲面/折面组合表达。禁止单位立方体拼接、体素、像素表面、方树和 MC 标志性造型。

### 3.2 拓扑、法线与面数

- 低模要求**有效而干净的拓扑**，不是机械地把面数压到最低。
- 地形可以保留明确三角切面；角色、树干、岩石等按造型选择平面法线、分组平滑、加权法线或小倒角。
- 允许为了轮廓和表情使用适度细分、形态键、骨骼或定制顶点；禁止以“任何细分都不允许”限制最终质量。
- 近景主角、近景植被与远景 LOD 分开预算。不得在远处仍然浪费细节，也不得把近景模型砍成粗糙 primitives。
- 若视觉验收与面数目标冲突，先调整结构、实例化和 LOD，不得直接牺牲主角与近景质量。

### 3.3 材质与光影

- 使用协调色板、柔和明暗、材质粗糙度差异、接触阴影、环境光遮蔽和适量边缘光表现体积。
- 允许原创程序化纹理、渐变、噪声、局部色带和非像素化细节；禁止的是 MC/像素纹理和外部素材，不是所有纹理。
- 草地、沙、岩石、树皮、水体和果冻必须在近景可区分，不只是同一种塑料换了颜色。
- 透明与发光必须有节制，不能靠泛白、强 Bloom 或高饱和掩盖轮廓问题。
- 正式效果以浏览器默认游戏镜头为准，Blender 渲染只作资产对照。

### 3.4 美术验收证据

关键模型依次交付：

1. 正/侧/45°剪影与结构设计说明。
2. 灰模近景，证明大、中、小结构和法线成立。
3. 材质/光影完成图与近、中、远三距离实机图。
4. 与默认世界同光照、同相机的浏览器高保真截图。
5. 面数、LOD、材质、穿插、阴影和动画检查。

**“不是方块”只是底线，“精致、完整、协调”才是通过标准。**

## 4. UI 目标：类似原神的开放世界游戏界面

参考的是**世界优先、操作直接、信息随情境出现、菜单与 HUD 风格统一**，不是复制具体素材。

### 4.1 默认 HUD

- 左上：精致小地图、区域名和必要的时间/天气。
- 任务追踪：少量当前目标，靠近小地图或位于轻量右侧区域，避免占据前方视野。
- 右上/边缘：少量原创圆形功能入口，地图、目标、暂停；不是网页导航栏。
- 底部中央：当前角色的必要状态，信息少而清晰。
- 角色/互动对象附近：输入图标、互动动作与蓄力反馈，按当前输入设备变化。
- 临时通知、区域发现和资源进度：自动消退，不堆成通知中心。

默认禁止三栏、固定左右侧栏、常驻 CLI、常驻日志、参数表格和大面积网页卡片。

### 4.2 完整游戏界面，不只是 HUD

以下界面都要有独立高保真设计与统一视觉语言：

- 全屏地图：缩放、拖动、回到玩家、地标、目标与路径点。
- 暂停/设置：清晰分组、游戏背景保留、关闭后精确返回。
- 世界创建：与游戏同一幻想世界气质，不做后台表单。
- 目标与拓荒反馈：当前状态、取消、成功、失败一目了然。
- 触屏布局：左下移动、右下动作、地图与菜单入口适配安全区。

CLI、日志和性能面板属于默认隐藏的开发者工具，不能混入玩家 UI。

### 4.3 高保真设计先行

在写界面前必须交付：

1. 桌面与触屏线框。
2. 默认 HUD、全屏地图、暂停/设置、互动状态的高保真效果图。
3. 字体层级、原创图标、色彩、透明度、间距、圆角、阴影与动效 token。
4. 进入世界、移动、打开地图、暂停、互动、返回的交互分镜。

高保真设计未确认前，不得用通用组件库拼出“功能完成”的 UI。

## 5. 操作目标：开放世界角色与相机手感

### 5.1 默认输入

| 输入 | 行为 |
|---|---|
| WASD / 方向键 | 相对相机移动，具有起步、停止与转向反馈 |
| 鼠标移动 | 单击游戏后锁定指针并环视；Esc 释放并打开暂停 |
| 滚轮 | 平滑调整跟随距离 |
| 空格 | 跳跃，包含预备、上升、下落和落地反馈 |
| Shift | 短冲刺或快速移动，行为必须一致且可预期 |
| E | 当前最佳目标的情境互动 / 迷雾蓄力 |
| M | 打开/关闭全屏地图 |
| J | 展开/收起当前目标详情 |
| Esc | 取消当前操作、关闭覆盖界面或暂停 |

指针锁定不可用时可用明确拖动模式回退。文本输入和覆盖界面必须隔离游戏输入。触屏使用左下摇杆、右侧滑动环视和右下动作按钮，并根据最近输入切换提示图标。

### 5.2 角色运动

- 具有待机、起步、移动、停止、转向、跳跃预备、上升、顶点、下落和落地的连续状态。
- 加速、减速与转身可调，不能瞬间换向、速度阶跃或动画滑步。
- 坡面、台阶边缘、区块接缝、空中与落地都有一致碰撞；相机朝向只决定移动参考，不抢夺角色控制。
- 动作与速度匹配，呼吸、视线、挤压拉伸只是精修，不能代替运动控制器质量。

### 5.3 相机

- 默认第三人称跟随，首屏角色、近景细节和前方路径清晰。
- 支持平滑跟随、自由环视、距离缩放、地形/大型物体避障和遮挡淡出。
- 不在每次松鼠标后强行回正；仅在移动且设置允许时温和辅助回正，玩家环视优先。
- 整岛俯瞰只用于诊断，不能替代默认游戏截图。

## 6. 外部参考边界

- `docs/MC元素对照表.md` 只比较设计问题，不决定模型、材质、UI、动画或手感。
- 原神及其他开放世界游戏只用于理解操作直接性、信息层级、镜头与界面完成度；不复制其具体资源或逐项复刻系统。
- 不追求条目覆盖率、行为等价或外部游戏“复刻感”。最终必须形成自己的低模幻想世界。

---

## 7. 资源与性能口径

详细定义以 `01_全局契约.md` 为准。

- 区块 10 BU，出生岛 100 块；L0 地形每块 11×11 个位置、200 三角面，基础地形共 20,000 面。
- 地形采样密度不是可见方格，不限制角色、树木和道具的细节量。
- 出生岛默认实际渲染场景的预算目标为 **≤250,000 三角面**；独立源资产、共享模板、实例与不同 LOD 不重复累加。
- 近景主角和关键模型先满足质量下限，再通过实例化、距离 LOD、遮挡和流式控制总成本。
- 出生岛满细节源资源不等于同屏渲染量；性能报告必须分别列出源资产、驻留资源和实际提交三角面。
- 浏览器同屏 draw call 目标 ≤600，1080p 验收硬件目标 ≥45fps。未达标时不得把近景主角和树木退回方块/简陋 primitives。

## 8. 施工与 Gate 顺序

按 `00_索引.md` 执行，但首先通过 **G0 精致可玩美术切片**：

1. 制作一小块完整地形的精致度样板，确认地形、树、岩石、史莱姆、材质与光影。
2. 交付高保真 UI 效果图和桌面/触屏交互分镜。
3. 在浏览器中加载真实新资产，验证完整角色运动、相机、地图和互动。
4. 用高保真实机截图与连续录屏证明“精致模型 + 开放世界体验”同时成立。
5. 用户确认 G0 后，才扩展后台、AI、生态和宇宙。

禁止先完成 CLI、API、宇宙编辑器或大量地形，再用“功能很多”请求通过美术验收。

## 9. 一票否决

出现任一项即失败：

- 使用或参考任何恢复包实现，或从外部游戏/现成模型包改造。
- 模型虽然非方块，但明显是少量 primitives 拼成的粗糙技术演示，缺少必要轮廓、结构和材质细节。
- 用极低面数、全平面法线或“低模”作为粗糙感的借口。
- UI 是通用网页组件、三栏、驾驶舱，或只有线框质量，没有统一的高保真游戏视觉。
- 操作仅满足按键响应，角色滑步、相机抢回、互动选择混乱，缺乏完整开放世界手感。
- 必须打开 Blender 才能游玩，或用静态图代替实时游戏。
- 用滤镜、Bloom、景深或截图角度掩盖模型和 UI 缺陷。

G0 至少提交：精致模型近/中/远实机图、高保真 HUD/地图/暂停图、完整运动与相机录屏、迷雾互动录屏，以及对应性能数据。
