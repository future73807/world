# 宇宙模拟软件对照表

> 参照物：**SpaceEngine**（1:1 尺度全宇宙模拟）、**Universe Sandbox**（N 体物理沙盒）。
> 这是"宇宙功能该有什么"的外部依据，避免我们凭想象设计。
> 数据抓取日期 2026-11-20（来源见文末）。

---

## 一、两款参照物的真实规格

### SpaceEngine（Steam 314650）

| 维度 | 它有什么 |
|---|---|
| **尺度** | 宣称 **1:1 真实尺度**，数十亿星系；从行星表面到星系际空间无缝旅行 |
| **程序化生成** | 未测绘空间里程序化生成：星系、恒星、星团、星云、行星系；行星用 **GPU 生成 3D 地形** |
| **天体类型** | 卫星、彗星、小行星、黑洞、中子星、多星系统 |
| **轨道运动** | 行星、卫星、**多星系统**的精确轨道运动 |
| **时间控制** | 时间加速、**倒流**、**跳到指定日期** |
| **渲染** | 大气散射（atmospheric scattering）、**日食阴影**、**极光**、黑洞**吸积盘与喷流** |
| **地表** | 有行星表面地形与着陆（这正是我们可以对标的） |

### Universe Sandbox（Steam 230290）

| 维度 | 它有什么 |
|---|---|
| **物理** | **牛顿 N 体引力**（可调速度）、实时碰撞、**气候与材质互动** |
| **季节** | 由**轴向倾斜**驱动的季节性冰雪 |
| **温度** | 表面加热可**煮沸海洋**；恒星的年龄/质量变化导致**超新星** |
| **光学** | **黑洞弯曲光线** |
| **天体** | 行星、卫星、恒星、黑洞、**星系**、环、彗星、**脉冲星**、航天器 |
| **编辑** | **从一颗恒星向外构建系统**；用 **12 种材质改造星球（terraforming）**；调倾角/质量/自转；**雕刻海洋与山脉**；触发碰撞/超新星/太空激光 |
| **分享** | Steam Workshop |

### 🟡 简化实现（做了，但明确降级）

| 能力 | 它们 | 我们 | 为什么降级 |
|---|---|---|---|
| 1:1 真实尺度 | SpaceEngine 数十亿星系 | 1 个星系 3~7 颗星，压缩尺度 | 低模 + 单人 + 可玩性优先。**真实比例下行星是一粒灰** |
| N 体引力 | U.Sandbox 真 N 体 | 恒星+行星两体 + 相邻弱摄动 ±3% | **N 体是混沌的**：三颗行星就飞散，玩家会看到世界崩溃而不是新秩序 |
| 行星表面 | GPU 生成高精度地形 | 平面噪声投影（12k 顶点） | 要能走、能玩、能拓荒 |
| 大气 | 真实散射 | 菲涅尔辉光（受光侧） | 视觉等价，成本 1/100 |
| 黑洞 | 真引力透镜 + 喷流 | 吸积盘 + 简化透镜（或贴图） | 后处理扭曲成本高 |
| terraforming | 12 种材质改造 | biome + 十色板 + 六滑杆 | 我们是"改设定卡"，不是"改地块" |
| 雕刻海洋与山脉 | U 盘刷子 | 改 `peak_height` / `roughness` | 低模不需要刷子，改参数更快 |
| 碰撞 | 实时碰撞 | ⛔ 软钳制（轨道过近→夹住） | 碰撞会产生不可逆破坏，与"可玩"冲突 |

### ⛔ 明确不做（附理由）

| 能力 | 为什么不 |
|---|---|
| **星系级（galaxy）** | 尺度跨 6 个数量级。做了会让"你的岛"消失在一个噪点里 |
| **中子星/脉冲星/类星体** | 视觉上与黑洞重叠，且需要科普文案才能理解 |
| **超新星/恒星演化** | 会**摧毁**玩家的世界。本项目不能有"世界没了"这个状态 |
| **真 N 体 + 混沌** | 见上。要让玩家"可预期地玩" |
| **航天器/任务** | 无目标系统 |
| **相对论效应**（时间膨胀、光线弯曲的精确解） | 感知不到（除了光行时，那是彩蛋） |
| **多宇宙/平行宇宙** | 概念噱头，无玩法落点 |
| **真实星表数据**（Hipparcos 等） | 我们造的是**虚构世界**，不是天文馆 |

## 三、三件我们从它们那里"抄"来的具体设计

### 1. 时间可倒流（SpaceEngine）

不只是"加速"——**能倒着走**。我们的实现几乎零成本，因为 42 用的是**解析解**（位置是 `t` 的函数，不是积分累积）。

- 面板上给一个时间轴拖拽器：拖到任意时刻，所有行星立刻就位。
- 这个功能在积分式模拟里做不出来（会漂移），是我们的架构红利。

### 2. 从恒星向外构建（Universe Sandbox）

编辑的**心智模型不是"列表"，是"从中心长出去"**。

- 43 的"加入一颗"就应该在**外侧插入**（`a × 1.35`），而不是"加到列表末尾"。
- 47 的轨道示意图按 `a` 排序，视觉上就是"由内到外"。
- 这条影响 UI 结构，不只是数据。

### 3. 轴向倾斜驱动季节（Universe Sandbox）

`axial_tilt` 不是一个装饰数字，它**必须改变日照角度**（49 已做）。

- 且要在 UI 上说清："倾斜 23° = 类似地球的季节"。
- 倾斜 0° = 永无季节；倾斜 45° = 极端季节。

## 四、我们比它们强的地方

外部软件都是**观察器**：你造好，然后看着它转。

我们有一个它们都没有的东西：

| 能力 | 它们 | 我们 |
|---|---|---|
| **星球表面可玩** | SpaceEngine 可以着陆看风景，但**不能改变它** | 走、跳、拓荒、扩环——**地表是真的能玩的** |
| **从地表长到星球** | 不可能（尺度不连续） | **同一座岛卷成球**（39）——"我走过的地"变成"我看到的天体" |
| **世界因你而变大** | 无 | 迷雾拓荒（28~32） |

**一句话**：它们是"宇宙浏览器"，我们是"宇宙里的一小块地，而且这块地会长大"。

---

## 五、由此得出的三条设计纪律

1. **不追真实，追因果。**（49 已写死）真实 N 体会毁掉可玩性；但"恒星变重 → 跳不起来"必须成立。
2. **时间必须可倒流。**这是解析架构的红利，也是"模拟"与"动画"的分界线。
3. **一切尺度必须标注"示意"。**我们压缩了尺度，就要诚实标注，不能假装 1:1。
